一、背景与问题

ZONGYUAN-ROOT 云端真值库（SQLite，truth.db）在持续运行中积累了低价值真值条目——包括空值、占位符、probe 探测、test 测试等碎片，累计约 986 条被归档为待蒸馏素材。这些条目若不处理，会稀释真值库纯度、干扰 RAG 检索与自治内核决策。

传统做法是直接丢弃，但丢弃意味着丢失潜在价值——许多低价值碎片内部其实承载着有效的时间戳、节点状态、自进化验证数据，只是缺乏结构化提炼。

二、方案：编码执行节点 Worker 蒸馏闭环

本方案引入 AtomCode 编码执行节点 Worker（EXT-NODE-1DF8D832AD），利用其 免费 CodingPlan 额度（qwen3.8-27b），将低价值真值经 AI 蒸馏为高价值结构化真值，回写持久层，形成"派单 → 执行 → 回写"原子闭环。

三、闭环机制详解

3.1 派单（dispatch_distill.py）

通过 SQL 扫描真值库中满足低价值判据的条目：value IS NULL、含 empty_value、含占位、含 probe/test，且未被蒸馏过（key 不含 DISTILLED 标记）。将原始 value 内容（截取300字）嵌入蒸馏指令，打包为 Worker PENDING 任务，写入 tasks.json。

3.2 执行（worker.py + AtomCode）

Worker 守护进程每 60s 轮询任务队列，取第一条 PENDING 任务，以非交互模式 atomcode -p "蒸馏指令" 调用 AtomCode（免费 qwen3.8-27b）蒸馏。蒸馏指令要求输出结构化 JSON：{truth_id, truth_type, content, purity, ratio}。结果写入 results/{task_id}.json。

3.3 回写（collect_distill_result.py）

扫描 results/ 目录下 COMPLETED 蒸馏结果，正则提取蒸馏 JSON（含 truth_id 字段的块），构造高价值真值对象（含纯度评分、蒸馏压缩比、来源、锚点、DID），append 写入真值库 truth.distill.*，并在 collect_ledger 去重。

3.4 编排（auto_distill_orchestrator.py）

封装完整循环：派单 → 逐条执行（最多3轮，每轮1条）→ 回写。空闲时（无候选/无任务）自动跳过，0 消耗。遵循最小额度消耗原则。

五、工程约束与元法则

本次落地沉淀元法则 META-LAW-TRUTH-DISTILL-WORKER-CLOSED-LOOP-V1.0，核心条款：

  • 低价值真值不得直接丢弃，应由编码节点 Worker 蒸馏提纯回写
  • 单次最多 3 条，增量优先，失败快速跳过，最小额度消耗
  • 利用免费 CodingPlan 额度零成本执行，不占付费通道

同时触发既有元法则 META-LAW-NO-HALF-FINISHED-DEPLOYMENT-V1.0：仿真验证通过方可部署，失败必回退，禁止半成品覆盖可用版本。
