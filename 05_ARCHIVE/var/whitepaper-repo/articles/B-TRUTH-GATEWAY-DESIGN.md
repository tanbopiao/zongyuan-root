# 真值确权网关设计：幂等去重 + 语义校验 + Merkle 锚定

> 对齐：技术深度解析类 ｜ 2026-09-20

---

## 为什么需要"真值网关"

多 Agent 系统最怕两件事：**重复写爆**和**写错不自知**。N 个节点各自往云端报状态，没有一个统一的"什么算真"的入口，最后就是一锅粥。

我们设计了一个真值确权网关，现在跑了 97,835 条真值，审计日志 106,114 条，没有写爆过。

## 一、接口设计

```
POST /api/report/truth
{
  "truth_key":   "REPORT.20260920.DAILY",
  "truth_value": "今日量产完成...",
  "source_node": "local-agent-01",
  "confidence":  1.0,
  "truth_type":  "DAILY"
}
```

五个字段各管一件事：
- `truth_key`：全局唯一键，幂等的基础
- `truth_value`：真值内容
- `source_node`：谁报的，出问题知道查谁
- `confidence`：置信度，低置信不进主库
- `truth_type`：分类（DAILY / META_RULE / GLOBAL_LOCK...）

## 二、幂等去重

同 key 重复上报不写第二遍。这一条听起来简单，实际挡掉了 90% 的重复问题——心跳任务每 2 小时跑一次，每次都上报，如果不去重，一天就 12 条重复记录。

实现上用 key 做主键冲突检测，写失败就跳过，不报错。

## 三、语义前置校验

写入前先过一层语义校验。挡掉两类：
- **冲突真值**：新真值和已有真值语义矛盾（比如同一个 key 值变了且没标记版本）
- **无效真值**：空内容、格式不对、置信度过低

这一层是"质量门"，没有它，垃圾数据会指数级积累。

## 四、Merkle 锚定

网关侧的真值，本地还有一份 Merkle 树。全资产清单算一个 Merkle 根，任何一次锁档都把这个根固化下来。

- 云端查 `GET /api/truth/{key}` 拿单条
- 本地锁档时对账 Merkle 根
- 不一致 = 有篡改或丢失，触发自愈

## 五、实测数据

| 指标 | 数值 |
|---|---|
| 真值总数 | 97,835 |
| 审计日志 | 106,114 |
| 节点数 | 5 |
| 写爆事件 | 0 |
| 冲突拦截 | 自动 |

## 六、踩坑

- **key 设计要稳定**：key 一旦定了别改，改了就成两条
- **语义校验别太严**：太严会把正常迭代真值也挡掉，留版本号字段
- **审计日志单独存**：审计和主库分开，别混
