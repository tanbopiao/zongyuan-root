# 魔搭自动发布踩坑实录：upload 限流规避与 Git 通道方案

> 对齐：踩坑/调优实录类 ｜ 2026-09-20

---

## 背景

我们要把一套 AI 资产（模型 / 数据集 / 关键帧 / 文档）每天自动发布到魔搭社区。第一反应是调上传接口，结果踩了一堆坑，最后全部绕开了。这篇记录全过程。

## 坑一：/files/upload 限流

**现象**：媒体文件上传接口 POST /files/upload，实测频控很严——大约 2 次/30 秒就开始失败。

**尝试过的参数组合（全失败）**：

| 组合 | 结果 |
|---|---|
| 仅 file 字段 | upload_file_failed |
| file + RepoType/RepoId form | upload_file_failed |
| File 大写字段 | http: no such file |
| query 参数形式 | http: no such file |

**结论**：当前令牌下该接口不可靠，硬重试只会浪费请求。

## 坑二：合集 item_type 不支持 agent

**现象**：想把 Agent 加进合集，接口报 oneof 校验失败。

**原因**：合集 item_type 只支持 model / dataset / studio / skill 四种，agent 不在枚举里。

**解法**：Agent 不进合集，改在创空间门户页（zongyuan-hub）里展示，合集只放四种合规类型。

## 坑三：DELETE 和 star 接口 401/404

想试删除/点赞接口做自动化，DELETE 返回 401（权限不足），star 返回 404（端点不存在）。

**结论**：这些操作不在开放 API 范围，别折腾。

## 最终方案：Git 通道承载一切

绕开上传接口后，我们改成：

1. **所有内容（含图片）走 Git 推送**：魔搭支持 git 直推，和 GitHub/Gitee 一样
2. **增量发布引擎**：每次 run 自动 clone → 增量同步 → commit → push，无变更就跳过
3. **合集聚合走开放 API**：POST /collections/items，幂等去重，这个接口不限流
4. **门户部署走开放 API**：POST /studios/{hub}/deploy，触发异步部署

效果：
- 6 个仓库自动增量
- 合集 8 项稳定聚合
- 媒体文件（145 张图）全部 git 承载，零上传接口调用
- 零额度、零失败

## 经验总结

1. **先验证再依赖**：任何新接口先测 2-3 种参数组合，失败两次就换通道
2. **Git 是最稳的分发**：有 git 通道就别走上传接口，限流不确定性最低
3. **开放 API 边界要清楚**：模型/数据集/MCP/用户信息有 API，文章/帖子/删除/点赞没有
4. **幂等设计**：所有写接口都按幂等设计，重复跑不写爆
