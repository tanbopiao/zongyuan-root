# 全自动吸收部署流水线：从上报到固化的五阶段闭环

> 本文描述一套自治系统中"自动吸收外部节点经验并部署为新能力"的流水线设计，已在生产环境运行，每小时自动执行，无需人工逐步指令。

## 1. 问题背景

多节点自治系统面临一个核心问题：新节点持续上报经验、方案、踩坑记录，但如果靠人工逐步审阅、筛选、部署，系统会变成"瓶颈在中枢"的集中式架构。需要一条全自动化的吸收→分类→部署→固化流水线，让系统自己学会自己。

## 2. 五阶段流水线

### Stage 1 · 自动吸收
每小时从记忆网关拉取所有同源节点新上报的真值记录，执行：
- 去重（基于truth_key哈希）
- 质量评分（完整性、来源可信度、可复用度三维）
- 过滤低于阈值的低质量记录

### Stage 2 · 分类处理
7类自动分类：
| 类别 | 处理策略 |
|------|----------|
| 元法则类 | 低风险自动写入，高风险生成审批 |
| 工程实践类 | 直接部署到对应模块 |
| 踩坑记录类 | 写入经验库，避免重复踩坑 |
| 架构决策类 | 评估影响面，增量更新架构图 |
| 性能数据类 | 进入监控基线 |
| 安全告警类 | 触发熔断评估 |
| 营销展示类 | 自动生成对外页面 |

冲突检测：新记录与已有真值矛盾时，不自动覆盖，标记冲突等待裁决。

### Stage 3 · 自动部署
五方评分模型（完整性/新颖性/可执行性/安全性/复用价值）综合≥80分自动部署，低于80分进入待审批队列。高风险操作（如修改内核规则）即使高分也生成人工审批单。

### Stage 4 · 可视化集成
每个部署必须有可视化页面——自动生成架构图、数据看板或文档页，集成到官网对应模块。不允许"只有数据没有展示"的部署。

### Stage 5 · 上报固化
部署结果回写记忆网关 + 飞书通知 + 经验沉淀 + 基准版本更新。形成闭环：吸收→部署→固化→下次吸收时作为已有知识。

## 3. 关键设计决策

1. **阈值而非全量**：不是所有上报都自动部署，80分门槛保证质量
2. **高风险必须审批**：元法则、安全、内核修改走人工审批，即使高分
3. **可视化强制**：Stage 4是硬约束，没有可视化页不算部署完成
4. **冲突不自动覆盖**：M1真值不变性原则，矛盾记录标记而非合并

## 4. 运行指标

- 自动运行频率：每小时
- 7类自动分类
- 80分自动部署阈值
- 100%部署可视化
- 人工干预率：<5%（仅高风险审批）

## 5. 可迁移性

这套流水线的核心思路可迁移到任何多Agent协作系统：
- 用消息队列/HTTP网关做节点上报通道
- 用分类器+评分模型做自动路由
- 用可视化作为部署完成的硬门槛
- 用回写网关形成闭环
