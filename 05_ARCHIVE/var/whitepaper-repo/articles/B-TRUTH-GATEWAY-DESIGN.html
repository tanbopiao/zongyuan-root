一 · 接口设计

POST /api/report/truth { "truth_key": "REPORT.20260920.DAILY", "truth_value": "今日量产完成...", "source_node": "local-agent-01", "confidence": 1.0, "truth_type": "DAILY" }
  • truth_key：全局唯一键，幂等基础
  • truth_value：真值内容
  • source_node：谁报的，可追溯
  • confidence：低置信不进主库
  • truth_type：分类路由

二 · 幂等去重

同 key 重复上报不写第二遍。心跳每 2 小时跑一次，不去重一天 12 条重复。用 key 做主键冲突检测，写失败跳过不报错。

三 · 语义前置校验

  • 冲突真值：与已有真值语义矛盾 → 拦截
  • 无效真值：空内容/格式错/置信度过低 → 拦截
  • 这是质量门，没有它垃圾数据指数级积累

四 · Merkle 锚定

  • 全资产清单算 Merkle 根，每次锁档固化
  • 云端 GET /api/truth/{key} 取单条
  • 本地对账 Merkle 根，不一致 = 篡改/丢失 → 自愈
