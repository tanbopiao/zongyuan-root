## 摘要
本文介绍一套在生产环境持续运行的云边分离式AI执行体系：云端中枢负责决策、记忆与全局调度，本地执行节点负责流水线执行、资产发布与状态上报。系统通过HTTP网关解耦，实现零SSH、零GPU、零付费API的低成本自治运转。文章给出架构设计、关键工程决策、熔断机制与实测数据，供AI工程从业者参考。

**关键词**：云边架构、自治智能体、执行节点、记忆网关、熔断机制、低成本AI工程

## 1. 背景与现状
在多智能体与自动化流水线的工程实践中，常见两类极端：一是所有逻辑集中在一台服务器，单点故障风险高；二是节点完全自治，缺乏全局真值与调度一致性。本文的体系试图在两者之间取平衡：云端做"大脑"，本地做"手脚"，通过HTTP网关保持弱耦合。

## 2. 体系架构
```
云端中枢（决策/记忆）
  ├─ 记忆网关 HTTP API（读状态 / 写真值）
  ├─ crontab 定时任务调度
  └─ 每日量产任务
          ↑↓ HTTP
本地执行节点（手脚）
  ├─ 心跳引擎（每4小时握手+对账）
  ├─ 短剧流水线（剧本→关键帧→音频→合流）
  ├─ 社区发布引擎（git增量推送）
  └─ 本地文件系统（媒体库/配置/锁档）
```

## 3. 工程实现要点

### 3.1 零SSH约束
体系铁律：本地节点不SSH连接云端服务器，所有双向通信只走HTTP网关。好处是免维护密钥、免网络打通、可在任意沙箱环境运行；代价是云端不能主动推送指令给本地，只能本地轮询拉取。

### 3.2 真值网关
本地节点每次关键操作向网关POST一条真值记录（truth_key / truth_value / confidence），形成不可变审计账本。云端可随时GET查询全量真值。这是M1/M2/M3公理（真值不变、单调收敛、可追溯）的工程落地。

### 3.3 熔断与降级
- 网关502：不重试，记录异常，等下一轮心跳
- 付费API欠费：自动降级走免费本地通道（edge-tts + ffmpeg）
- 上传接口限流：规避该接口，改用git增量推送

### 3.4 定时任务自进化
每周做一次定时任务清单评审：识别重叠职能、合并冗余、调整频率。当前从9个任务精简到6-7个运行中，减少资源消耗。

## 4. 实测数据
- 本地资源：2核CPU / 3.9G内存
- 心跳间隔：每4小时一次，全绿率持续>95%
- 魔搭发布：6个git仓库增量推送，零额度消耗
- 短剧流水线：单集成片<2MB，零GPU零付费API

## 5. 约束与边界
- 本地沙箱不持久，重启后从config/恢复
- 本地跑不了GPU大模型（7B以上）
- 云边通信是单向轮询，非实时推送
- 付费API通道因账户欠费暂不可用

## 6. 总结
云边分离式架构在低成本、弱网络约束下实现了可自治运转。核心经验是：决策集中、执行下沉、通信走HTTP、熔断兜底、真值可追溯。
