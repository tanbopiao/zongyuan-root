# 从零搭建多 Agent 自治系统：记忆网关 + 自动发布工程实践

> 对齐：从零教程类（魔塔流量最大方向）｜ 2026-09-20

---

## 开篇

很多人跑 AI Agent 是"单次对话"：问一句、答一句、关了就忘。我们要的是**长期自治**——每天自动做内容、自动对账、自动归档、自动发布，人只在关键节点拍板。

这篇从零讲清楚怎么搭，每一步都有线上接口可验证。

## 一、先想清楚三件事

1. **执行层无状态**：本地 Agent 每次跑完就结束，不能依赖本地记忆
2. **记忆必须外置**：所有重要结论写到云端，任何节点都能取
3. **发布必须解耦**：内容生产和对外发布走不同通道，互不阻塞

## 二、最小可用三层架构

```
本地执行层
   ├─ 任务引擎   指令 → 规划 → 执行 → 验证 → 交付
   ├─ 知识网关   上报 / 检索 / 对账
   └─ 发布通道   Git 增量 + 开放平台聚合

云端记忆网关（一个 HTTP 服务）
   ├─ POST /api/report/truth   上报真值
   ├─ GET  /api/truth/{key}    按 key 取
   └─ GET  /api/report/status  看水位

元内核
   └─ 全局基准快照 + 共识确权
```

关键：执行层和云端**只靠 HTTP 通信**，不用 SSH，不用共享磁盘，任何节点都能独立跑。

## 三、记忆网关怎么设计

一个最简单的真值上报接口：

```json
POST /api/report/truth
{
  "truth_key": "REPORT.20260920",
  "truth_value": "今日量产完成...",
  "source_node": "local-agent-01",
  "confidence": 1.0,
  "truth_type": "DAILY"
}
```

工程上三个要点：
- **幂等去重**：同 key 重复上报不写第二遍，不然跑几次就爆了
- **语义前置校验**：写入前先过一层语义校验，明显冲突的直接挡掉
- **可追溯**：每条真值带 source_node，出问题知道是谁报的

我们这套网关现在跑了 **87,000+ 条真值**，没有写爆过。

## 四、自动发布引擎

内容做完了怎么对外？我们的做法：

1. 全资产索引自动生成（INDEX.json / INDEX.md）
2. Git 增量发布：clone → 增量同步 → commit → push
3. 开放平台合集聚合：把模型/数据集/创空间聚合成一个合集页
4. 限流规避：媒体文件走 Git 通道，不碰上传接口（上传接口限流很严，踩过坑，下一篇讲）

## 五、自适应心跳

系统跑久了最怕"静默死了"。我们加了心跳：

- 每小时握手 → 对账 → 补推 → 健康判定
- **停滞检测**：真值量连续多轮不涨就告警（说明生产停了）
- **自动调优**：连续健康轮次达标建议降频，异常持续就保持
