# 不可变快照流水线：锁档、Merkle 与自愈

> 对齐：工程化流水线类 ｜ 2026-09-20

---

## 为什么要快照

多 Agent 系统天天在改东西：改代码、改配置、改资产。没有快照，改坏了就是坏了，回不去。

我们要的不是"备份"，是**不可变快照**——一旦锁住，谁也改不了，改了就能发现。

## 一、流水线五阶段

```
变更发生 → 哈希锁档 → Merkle 根 → 熔断校验 → 自愈恢复
```

1. **哈希锁档**：全资产清单算 SHA256，每个文件一个指纹
2. **Merkle 根**：所有指纹归约成一个根哈希，任何文件变了根就变
3. **熔断校验**：eFuse 链检查，不一致就熔断（不让脏数据继续流）
4. **自愈恢复**：发现不一致，从最近快照拉回来
5. **台账写入**：所有变更进不可篡改账本

## 二、关键设计

- **快照不可变**：不是"覆盖写"，是"新版本号追加"
- **根锚定**：每次锁档的 Merkle 根写入网关真值，云端对账
- **最小粒度**：不是全量重跑，是增量 diff
- **熔断优先**：宁可停，不可脏

## 三、实测

| 指标 | 数值 |
|---|---|
| 快照数 | 多个（按版本递增） |
| Merkle 根 | 每次锁档唯一 |
| 自愈事件 | 自动 |
| 脏数据流出 | 0 |

## 四、踩坑

- **别全量重跑**：慢且贵，增量 diff 就够
- **根要上云端**：本地快照自己改自己发现不了，云端锚定才行
- **熔断别太敏感**：正常迭代也熔断就没法干活

---

不可变快照是多 Agent 系统的安全带：改坏了能回去，改脏了能拦住。
