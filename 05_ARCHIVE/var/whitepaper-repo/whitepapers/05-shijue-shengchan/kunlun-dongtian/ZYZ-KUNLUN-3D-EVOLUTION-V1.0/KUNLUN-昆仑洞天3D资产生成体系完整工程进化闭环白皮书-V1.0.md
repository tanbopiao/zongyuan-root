## 1. 现状基线：阶段 1｜规则稳态层（已完成）

### 1.1 阶段本质：零训练、零微调、规则约束式生成

当前整套昆仑 3D 体系的运行状态：

- 不修改 3D 模型权重
- 不参与模型训练
- 不做梯度更新
- 不依赖自建数据集

当前只做**三层治理**，不做生成内核改造：

| 层 | 载体 | 职责 |
|---|---|---|
| 前置语义治理 | Skill 裁决语义层 | 公理过滤、人设隔离、违禁熔断、标准 Prompt 归一 |
| 中台调度治理 | Agent 调度层 | 异步任务管理、工单 DID 溯源、全链路日志 |
| 后置几何治理 | OP-KUNLUN 算子组 | 水密性、尺度、比例、网格合法性校验 |

### 1.2 既有资产盘点（可复用基线，非从零开始）

| 资产 | 路径 | 作用 |
|---|---|---|
| 昆仑生产规则全集 | `var/whitepaper-repo/config/kunlun-production-rules.md` | L0 天元法则 4 条、天元元规则 7 条（R1-R7）、负面词全集、语义适配器 |
| 短剧工业化 SOP | `01_ASSETS/documents/docs/education/SOP-昆仑洞天短剧工业化流水线-V1.0.md` | 视觉生产流水线范式（可平移至 3D 资产线） |
| 2D LoRA 训练工程 | `models/kunlun-lora-dataset/`（README + `train_kunlun_lora.sh`） | 角色分桶、caption 生成、diffusers 训练脚本——**阶段 3 的方法论原型** |
| 昆仑算子组 | OP-KUNLUN-001 语义/世界观、002 尺度、003 网格水密、004 合规 | 后置几何与合规门禁（算子编号以算子注册台账为准） |

### 1.3 本质真相

> **现在的稳定，是"规则锁出来的稳定"，不是"模型学出来的稳定"。**

- **优势**：极速落地、零训练成本、零算力消耗、世界观可随时迭代（改规则即改产出）。
- **短板**：模型本身**不懂**昆仑世界观，只是被强制约束输出合规内容。

一旦 Prompt 写法波动、词语缺失、描述偏差，模型立刻崩坏、人设串扰、画风漂移。**当前的高级效果来自人工强行规范，不是 AI 原生理解**——这正是必须走向训练的根本原因。

## 2. Q1 补齐：为什么现在可以"简单"

### 2.1 可控性来源的三段论

```
生成质量 Q = 模型能力 M × 约束强度 C × 输入精度 P
```

- 阶段 1 中 **M 固定**（通用模型，不懂昆仑），所以全部 Q 由 **C 与 P** 贡献。
- C 由三层治理提供，P 由标准 Prompt 归一提供。
- 因此：**在不训练的前提下，把 C 和 P 推到极限，就是当前阶段的最优解**——这就是"简单"的合理性。

### 2.2 为什么不是一上来就训练

| 维度 | 直接训练 | 先规则后训练 |
|---|---|---|
| 数据 | 无干净数据 → 训练即污染（垃圾进垃圾出） | 先用规则产线攒纯净数据 |
| 风险 | 权重改动不可逆、失败需从头回滚（违反元宪法风险最小铁律） | 权重零改动，规则可随时回退 |
| 成本 | 立即消耗算力（违反成本序位） | 零算力 |
| 世界观 | 未定型的规则会把混乱写进权重 | 先把世界观在规则层迭代定型，再固化 |

**先规则后训练不是偷懒，而是风险最小 > 成本最小 > 收益最大的铁律在工程顺序上的必然投影。**

## 3. Q2 补齐：为什么必须训练（底层理论必然性）

### 3.1 通用 3D 大模型的天生缺陷

通用 text-to-3D 模型（本体系称 **Lux3D 基座**）的训练集是全网混杂 3D 数据：

- 现代、古风、科幻、Q 版、写实、西式、中式、奇幻全部混杂
- 没有统一的昆仑神谱世界观
- 没有固定神祇配色、服饰、气场、形制规范
- 没有上古仙侠结构化空间逻辑

> **结论：通用模型永远不可能天然输出统一世界观的资产。**

### 3.2 必须训练的三大理由

1. **规则约束有上限**
   Prompt + 算子只能"拦截错误"，不能"主动生成正确风格"。拦截是 0/1 判定，生成是高维分布——用 0/1 判定去塑形高维分布，覆盖率存在数学上界。
2. **世界观无法靠文字内化**
   复杂纹样、衣褶、仙气、玉质、云阶制式、神格气场，语言符号存在表达带宽上限，无法完整描述；必须靠模型在视觉隐空间（latent space）直接学习。
3. **长期量产必须模型内化**
   想要：短 Prompt、零约束、自动统一画风、自动区分诸神、自动匹配场景——**只能靠 LoRA / 微调把世界观压进模型权重**。

### 3.3 "拦截"与"内化"的能力边界对照

| 能力 | 规则（阶段1） | 训练（阶段3+） |
|---|---|---|
| 阻止违规输出 | ✅ 可以 | ✅ 可以 |
| 主动生成正确风格 | ❌ 不能 | ✅ 可以 |
| 短 Prompt 稳定复现 | ❌ 依赖长 Prompt 堆砌 | ✅ 原生理解 |
| 神祇间自动隔离 | ❌ 靠人工分桶约束 | ✅ 隐空间分域 |
| 画风随规则即时迭代 | ✅ 秒级生效 | ⚠️ 需重训 |
| 风格稳定性 | ⚠️ 输入敏感 | ✅ 分布稳定 |

**规则是"法律"，训练是"教养"。法律管住底线，教养决定上限——两者不是替代关系，而是层的关系（见 §4）。**

## 4. Q6 补齐：为什么必须分层（分层原理）

### 4.1 分层的第一性原理

把"**风控**"与"**能力**"放在不同层，二者才有独立的演化速度与回滚粒度：

- 风控层（公理/算子）：**永不下线**，任何模型版本都必须过同一套门禁；
- 能力层（LoRA/基座）：**持续升级**，每次升级只需重新过门禁，不必重造风控。

### 4.2 分层带来的四项工程收益

1. **风险隔离**：训练失败、LoRA 有毒、基座换代——最坏情况是能力层回退一版，风控层与产线不受影响（满足元宪法"风险最小"）。
2. **成本渐进**：每层独立投入，阶段 1 零算力、阶段 2 近零算力、阶段 3 才进入算力支出，避免一次性重投入。
3. **真值可审计**：每层独立留痕（Skill 裁决记录 / 算子 pass 记录 / 训练评估报告 / 推理日志），四维本体（空间+时间+属性+因果）建模成立。
4. **升级不推倒重来**：换基座（Lux3D v1→v2）时，治理层与数据集完全复用，只重训 LoRA。

### 4.3 为什么不分层（反例）

若把"世界观约束"直接写死进单一 Prompt 模板、或直接全量微调基座权重：

- Prompt 方案 = 把能力塞进输入层 → 无法扩展、无法审计；
- 全量微调 = 把风控与能力塞进同一层 → 无法回滚、灾难性遗忘、每次改世界观都要重训全部权重。

**结论：分层不是架构洁癖，而是让"规则可改、模型可换、数据可攒、产出不断线"同时成立的唯一结构。**

## 6. 阶段 3 核心：Q3/Q4/Q5 —— 什么时候训、怎么训、训练什么

> （阶段 2 数据流水线详设见 §7；本节先锁定训练侧门禁，因为"什么时候"决定了阶段 2 要攒什么。）

### 6.1 Q3｜什么时候训练：三重启动门禁（全部满足才开训）

**GATE-TRAIN-001 数据门禁**

| 指标 | 阈值 | 校验方式 |
|---|---|---|
| 有效 3D 样本总量 | ≥ 1,500 个 | `find` + metadata 计数 |
| 单神祇（主推 5 位）样本量 | 各 ≥ 150 | 分桶计数 |
| 场景类样本量 | 各场景 ≥ 80 | 分桶计数 |
| 纯净度（算子全 pass 且无人设串扰） | ≥ 99% | 抽检 + 自动过滤日志 |
| 标签完整率（metadata 必填字段） | 100% | schema 校验脚本 |
| 训练/验证切分 | 9:1，验证集固定冻结 | 切分清单哈希锁档 |

**GATE-TRAIN-002 评估门禁**

- 已建立**短 Prompt 评测集** `kunlun_eval_v1/`：每神祇 ≥ 24 条、场景 ≥ 30 条，共 ≥ 120 条；
- 已跑通**阶段 1 baseline 得分**（同一评测集、同一算子组），否则无对照不训；
- 评测口径固定：算子通过率 + 人设一致性人工抽检 + 短 Prompt 命中率。

**GATE-TRAIN-003 算力与审批门禁**

- 单卡显存 ≥ 24GB（或按 §6.4 配置的等效云 GPU 规格）；
- 付费算力属**高危/付费操作**，按元宪法强制人工审批后方可执行（不自动扣费）；
- 训练环境隔离：本地仿真先行，云端训练仅在审批通过后启动（本地仿真-云端双隔离公理）。

> **未同时满足三重门禁：一律不训。宁可继续在规则层迭代，也不用脏数据污染权重。**

### 6.2 Q5｜训练什么：世界观七要素

训练目标是把以下七要素压进模型隐空间，使其**短 Prompt 即可原生复现**：

1. **神祇人设恒定**——太阴月神永远红裙、不串其他神祇；西王母永远威严黑金青玉制式；九天玄女永远清冷玄色天书气质；九尾狐永远烟青霜白空灵形态；元明洞阳永远相应制式。
2. **配色体系恒定**——五神祇各自的法定配色不得漂移（红/黑金/玄色/烟青霜白/青金）。
3. **仙侠制式恒定**——服饰形制、纹样、冠戴、法器制式统一。
4. **光影风格恒定**——所有场景统一低饱和青金仙侠光影。
5. **灵气质感恒定**——所有灵气统一青白流动雾霭质感。
6. **场景结构恒定**——瑶池玉山、玄霄丹台、月阙玄圃、青丘崖谷的结构逻辑自洽。
7. **反污染恒定**——彻底杜绝现代、赛博、卡通、西式混入（对应负面词全集）。

> 训练什么 = **把 `kunlun-production-rules.md` 的 L0 公理与 R1-R7 元规则，从文本形态转成权重形态。**

### 6.3 Q4｜怎么训练之一：方法选型与数据准备

**训练方式**：3D-Diffusion LoRA（低秩适配），不改动基座权重，只注入可插拔的 LoRA 分支。

| 项 | 规范 |
|---|---|
| 基座 | Lux3D text-to-3D 扩散基座（占位名，落地时按实际可用基座替换并记录指纹） |
| 注入点 | 去噪 UNet / DiT 主干注意力层；文本编码器侧同步轻量 LoRA（用于 Prompt 语义对齐昆仑术语） |
| 训练精度 | bf16 混合精度；梯度累积补偿小 batch |
| 数据形态 | 每样本 = 3D 资产（GLB）+ 多视角渲染图 + 结构化 caption（真值标签直出） |
| caption 来源 | **非自由书写**：由 metadata 模板拼装（见 §7.3），保证标签与真值一致 |
| 验证集 | 冻结不参与训练，训练全程只评估不更新 |

**数据准备清单（开训前必须完成）**

1. 阶段 2 产出 `kunlun_dataset_v1/` 通过 GATE-TRAIN-001 校验；
2. 渲染：每个 GLB 按固定机位集渲染（正面 0°/45°/90°/135°/180° + 俯仰 ±15°，共 8 视角），分辨率统一；
3. caption 落盘：`<sample_id>.txt` 与渲染图同名同目录；
4. 切分锁档：训练/验证清单 SHA256 写入 truth-ledger，防止切分漂移；
5. 污染扫描：负面词命中率、异色异质样本剔除，剔除记录入 `rejects/` 留痕。

### 6.4 Q4｜怎么训练之二：超参规范（适配 Text-to-3D 扩散 LoRA）

| 参数 | 取值 | 说明 |
|---|---|---|
| 训练方式 | 3D-Diffusion LoRA | 低秩注入，可插拔可回滚 |
| 学习率 | `1e-4 ~ 2e-4` | 常量调度 + 线性 warmup 100 步 |
| 迭代轮数 | `1200 ~ 2500` 步 | 按 §6.5 评估曲线选早停点 |
| 批次 | 小 batch 精训（train_batch_size=1~2） | 配梯度累积 4~8 等效大批 |
| LoRA rank | 32（风格紧凑）/ 64（角色细节重） | alpha = rank × 2 |
| 冻结范围 | VAE/几何解码器全冻结 | 保证几何质量不回退 |
| 正则 | 世界观风格正则（对照集 + 正则 Prompt） | 防止画风向基座均值回归 |
| 数据增强 | 轻微视角、光影扰动 | 幅度受控，**不破坏基准真值** |
| 混合精度 | bf16 | fp16 需额外 loss scale 时才用 |
| 检查点 | 每 250 步存档 + 保留最优 3 个 | 便于早停与回滚 |
| 随机种子 | 固定并入 manifest | 保证可复现 |

### 6.5 Q4｜怎么训练之三：过程评估与验收

**训练中（每 250 步）自动评估三项**

| 指标 | 口径 | 用途 |
|---|---|---|
| 短 Prompt 命中率 | 短 Prompt 生成 → 算子组 + 抽检，判定是否符合该神祇法定特征 | 主早停指标 |
| 人设串扰数 | 生成 A 神祇却出现 B 神祇特征的样本数 | 必须为 0 |
| 算子 pass 率 | OP-KUNLUN-001~004 全 pass 比例 | 不得低于阶段 1 baseline |

**最终验收（GATE-LORA-001）**

1. 短 Prompt 评测集通过率较阶段 1 baseline 提升 **≥ 30pp**；
2. 人设串扰 **0 例**；
3. 算子 pass 率不低于阶段 1 baseline（几何质量无回退）；
4. 消融验证：**去掉长 Prompt 堆砌**，仅输入神祇名（如"太阴月神"）即可稳定产出朱砂红裙、月白银纹、月华光影、幽柔神性、昆仑标准光影、标准仙侠比例；
5. LoRA 权重 SHA256 + 训练配置 + 数据清单哈希三件套写入 truth-ledger 锁档；
6. 验收未通过 → 回滚：下线该 LoRA，产线继续以阶段 1 规则版运行（分层解耦价值的直接体现）。

### 6.6 训练后效果质变（有无 LoRA 对照）

| 维度 | 现在（无 LoRA） | 未来（带昆仑 LoRA） |
|---|---|---|
| Prompt | 必须超长精准堆砌 | 短 Prompt 甚至仅神祇名 |
| 校验 | 层层校验 + 强规则约束 | 规则层降级为兜底抽检 |
| 稳定性 | 稍有偏差就崩 | 分布级稳定 |
| 人设区分 | 靠人工分桶约束 | 隐空间原生分域 |
| 迭代成本 | 改 Prompt 即时生效 | 规则层仍即时，权重层按门禁迭代 |

## 7. 阶段 2：自生长数据集全自动流水线（工程详设）

### 7.1 设计原则

1. **零人工标注**：标签由产线真值直出，不靠事后标注；
2. **非全量入库**：只有五重条件全满足的资产才允许进入训练集；
3. **只进不改**：入库样本不可原地修改，修正一律新增版本；
4. **留痕闭环**：剔除也留痕（`rejects/` + 原因码），可审计可回溯；
5. **哈希确权**：每批入库自动生成 SHA256 与 Merkle 聚合，写入 truth-ledger。

### 7.2 五重入库条件（全部满足才入库）

| # | 条件 | 判定来源 |
|---|---|---|
| 1 | Skill 前置裁决 = PASS | Skill 裁决语义层日志 |
| 2 | OP-KUNLUN-001 / 004 无违规 | 世界观与合规算子 |
| 3 | OP-KUNLUN-002 尺度合规 | 尺度算子 |
| 4 | OP-KUNLUN-003 网格水密合规 | 水密/网格算子 |
| 5 | 人工抽检无崩坏（可选抽样，默认抽检率 5%） | 抽检工单 |

### 7.3 自动打标体系（metadata.json 字段规范）

每条样本自动绑定真值标签，**必填字段缺失即拒收**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `sample_id` | string | 全局唯一，`KL3D-<神祇/场景>-<yyyymmdd>-<seq>` |
| `deity_id` / `scene_id` | string | 神祇 ID / 场景 ID（唯一，禁止并存） |
| `asset_type` | enum | `character` / `scene` / `weapon` |
| `operator_records` | object | OP-KUNLUN-001~004 各自 pass/fail + 时间戳 |
| `skill_verdict` | string | 前置裁决结果（必须 PASS） |
| `benchmark_prompt` | string | 标准基准 Prompt（模板拼装，非自由书写） |
| `caption` | string | 训练用 caption（由 benchmark_prompt + 真值特征字段生成） |
| `audit_did` | string | 审计指纹 DID |
| `generated_at` | ISO8601 | 生成时间 |
| `baseline_version` | string | 版本基线（规则库版本 + 算子版本 + 模型指纹） |
| `sha256` | string | 资产文件哈希 |
| `split` | enum | `train` / `val`（切分后回填，冻结不可变） |

**记录示例**

### 7.5 流水线阶段定义（可直接排程的 S0-S5）

| 阶段 | 名称 | 动作 | 失败处置 |
|---|---|---|---|
| S0 | 采集 | 从生产流水线回收产出资产与全链路日志 | 落 `quarantine/` 待人工 |
| S1 | 前置裁决 | Skill 公理过滤、人设隔离、违禁熔断 | 熔断 → `rejects/` + `SKILL_FAIL` |
| S2 | 算子校验 | OP-KUNLUN-001~004（世界观/尺度/水密/合规） | 任一 fail → `rejects/` + 算子码 |
| S3 | 纯度过滤 | 画风漂移、人设串扰、破损网格、比例失调检测 | → `rejects/` + `DRIFT/CROSS/MESH/SCALE` |
| S4 | 打标入库 | 生成 metadata 条目、渲染 8 视角、切分、哈希 | schema 校验失败 → 拒收留痕 |
| S5 | 锁档上报 | 批次 SHA256 + Merkle 根写 truth-ledger，同步数据湖 | 上报失败重试并告警 |

**剔除原因码表**：`SKILL_FAIL` / `OP001..OP004_FAIL` / `DRIFT`（画风漂移）/ `CROSS`（人设串扰）/ `MESH`（破损网格）/ `SCALE`（比例失调）/ `SCHEMA`（标签缺失）。

### 7.6 纯度保障机制

- 违规资产自动剔除（S1/S2）；
- 画风漂移自动过滤（S3，与最近邻基准分布距离超阈值即弃）；
- 人设串扰样本直接丢弃（S3，标签与视觉特征不一致即弃）；
- 破损网格不入数据集（S2 水密性）；
- 比例失调样本不入数据集（S2 尺度）。

**最终得到：全网唯一、纯原生昆仑洞天高质量纯净 3D 数据集。**

### 7.7 自动化调度与运行契约

- **触发**：周期调度（心跳驱动），按 S0→S5 单向推进，禁止跳步；
- **幂等**：以 `sample_id + sha256` 去重，重复批次直接跳过；
- **观测**：每批输出计数、纯净度、剔除原因分布，异常自动上报记忆网关；
- **落位**：脚本归 `02_SKILLS/`（算子/技能类），数据归 `01_ASSETS/`，调度定义归 `00_KERNEL/` 周期任务台账；
- **不入库物**：运行态中间件、`quarantine/` 内容不进 Git（快照与源码分离，避免二进制膨胀）。

## 11. 风险与回滚

| 风险 | 触发信号 | 处置 |
|---|---|---|
| 数据污染导致权重学坏 | 短 Prompt 命中率不升反降、串扰计数 > 0 | 立即停训 → 溯源污染批次 → 从数据集剔除后重训 |
| 灾难性遗忘/几何质量回退 | 算子 pass 率低于 baseline | 回滚 LoRA，产线回阶段 1 规则版 |
| 数据量不足仍强行开训 | GATE-TRAIN-001 任一指标不达标 | 不开训，继续阶段 2 攒数据 |
| 云训练误扣费/越权 | 未审批即发起付费算力 | AxiomGate 拒绝，强制人工审批闸门 |
| 基座换代失效 | LoRA 与新基座指纹不匹配 | 以阶段 2 数据集重训 LoRA，治理层复用 |

**统一回滚语义**：任一阶段失败，最多回退到上一稳态，且**下层资产（规则、数据集、日志）永不丢失**。
