## 一、定位

多轮 Agent 通用协议栈面向跨框架、跨轮次、跨 Agent 的多智能体协作，提供三层结构：

- **生态互通层（本版公开）**：A2A 消息互通 + 状态同步（SAMP/StateMesh）+ 执行控制（AEP）
- **标准化实体引用与状态校验子模块（对内称 Ω-Refer，简化描述）**：统一实体引用、状态版本与合法性校验
- **框架适配层**：LangGraph / AG2 / CrewAI / AgentScope 适配器

核心原则：**传输由外部标准协议负责，实体引用与状态一致性由统一校验层先行把关，业务推理在其之后进行。**

## 二、生态互通层

### 2.1 通信层（A2A）

承接 V2.3 十协议族第 5 族（`/v1/a2a/kunlun/dispatch`，LIVE）：A2A 仅承载业务 payload，消息外层包裹统一头部信封。外部异构 Agent 不支持信封时自动降级为**兼容模式**（仅限信息查询，不允许长任务工具调用），降级消息标记高风险标签。

### 2.2 状态同步层（SAMP / StateMesh）

状态单元带版本号与校验哈希，同步时一并传输；接收方校验一致后加载，不一致判定传输异常并拒绝加载，防止多端状态串扰。

### 2.3 执行控制层（AEP）

执行循环 SENSE→REASON→PLAN→ACT→OBSERVE 每步入参、出参统一信封封装；ACT 前强制触发参数类型/值域校验与权限校验，非法参数不流向工具。

### 2.4 上下文管理

多轮上下文压缩产物保留完整实体引用映射表；摘要只是面向模型的可读视图，权威源始终为引用账本；摘要与账本一致性反向核验，失真即丢弃重建。

## 三、框架适配方案

框架仅实现轻量适配器，协议定义与框架解耦——框架 API 升级不触碰协议本体，适配器异常不影响协议层一致性：

- `ref_resolve(text) → 引用集合 | null`
- `state_commit(引用集合, payload) → 版本号, 校验哈希`
- `state_rollback(版本号)`
- `verify_fuse(熔断掩码)`

## 四、与 V2.3 生态栈的关系

```
外部 Agent / 框架
   │  A2A / OAuth2 / DPoP（V2.3 十协议族标准接入）
   ▼
多轮协议栈：信封封装 → 状态校验 → 执行控制 → 业务推理
   │
   ▼
工具执行 / 模型调度（OpenAI 兼容、MCP、昆仑生产协议）
```

标准接入面不变（OAuth2/OIDC → DPoP → A2A → MCP → SLIM），多轮协议栈作为其上的会话一致性层叠加，不替换既有任何标准协议。
