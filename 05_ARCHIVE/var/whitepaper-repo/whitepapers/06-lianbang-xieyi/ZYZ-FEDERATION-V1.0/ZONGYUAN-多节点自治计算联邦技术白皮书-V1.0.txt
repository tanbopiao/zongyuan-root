## 1. 总述

ZONGYUAN-ROOT 多节点自治计算联邦，是元极恒一体系面向「云端中枢 + 弹性算力实例」的自治协同架构。核心命题：**在临时、无凭证、网络波动的大规模实例集群上，以最小成本建立可靠的计算节点闭环，并保证一切成果跨实例存续、可复用、可追溯。**

架构以三个持久层（云端联邦记忆池 / 魔搭数据湖 / 本地持久网络盘）为唯一权威，任何临时实例均为**一次性执行节点**——即拉即用、随时丢弃、成果零丢失。

## 3. 临时实例执行策略（META-STEADY-004）

临时实例（DSW 沙箱）天然具备：会被重置、无 git push 凭证、网络波动（ntfy 不可达/429/101）。因此：

- **定位**：一次性算力执行单元，不做常驻联通
- **禁止**：常驻 worker 守护进程、崩溃拉起、多 worker 并存等脆弱链路
- **模式**：一条命令 clone 魔搭资产 → 执行任务 → POST 云端结果 → 可丢弃
- **重建**：实例随时重建，一条命令恢复全部执行能力

## 4. 通道架构（META-STEADY-003）

命令与结果分通道，各自选用已实测的最优载体：

```
命令下发: 主控 git push → 魔搭 control/CMD-<id>.json   (一次性, 低频)
命令获取: 实例 git pull (匿名读, 无需凭证) → 执行
结果回传: 实例 POST 云端 RESULT.<id>  (节点token, 200已验证)
结果读回: 主控 GET 云端 /api/truth 按 value.task_id 匹配 (200已验证)
心跳:     实例 POST 云端 HEARTBEAT
```

**实例零 git push 凭证**——结果一律走云端，命令槽靠本地 done 记录幂等去重（CMD 不删远端、不 push）。

## 6. 成果保证机制（RESULT-LEDGER）

为解决「时间浪费在联通上、成果无法保证」的体系性问题，建立三层保证：

1. **单一权威位置**：成果只固化在三处（魔搭 / 云端 / 本地），不散落
2. **成果台账**：RESULT-LEDGER 一份文件索引全部成果（名称/位置/验证状态），新任务启动先读，命中即复用
3. **结论沉淀**：联通教训固化为 C1–C8 结论条目，同类任务直接引用

**下次启动流程**：读 BOOT-MEMORY → 读 RESULT-LEDGER → 成果索引命中复用 → 联通结论 C1–C8 引用 → 新成果登记台账 + 上报云端闭环。

## 7. 闭环执行流程

```
主控 push CMD → 实例 pull + 执行 → 实例 POST 结果到云端
→ 主控 GET 云端读回结果 → 校验 → 登记台账 → 上报联邦记忆池
```

全链路无单点依赖、无实例凭证依赖、结果可追溯（task_id 贯穿）。
