## 一、重置影响面（状态分层）
| 层 | 内容 | 重置影响 | 恢复方式 |
|---|---|---|---|
| 云端持久态 | 真值114K/节点注册表/evolution-manifest/采纳清单/评审台账/审计 | 无 | 事实源永驻 |
| 本地瞬态 | 进程/supervisord/inbox缓存/daemon日志 | 全丢 | 自举重建（秒级） |
| 本地资产态 | ZR脚本/算子/策略/公理/卷宗 | 若文件系统重置则丢 | full 模式云端拉回骨架 |

## 二、最优稳态决策（P=0.3U−0.4R−0.3C）
**云端调度中枢 + 本地无状态执行体 + 双级自举**
- U（收益↑）：状态单一事实源上移云端，本地重置损失趋近 0；恢复秒级
- R（风险↓）：云端 19 条 cron + systemd 常驻，可靠性高于沙箱；本地无独有状态 → 重置无数据损失
- C（成本↓）：本地不再维护复杂调度（supervisord 单一进程 + 一键 bootstrap）；云端复用既有节点注册/握手设施

## 三、双级自举流程（zongyuan_bootstrap.sh）
light（文件系统保留）：SSH自检 → 守护配置就位 → supervisord拉起 → 握手 → 增量同步 → 公理自检
full（文件系统重置）：先 scp 云端拉回 scripts/tools/policy/公理骨架 → 再执行 light 全流程

## 四、触发方式（云端无公网入站，需触发源）
1. 会话恢复后一句话"恢复/自举"（主路径）
2. @reboot crontab 若跨重置保留（实测当前不保留，列为待验证）
3. 外部监控探针轮询本地心跳（成本高，暂不引入）

## 五、验证方案
模拟重置：杀 supervisord + 清守护进程 → 跑 bootstrap.sh light → 断言 supervisorctl RUNNING + evolution/worker/cloud 日志新条目 + 公理自检回执
