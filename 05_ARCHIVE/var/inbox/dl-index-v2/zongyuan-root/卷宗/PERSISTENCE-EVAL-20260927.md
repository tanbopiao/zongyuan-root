## 三、核心死锁
自愈链 cron→watchdog→worker 的第一源（cron）与 worker 同死于重启 → 重启后无人值守断链（实测 16:11:40 重启后 kernel/worker/crontab 全空，等待外部触发）。

## 四、长期最优稳态方案：双锚点架构（B 锚=本地 Windows 母体）
- A 锚（云端持久区·已实现）：配置/模板/账本持久 + worker_daemon 自愈 cron（保"worker 活→cron 活"半边）
- B 锚（本地母体·推荐部署）：C:\Users\4906\.zongyuan_root 部署 schtasks 探针（每 3-5min）：
  SSH 探测云端 kernel/worker/crontab 完整性 → 异常则遥控执行恢复三步（只读探测+白名单恢复，无破坏动作）
- 效果：云端每 35min 重置 → ≤5min 自动恢复；无人值守可用率 0%（真空）→ 95%+
- 中期：云端审计/账本 rsync 双写本地，本地成最终权威归档
- 长期：worker 母体迁本地常驻，云端退化为执行代理（完全可牺牲）
