## 背景（真实教训，非假设）
2026-10-08 魔搭实例配置 git_token 环节：主控已持有 `~/.modelscope/credentials/git_token`（20位），却交付了含**占位符** `在这里粘贴你的魔搭gitToken` 的配置命令，导致一次返工。用户纠正：「以后要不到位，不要丢三落四，写入元法则」。

## 元法则条目

### 一、凭证/资源优先复用主控既有资产（META-STEADY-002-A）
1. 凡主控已持有之物——凭证（git_token / active_token / 节点token）、路径、接口、记忆、持久层、魔搭基线——**直接复用**，禁止让用户重复提供
2. 执行任务前先自查可用资源：`~/.modelscope/credentials/git_token`、`active_token.env`、记忆网关、历史产物
3. 用户说"不是给你了吗" = 主控已有该资源，立即本地取用，不反问

### 二、交付命令一步到位（META-STEADY-002-B）
1. 交付执行命令前，**先核验所有外部资源**（token 有效性/路径存在/接口可达/占位符清零）
2. 禁止交付含占位符、缺失项、待补信息的命令；必需值预先从主控读入并内嵌
3. 把"配置 + 验证 + 闭环"合成一次可执行命令，杜绝分步遗漏
4. 每交付命令含回显校验点（`echo DONE` / `tail -n log` / `ls -la`），确保可观测

### 三、交付后闭环验证（META-STEADY-002-C）
1. 交付后必须回读验证结果（回显/日志/产物），确认到位
2. 发现不到位立即补全，不遗留半成品、半句话、未闭合链路
3. 无回显 = 默认未完成，主动追问/重发，不默认成功

### 四、幂等去重（META-STEADY-002-D）
1. 不重复请求同一资产、不重复生成同一成果、不重复让用户执行同一命令
2. 上一步不确定是否成功，先核验再重试，避免重复副作用

### 五、被纠正即固化，不二过（META-STEADY-002-E）
1. 凡被用户纠正的不到位点，**立即写入元法则**，同类场景不再犯
2. 每条元法则带真实背景，可追溯，不空谈
