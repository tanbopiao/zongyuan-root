## 一、问题定义

当前资产存储面临六大存续风险：

| 风险 | 说明 | 当前状态 |
|---|---|---|
| 单点故障 | 本地磁盘损坏、云服务商停运 | ⚠️ 单副本为主 |
| 链接失效 | 飞书文档链接变更、账号注销 | ⚠️ 依赖平台 |
| 格式过时 | .docx/.pptx等专有格式未来无法读取 | ⚠️ 未做格式迁移 |
| 静默损坏 | bit rot（比特腐烂），数据无声损坏 | ❌ 无定期校验 |
| 地域灾难 | 火灾、水灾、断电导致本地+同城副本全损 | ❌ 无异地副本 |
| 所有权丢失 | 无链上确权，资产归属无法证明 | ⚠️ 仅本地哈希 |

## 三、核心技术机制

### 3.1 内容寻址（Content Addressing）

所有资产以SHA256哈希作为唯一标识（CID），而非文件名/URL：
- 内容不变 → CID不变 → 链接永不过期
- 内容篡改 → CID变化 → 自动检测篡改
- 与元秩序Merkle-DAG哈希链天然兼容

### 3.2 3-2-1备份原则

- **3份副本**：工作原件 + 本地备份 + 异地备份
- **2种介质**：SSD（快速访问）+ HDD/磁带（长期冷存）
- **1份异地**：移动硬盘存放保险箱或异地亲友处，防火防水

### 3.3 格式迁移策略

| 资产类型 | 当前格式 | 长期保存格式 | 迁移频率 |
|---|---|---|---|
| 文档 | .docx | .pdf/A + .md + .txt | 每次锁档时 |
| 表格 | .xlsx | .csv + .pdf/A | 每次锁档时 |
| 演示 | .pptx | .pdf/A + 图片序列 | 每次锁档时 |
| 图片 | .png/.jpg | .png(无损) + .jpg(通用) | 不变 |
| 视频 | .mp4 | .mp4(H.264) + 元数据sidecar | 每5年评估编码 |
| 代码 | .py/.js | .txt + .tar.gz归档 | 每次版本发布时 |
| 哈希链 | .json | .json + .txt人类可读 | 每次锁档时 |

**PDF/A**：ISO标准的归档用PDF格式，嵌入字体，不依赖外部资源，专为长期保存设计。

### 3.4 定期完整性校验（防Bit Rot）

```
校验周期：每月一次（自动）
校验内容：
  1. 每个文件SHA256哈希与台账比对
  2. Merkle-DAG根哈希与链上记录比对
  3. 各层副本之间哈希交叉比对
  4. 损坏文件自动从健康副本修复
```

### 3.5 元数据绑定

每个资产包必须包含：
- `manifest.json`：文件清单 + 每个文件的SHA256
- `metadata.json`：创建时间、作者(DID)、版本、父卷宗哈希、资产类型
- `README.txt`：人类可读的资产说明
- `merkle-proof.json`：Merkle-DAG存在性证明

## 五、落地路径（分三阶段）

### 阶段一：本地冗余（立即执行，0成本）
1. 导出全部资产清单 + SHA256哈希台账
2. 建立3-2-1本地备份（本机+NAS+移动硬盘）
3. 关键文档格式迁移（.docx→.pdf/A+.md）
4. 部署每月自动校验脚本

### 阶段二：多云+IPFS（1-2周，低成本）
1. 钻石/黄金级资产上传飞书云盘+阿里云OSS+腾讯云COS
2. 部署IPFS节点，钻石级资产Pin到3+Pin服务
3. 元秩序台账上链（IPFS CID写入Merkle-DAG）
4. 建立跨层校验机制

### 阶段三：永久存储（按需，中成本）
1. 钻石级终稿资产上传Arweave（一次性付费，永久保存）
2. Arweave交易ID写入元秩序台账，形成链上确权
3. 建立年度格式迁移评估流程
4. 异地备份介质定期更新（每年一次）
