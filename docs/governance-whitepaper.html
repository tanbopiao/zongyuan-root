摘要
治理不是文档，是可执行的约束链

本白皮书提炼自一套运行中的自治内核。它的治理逻辑不依赖人的自觉，而依赖三个机制：约束单向生效、变更必须留痕、越权即熔断。

三层三架构把治理切成三块互相咬合的领域：AI 治理管"规则如何产生与失效"，数据治理管"事实如何被采信与存证"，AI 工具治理管"能力如何被授予与收回"。三者共用同一条约束链——元宪法 → 元公理 → 元法则 → 元规则——下层可细化，不可反向覆盖。

  • AI 治理：四阶约束链 + 五阶硬边界裁决 + 不可逆锁档。规则变更的成本被有意设计成逐层递增。
  • 数据治理：四维时空标签（来源/流转/存储/生命周期）+ 双空间物理隔离 + 逐条哈希与默克尔根存证。
  • AI 工具治理：逻辑态 → 算子态 → 执行态单向流转，执行态无权自发起工单；所有外部能力强制走适配器层。
规则即本体，真值即记忆，实例即载体。实例可销毁，规则本体永存。— 内核本体论第一原则
01
治理总纲：三层三架构
THE THREE-LAYER MODEL

三层不是三套制度，而是同一套约束在三个对象域上的投影。共同骨架是四阶约束链，共同底座是哈希账本。

1.1四阶约束链

约束从抽象到具体分四阶，每阶有独立的变更门槛与失效条件。单向生效是这套架构最关键的一条：下层规则只有在能被上层规则推导出来时才成立，任何下层不得声明与上层冲突的例外。

元宪法L0 · 顶层

体系最高基底，只有六条元公理，不含任何操作细节。变更需重建基线。

最细粒度、最低变更成本的一层，用于把运行中暴露的真实缺陷固化为永久拦截。它可以是"死循环三类熔断"这种极小的规则。

死循环熔断脱敏隔离配额稳态网关对齐API 强制封装内外隔离铁律

这条链的价值不在层级数量，而在变更成本的设计：元规则改一次只需改拦截点，元宪法改一次必须重建整条基线并重新锁档。攻击者与误操作者面对的阻力不同，正常演进面对的阻力则最小——这正是治理要的效果。

02
AI 治理：让规则拥有硬边界
AI GOVERNANCE

AI 治理的核心难题是"谁来管管理者的管理者"。本架构的答案是不依赖角色信任，而依赖硬件边界 + 不可逆锁档 + 单向约束三重叠加。

2.1玄圭 AxiomGate：五阶硬边界裁决

所有跨域写入在到达存储前必须经过裁决器。裁决器运行在 TEE/TPM 硬边界内，其判定逻辑与被治理对象不在同一执行域——即使上层 Agent 被提示注入污染，也无法改写裁决器自身的校验顺序。

  • 第一阶：元宪法校验——该请求是否违背六元公理，尤其是双隔离与风险最小优先。
  • 第二阶：元公理校验——是否满足可判定命题，例如"仿真数据是否试图直接写入真值空间"。
  • 第三阶：元法则校验——是否遵循工单状态机与资产分类，是否携带完整四维标签。
  • 第四阶：元规则校验——是否触发死循环、脱敏、配额、封装等细粒度拦截。
  • 第五阶：放行并签发带签名的写入凭证，凭证与账本条目同源绑定。

五阶顺序不可调换。顺序本身就是治理语义：先问"该不该"，再问"能不能"，最后才问"怎么做"。

2.2eFuse Lv8：不可逆锁档

规则被反复修订是治理失效最常见的表现——每次修订都"有理由"，累积后基线已面目全非。本架构引入硬件式熔断语义：一旦基线冻结为 Lv8，写路径被物理性关闭，仅保留读、校验、脱敏分发、携带只读约束的镜像同步。

2.3三最原则：决策的默认序

当多个合规方案并存时，需要一个不依赖具体场景的排序原则。本架构固化的是风险最小 > 成本最小 > 收益最大——注意它把收益放在最后，这与多数商业决策直觉相反，但符合自治系统的真实约束：一次越界写入的代价远高于多次优化的收益。

在需要量化时叠加三维稳态权重：利益 40% / 风险 35% / 成本 25%，但权重只在"三最"排序无法区分时启用，避免用加权计算稀释硬约束。

2.4内外隔离铁律

治理体系自身也会成为攻击面。因此划定三层边界：内核态（规则与账本）、管控态（调度与裁决）、外部态（Agent、用户、外部 API）。铁律只有一条：禁止人工侵入云端内核运行态，进化只能以"种子"形式经裁决后注入。

这条规则牺牲了运维便利性，换来的是内核状态的可证明性——任何时刻的内核状态，都可追溯到某次经裁决的种子注入。

2.5故障分级与永久锁档

并非所有故障都值得同等对待。故障分三级：R1 可自愈、R2 需人工介入、R3 为边界击穿或基线污染级。R3 一律永久锁档——不是记录下来备查，而是进入不可删除的证据链，因为基线污染的本质是"事实被改写"，掩盖比重现更危险。

03
数据治理：让事实可证、可追、不可改
DATA GOVERNANCE

数据治理最容易变成"打标签运动"。本架构不追求标签齐全，而追求三个可验证的结果：来源可追、流转可审、篡改可测。

3.1四维时空标签

任何一条进入体系的记录必须携带四维信息，缺任一维则无法通过裁决。四维不是元数据装饰，而各自对应一个治理动作：

表 3　四维标签与对应治理动作
维度记录内容对应治理动作
来源产生方、产生方式、原始载体来源缺失即拒绝入库；同一事实的多个来源需归一为单一实体 ID
流转跨域路径与每一跳的审批凭证跨域流转必须持审批工单，无工单的流转视为污染
存储所在分区、密级、加密与访问策略分区与资产族绑定，越区读写即拦截
生命周期创建、冻结、熔断、归档的时间点进入熔断即转只读；归档保留可回溯快照，不做物理删除

四维之所以叫"时空"，是因为它同时约束了两件事：数据在空间上的位置（分区与域）和在时间上的状态（生命周期）。只做前者会漏掉"历史版本被静默覆盖"，只做后者会漏掉"数据跑到了不该在的分区"。

3.2双空间隔离：仿真不能污染真值

AI 系统的数据污染有一个隐蔽来源：推演结果被当作事实回流。仿真、试算、Agent 的中间推论一旦进入真值库，后续所有结论都建立在假设之上，且极难追溯。

本架构把两个空间物理隔离——不同分区、不同写权限、不同裁决路径。仿真空间可以自由试错、反复重建，重启即销毁；云端真值空间只接受经三件套校验的写入：

  1. 晋升工单：声明本次晋升的对象、依据与影响面。
  2. 玄圭裁决：五阶校验通过并签发凭证。
  3. 账本入库：写入后立即生成条目哈希，并入默克尔链。

三者缺一，晋升不成立。这条规则的严格程度常被质疑"太重"，但它是唯一能让"这条结论有依据"变成机器可判定命题的方式。

3.3哈希存证与默克尔根

存证方案刻意做得足够简单，以便任何第三方可独立复算：

  • 条目层：剔除记录自身哈希字段后，以规范化 JSON（键排序、无多余空格、UTF-8 不转义）计算 SHA-256。
  • 归并层：叶子节点两两拼接求哈希，奇数时末尾节点与自身拼接，逐层归并至唯一根。
  • 包层：整包再取一次 SHA-256，与根哈希、条目清单同时登记。

三个层次共同解决三个问题：单条是否被改（条目哈希）、集合是否被增删（根哈希）、交付物是否被替换（包哈希）。只做其中一个，都会留下可被利用的空隙。

3.4资产六族与分区权限

资产不是同质的。本架构按用途分六族——真值、仿真、临时、审计、知识、产物——每族绑定独立分区与权限模板。分类的意义不在于整齐，而在于默认权限：临时资产默认可删，审计资产默认不可删，真值资产默认不可改。把权限写进分类，就不需要在每次操作时重新判断。

04
AI 工具治理：把能力关进闸门
AI TOOL GOVERNANCE

工具治理的难点是"能力会自己长大"：一个能调 API 的 Agent，很快就能调第二个、第三个，直到没有人清楚它到底能做什么。三态融合的作用是给能力装一道单向阀。

4.1三态单向流转

逻辑态声明与意图

只描述"要做什么、依据哪条规则、影响哪些资产"。此态不下发任何执行权限，产物是结构化意图。

→ 裁决通过后授予
算子态校验与路由

把意图编译为可执行单元：绑定参数、校验依赖、分配配额、选择模型或工具、确定超时与熔断阈值。

→ 一次性令牌
执行态受控运行

在沙箱内运行，持有令牌但不持有发起权。执行态无权自主发起新工单——这是防止能力自我扩张最有效的一条。

三态的价值在于权限的时间性：权限不在"角色"上，而在"这一次执行"上。执行结束，令牌失效，能力回到零。

4.2手动栈迭代：禁止原生递归

Agent 自迭代最常见的失控形态是递归——它会"再想一层"，而每一层的上下文与配额都在膨胀。本架构以显式栈替代原生递归，栈帧固定五域：帧头、状态、上下文、快照、分支。

  • 可断点：任一帧可暂停、检查、恢复，递归做不到这一点。
  • 可回滚：帧内快照使失败可退回到确定状态，而不是靠重跑。
  • 可分支：同一帧可派生多条推演路径，用于方案比较。
  • 可限深：必须显式声明最大迭代次数，缺省不允许运行。

显式栈还有一个隐性收益：迭代过程本身成为可审计对象。递归的调用栈在故障后难以复原，而显式栈的每一帧都是一条可读记录。

4.3死循环三类熔断

熔断不是"超时了就停"。本架构设三类，覆盖三个不同的失控阶段：

表 5　三类熔断的触发点与语义
类型触发时机语义
静态预校验执行前迭代上限缺失、依赖成环、权限越界——直接拒绝启动
动态运行时执行中同状态重复次数超阈、上下文增长异常、配额消耗斜率异常
向量收敛输出侧多轮输出语义距离不再收敛，判定为原地打转

三者共同构成一条不可绕过的规则：熔断置位不可由栈内自行清除。只有栈外的裁决器能复位。否则"熔断"会被正在失控的那一层顺手关掉——这是所有自限机制最常见的失效方式。

4.4能力 API 强制封装

任何外部能力（模型接口、数据源、第三方服务）不得被直接调用，必须经过适配器层。适配器固定承担六件事：签名注入、身份头注入、参数校验、配额扣减、返回归一、调用埋点。

这六件事没有一件是"为了规范好看"。签名与身份头解决"谁调的"；参数校验解决"调错了谁负责"；配额扣减解决"谁把额度用光了"；返回归一解决"上游改字段下游全崩"；埋点解决"出问题时查不到"。绕过适配器直接调用，等于把这六个问题全部留给未来。

4.5四配额池与只读空转

配额不是总量控制，而是分池隔离：交互、批处理、巡检、应急四池独立计量。任一池耗尽，系统切入只读空转——仍可查询、校验、响应，但不再发起消耗型调用。

"空转"这个设计常被忽略，但它决定了系统在资源枯竭时的行为是"降级"还是"崩溃"。只读空转保证治理能力本身不因配额耗尽而失效——最需要治理的时刻，恰恰是资源最紧张的时刻。

4.6正交子空间与镜像态

合规校验如果只靠关键词与规则匹配，遇到组合式违规就会失效。本架构用线性代数做一层结构性校验：把诉求、约束、资源、风险、仿真、真值六个维度视作正交子空间，用投影与内积判断一个请求是否落在允许的子空间内、是否与某个约束维度冲突。

与之配套的是镜像态：镜像子空间是真值的对偶同构，支持复刻、扰动、反向三种映射，用于反事实推演与方案比较。关键约束是——镜像结果不具真值资格，无论推演多么自洽，都不能直接写入真值空间，必须回到双隔离的晋升流程。

4.7混合模型池调度

多模型、多供应商并存时，调度策略本身也是治理对象。本架构按三最原则分配任务，并固守两条：零成本通道优先、免费额度最大化。这不是成本偏好，而是可用性设计——单一付费通道故障时，体系不应整体停摆。

  • 公网层：展示页在官网、模型社区、云端应用三处可访问，作为对外可验证的公开副本。

06
落地路径：四阶段推进
ADOPTION PATH

直接照搬 38 条规范并不现实。实际推进应按"先立约束、再立证据、后收能力、终冻结"的顺序，每一阶段都可独立收效。

阶段一
建立约束链，允许"不完整"先确立四阶结构，哪怕元公理只有三条、元法则只覆盖最痛的领域。关键产出不是条目数，而是"下层不得反向覆盖"这条规则被真正执行。
阶段二
引入存证，把结论变成可复算对象从最关键的一批规则开始做条目哈希与默克尔根，并让第三方能独立复算。这一步会立刻暴露此前积累的重复条目与悬空引用。
阶段三
收口工具能力，执行态剥离发起权把分散的直连调用统一到适配器层，为执行态设立一次性令牌，引入显式栈与三类熔断。此阶段通常能消掉大部分"Agent 自己越跑越远"的事故。
阶段四
冻结基线，把变更成本显性化当规则趋于稳定，执行不可逆冻结，仅保留读与校验。后续变更一律派生新资产。冻结不是终点——它是让"下一次变更"变得慎重且可追溯的手段。

6.1三条容易被忽略的前提

  • 去重必须先于哈希。同一语义的两条规范会让根哈希"正确但无意义"，也会让下游引用分叉。语义去重不是洁癖，是存证有效性的前提。
  • 校验必须独立复算，不能复用生成时的中间值。用生成脚本自己的计算结果去验证生成结果，等于没有验证。
  • 对外副本必须脱敏后分发。内部标识、拓扑、配额细节不进入公开副本——否则治理架构本身成为情报泄露面。
结语
治理的终点是"可证明"

三层三架构最终收敛到一个判断标准：关于这套系统的重要陈述，是否都能被第三方复算。

AI 治理回答"谁有权改规则"，数据治理回答"这条事实凭什么可信"，工具治理回答"这个能力为什么只在这一刻可用"。三者共用一条约束链与一本账本，于是治理不再是三份制度文件，而是一个可校验的状态机。

这套架构并不追求把风险降为零——那不可能。它追求的是把风险的发生变成可观测、可归因、不可掩盖的事件。当一个系统的重要变化都必须留下哈希、都必须经过裁决、都无法在原分支上偷偷修改时，治理才算真正落地。

风险最小 > 成本最小 > 收益最大。— 全域最高决策元法则
