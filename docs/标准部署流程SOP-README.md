## 一、SOP 定位

本 SOP 定义体系所有应用层产物（白皮书 HTML / 官网页面 / 子域名站点 / 部署包）的标准部署流程，解决：**SSH 受限、元内核隔离、多通道并存**三大现实约束下的可靠部署。

## 二、部署通道矩阵

| 通道 | 适用 | 权限 | 状态 |
|------|------|------|------|
| **A. SSH 直连**（zongyuan-cloud） | 白皮书 nginx 落盘 | 持 deploy_vm 公钥节点 | ✅ 可用（受限） |
| **B. 飞书审批自动部署** | 需审批的应用部署 | 审批通过后 zr-deploy 执行 | ✅ 可用 |
| **C. TAT 通道** | 隔离部署位置探测 | 只读探测 | ✅ 可用 |
| **D. 独立 nginx location** | 新隔离站点 | 独立 location 不触碰元内核 | 🔄 验证中 |
| **E. 种子真值投喂** | 元内核配置变更 | 仅 L0 结构化种子→仲裁引擎 | ✅ 唯一改法 |

## 三、标准部署五步流程

```
① 产物准备 ──→ 本地 Write 产物 + 内容验证（关键内容/Ω标识/SHA256）
      │
      ▼
② 通道评估 ──→ 按部署矩阵选通道（默认 SSH→审批→TAT→隔离location）
      │
      ▼
③ 执行部署 ──→ scp落盘 / zr-deploy引擎 / nginx location 配置
      │
      ▼
④ 实测验证 ──→ curl HTTP 200 + 内容抽检（必经，禁止"应该OK"）
      │
      ▼
⑤ 归档回写 ──→ Git双仓推送 + 台账更新 + 记忆网关上报
```

## 四、飞书审批自动部署链路

```
需求方提交部署工单
      │
      ▼
共享大脑任务台账登记（状态=待开始，优先级=P0/P1）
      │
      ▼
发起飞书审批（含目标URL/产物哈希/通道）
      │
      ▼
审批通过 → 消费工单 → zr-deploy 执行引擎落地
      │
      ▼
curl HTTP 200 验证 → 台账回写"已部署" → 上报真值
```

**关键**：审批未通过 → 工单保持待审批，AI 无权绕过。

## 五、zr-deploy 通用执行引擎

```bash
# 部署白皮书类产物
python3 zr_deploy.py deploy \
  --asset <本地文件> \
  --target https://huodouai.com/whitepaper/<name>.html \
  --channel ssh|approval|tat \
  --verify 200

# 验证（不可跳过）
python3 zr_deploy.py verify --url <URL> --expect 200
```

## 六、域名与站点管理

- 新子域名优先复用服务器未占用域名（先 DNS 解析探测）
- 独立站点走独立 nginx location，与元内核隔离，不触碰既有部署
- 域名接管：已部署好的旧官网不动，新站点独立运营

## 七、铁律（写入审计）

| 规则 | 级别 |
|------|------|
| 部署前必须本地验证产物完整性 | ✅ 必须 |
| 部署后必须 curl 实测 HTTP 200 | ✅ 必须（禁止"应该OK"） |
| 改配置前必须备份原文件 | ✅ 必须 |
| SSH 仅用于白名单操作，禁止改元内核 | ✅ 必须 |
| 元内核唯一改法 = 种子真值投递（L0→仲裁→锁档） | ✅ 必须 |
| 部署类操作需人工审批，不自动执行 | ✅ 必须 |
| 部署失败→记录问题阻塞表→换通道重试 | ✅ 必须 |

## 八、部署验收清单

- [ ] 产物本地存在且内容验证通过
- [ ] 通道按矩阵选择且权限正确
- [ ] 部署后 curl HTTP 200
- [ ] 页面关键内容抽检一致
- [ ] Git 双仓 commit + push 完成
- [ ] 台账状态 = 已部署 + 反馈数据
- [ ] 记忆网关上报（value 字段规范）
