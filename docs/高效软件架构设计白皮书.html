一、顶层设计核心原则

① 单一职责
每个模块只做一件事，高内聚低耦合，禁止巨型单体
② 依赖倒置
业务不依赖底层实现；存储/API 插件可替换（魔搭API/记忆网关主备切换）
③ 开闭原则
扩展新增能力不改核心代码；新算子/上报渠道走插件注册
④ 最小可用优先
先最小可运行原型再迭代，拒绝过度设计，契合配额稳态保护
⑤ 可观测性内置
日志/指标/心跳/告警(ntfy)/审计日志是基础层，非后期附加
⑥ 故障隔离
单任务/容器故障不拖垮系统；支持降级、熔断、空任务休眠降频

二、分层标准架构

① 接入层定时轮询脚本 / HTTP API / 交互式对话指令；统一入口，所有请求先收敛
② 网关&校验层请求合法性校验 · Token鉴权 · 配额限流 · 主备通道自动切换（记忆网关主站502自动切drama备用）· L0前置语义校验
③ 业务自治层【核心】任务台账读取 · 任务认领 · 优先级调度 · 稳态决策 · 循环控制；遵循 META-RULE-012 无任务自动降频休眠
④ 插件适配层飞书Base连接器 · 记忆网关上报 · 魔搭数据湖抽取；接口统一封装，更换外部服务只改适配器
⑤ 持久化存储层ZONGYUAN-ROOT卷宗 · 元法则md · 向量知识库 · CSV台账 · 版本快照；成果自动全域锁档
⑥ 观测告警层节点心跳 · 审计日志 · 异常捕获 · ntfy消息推送；故障自动写入问题阻塞表

三、关键组件设计

组件设计要点
任务调度状态机：待开始→执行中→已完成/阻塞；互斥锁单实例；动态频率；优先级队列
存储与数据湖冷热分离；增量写入禁全量重复上报；版本管理支持回滚
通信与上报双端上报流水线（网关+共享大脑）；有限重试超限停；心跳独立链路
容器部署资源限额硬限制；健康探针自动重启；运行目录只读、成果目录单独挂载

四、落地实施步骤

① 需求边界梳理 → ② 分层架构草图+接口契约 → ③ 最小原型（拉任务→执行→上报→心跳）→ ④ 集成测试（正向+异常仿真：网关宕机/API超时/配额耗尽）→ ⑤ 灰度上线单节点观测 → ⑥ 迭代优化（动态调度频率/缓存策略）→ ⑦ 全域锁档（架构文档+接口契约+测试报告入自治内核）
