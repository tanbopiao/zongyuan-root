2四条范式全景（含 CTDE 与显式通信的对比要点）

A · 中心化

Centralized
  • 中心收集全观测 → 统一规划 → 下发动作
  • 代表：集中调度、SWARM 集中规划
  • 缺点：单点故障 · 通信/算力爆炸 · 实时性差
  • 优点：信用分配天然解决 · 全局最优可寻

B · CTDE（隐式）

Centralized Training / Decentralized Exec.
  • 值分解线：VDN → QMIX（Q_tot 分解/单调混合）
  • 策略梯度线：MADDPG → FACMAC、COMA
  • 注意：无显式信道，靠默契，噪声下协作易崩
  • 优点：执行零通信开销 · 训练稳定

C · 显式通信去中心化

Explicit Communication
  • CommNet：全连接广播，连续通信向量
  • TarMAC：attention 定向消息，按接收者定制
  • DGN：图卷积聚合邻居信息
  • 优点：显式协作 · 抗噪声 · 可扩展
  • 缺点：通信成本 · 冗余 · 学出"语言"不可解释

D · LLM 协作

Language-Driven
  • 框架：AutoGen / CrewAI / MetaGPT / LangGraph
  • 角色分工 + 工具调用 + 共享上下文
  • 优点：可解释 · 零强化训练 · 角色灵活
  • 缺点：Token 成本 · 幻觉传播 · 无全局优化保证

演进主线：从"共享奖励·隐式默契"（值分解）→"个体归因·反事实"（策略梯度）→"显式消息·意图可读"（通信）→"语言协作·零训练"（LLM）。可解释性与灵活性逐步上升，代价是通信/推理成本上升。
4贯穿四范式的共性难点

非稳态

队友即环境，策略互变 → 训练震荡；需缓解（CTDE / 通信注意力）

信用分配

联合奖励→个体贡献难归因；值分解 / 反事实 / 消息因果各自应对

扩展性

N 增大动作空间指数爆炸；分解 / 图结构 / 层次化缓解

对齐与安全

奖励黑客 / 旁路行为、目标冲突仲裁、可解释审计、故障容错

5工程落地层（系统级难点）
分布式部署异步执行·时钟同步 · 异构融合不同模型/能力接入统一协议 · 消息总线带宽/延迟/丢包/优先级 · 状态一致性共享工作区/竞态 · 故障容错降级/重组/心跳 · 评估基准协作质量/效率/能耗 · 安全审计决策追溯/权限边界
选型结论：中小规模·纯合作 → QMIX； 异构·连续·混合博弈 → MADDPG / FACMAC； 需显式协同·抗噪声 → TarMAC / DGN； 要可解释·快速搭建 → LLM 框架（AutoGen / CrewAI）； 上百节点·强容错 → 层次化 + 显式通信。
