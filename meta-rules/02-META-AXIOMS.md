## M1 变更必留痕（真值不变 · append-only 语义）

**公理**：内容可变，但每一次变更必须在账本留下版本记录。

**判定谓词**：

```
sha_disk(p) ∈ { e.sha256 | e.path = p }   → 合规（含版本演进）
否则                                       → 变更未留痕（违规）
```

**分级**：

| 情形 | 判定 |
|---|---|
| 本条 sha = 磁盘 sha | 合规 |
| 本条 sha ≠ 磁盘 sha，但账本另有同 path 同 sha 记录 | 合规版本演进 |
| 本条 sha ≠ 磁盘 sha，且账本无当前 sha 记录 | 变更未留痕（违规） |

**不采用「字节不可变」语义的原因**：校验脚本每次迭代 sha 必变，字节不可变语义下脚本永远违反自身负责的公理。已实测：违规 19 条中有 1 条是脚本自己。

## M1.1 可追溯（原 M3，降为 M1 实现子句）

**从属声明**：M3 不是独立公理。无 `sha256` 则无法判断是否变更，无 `timestamp` 则无法判断变更先后——它是 M1 的**判定前提**。

**判定谓词**：

```
has(sha256) ∧ has(timestamp)  → 合规
```

**保留原编号 M3 以便历史追溯，但不再单独计入公理独立性门槛。**

## M2 单调收敛（操作化定义 + 衰减容差）

**原文缺口**：「收敛」与「回退」均未定义，原始表述不可判定。

**操作化定义（翻译引入的假设，非原文）**：同一 `path` 按 `timestamp` 排序，`value_score` 不得异常下降。

**衰减容差**：

```
value_score(t) ≥ value_score(t−1) × (1 − τ)     τ = 0.20
```

| 情形 | 判定 |
|---|---|
| 非降 | 合规 |
| 降幅 ≤ 20% | 合规衰减（记 `compliant_decay`，不报警） |
| 降幅 > 20% | 违规，进人工裁决队列 |

**引入理由**：实测抓到 `runtime/memory_index.json` 由 97 降至 80 被误报——价值分随资产重要性变化会自然衰减，「只升不降」会持续误报。τ=0.20 为经验阈值，非原文定义。

**未消除的张力**：「禁回退」与「修改需审批」——审批通过的修改算不算回退，本公理不作裁定，留人工位阶。

## M4 资产类型公理（AXIOM-AVT-001）

> 生效 2026-11-07 · 由元公理候选转正 · 依据 META-LAW-AVT-000

规则即本体，轨迹即经验，事实即记忆，噪声即边界样本。

| 项 | 本体地位 | 处置原则 |
|---|---|---|
| 规则 rule | 本体（最高） | 注入 AxiomGate，不可裁剪 |
| 轨迹 experience | 经验（稀缺） | 提炼为 SOP/技能包，不得判为噪声 |
| 事实 fact | 记忆 | 入检索层，按置信度分层 |
| 噪声 noise | 边界样本 | 不检索、不训练，仅作负样本 |

**判定谓词**：`type ∈ {rule, experience, fact, noise, poison}`

派生约束：
- 资产价值由类型决定，不由形态（长度/重复/结构）决定；
- 任何仅凭命名空间相似或长度过短的降级判定，违本公理；
- 清洗不删只隔离，索引须登记 type / value_score / reuse_hint。
