## 二、内核强制生效规则

### 规则1：统一产品架构四层规范（不可突破）

所有新增产品必须遵循四层架构规范：

```
L0 产品元数据层
├── 唯一产品ID（PROD-XXX格式）
├── 产品定位（一句话真值）
├── 真值锚点（绑定的真值条目ID列表）
├── 版本号+发布时间
└── Merkle哈希确权

L1 产品展示层
├── 统一视觉规范（黑金暗纹+溯源标识）
├── 统一交互规范（加载/错误/成功反馈）
├── 统一导航规范（产品切换栏+面包屑）
└── 统一响应式规范（桌面/平板/移动端）

L2 产品功能层
├── 各产品独立功能模块
├── 复用通用组件库（认证/权限/日志/导出）
├── 统一API网关接入
└── 统一错误处理+降级策略

L3 产品真值层
├── 每个产品声明必须绑定真值条目
├── 提供真值验证功能（用户可点击验证）
├── 真值变更触发产品版本升级
└── 真值凭证可下载（PDF+哈希签名）
```

**强制约束**：未通过四层规范校验的产品，禁止上线发布。

### 规则6：产品真值可验证（核心差异化）

每个产品页面必须包含"真值验证"区块：

```
┌─────────────────────────────────────────┐
│ 🔍 真值验证 - 点击验证本产品声明         │
├─────────────────────────────────────────┤
│ 产品声明：[具体声明内容]                 │
│ 绑定真值：[真值ID列表]                   │
│ Merkle根：[哈希值]                       │
│ [验证声明] [查看真值] [下载凭证]         │
└─────────────────────────────────────────┘
```

**验证流程**：
1. 用户点击"验证声明"
2. 前端调用云内核API获取真值完整内容
3. 本地计算Merkle哈希，与页面显示比对
4. 显示验证结果（✅已验证 / ❌验证失败）
5. 用户可下载真值凭证（PDF+哈希签名）

**强制约束**：
- 所有主推产品页面必须包含真值验证区块
- 验证逻辑必须前端本地计算，不可仅依赖后端返回
- 凭证必须包含完整真值内容+哈希+时间戳+签名
- 这是元极恒一体系的核心差异化："可验证的AI，不是黑盒"

## 三、法则执行与校验

### 执行时机
- 新产品上线前：必须通过四层规范校验
- 产品更新时：必须校验真值锚点一致性
- 每日自进化：自动校验所有产品的法则符合性
- 域名变更时：必须校验双域名定位铁律

### 校验失败处理
1. 轻度违规（如视觉规范不统一）：自动修复+记录
2. 中度违规（如真值锚点缺失）：阻断发布+要求整改
3. 重度违规（如双域名混淆、越权操作）：熔断隔离+人工审核
4. 所有违规记录写入Merkle-DAG审计链

### 法则变更流程
- 本法则为L2元法则，可由源序层自进化生成/废止
- 变更必须经过：提案→沙箱验证→影响评估→人工确认→生效
- 变更历史永久保留，不可删除
