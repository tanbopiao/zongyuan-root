# 设计系统治理规则

复杂项目的设计系统九成死在治理，不是死在画得好不好看。以下规则为硬约束。

## 一、准入（新增 Token / 组件）

任何新增必须走提案，缺一项打回：

1. 用途：解决什么具体问题，现有资产为什么不够用；
2. 复用预期：预计被几个页面/几条业务线使用，少于 3 处一律不做，走页面局部方案；
3. 依赖清单：用到哪些已有 Token，是否引入新 Token；
4. 影响范围：会不会影响已有页面；
5. 状态：初版一律 `status=alpha`，稳定使用两周以上才可升 `beta`。

## 二、审批

| 变更类型 | 审批人 | 门槛 |
|---|---|---|
| 新增语义 Token | 设计系统负责人 | 附对比度校验 |
| 修改原始色值/字号 | 设计系统负责人 + 品牌 | 需全域通告 |
| 新增基础组件（primitives） | 设计系统 + 前端负责人 | 五件套齐全 |
| 新增业务组件（domain） | 业务线提案 + 设计系统复核 | 复用≥3 处 |
| 破坏性变更（改名/删除） | 人工审批（META-003 解锁） | 升 major 版本 |

## 三、巡检（自动，不可跳过）

- `lint:hardcode`：扫描组件内 `#XXXXXX`、`rgb(`、裸 px 间距；
- `audit:tokens`：扫描 `var(--ds-*)` 与 TS 常量引用，是否存在未定义 Token；
- 两项任一失败，CI 阻断合并；存量违规登记白名单，只减不增。

## 四、废弃

标记 `deprecated` → 写替代组件与下线日期 → 灰度两个月 → `archive/` 锁档留痕。**禁止直接删除**，删除会打断下游且无法回溯。

## 五、版本与记账

每次合并生成语义版本号，写 `CHANGELOG.md` 一行：版本 / 日期 / 变更摘要 / 影响面 / 审批人。锁档资产追加 SHA256 与 Merkle 指纹，对齐 ZONGYUAN-ROOT 归档与 DID-BR-000002 确权。

## 六、单源真值冲突消解

设计与工程出现两套值时，以本仓库 `tokens/tokens.json` 为准；如确需变更，先在仓库改、生成、再同步到设计工具，不允许反向覆盖。
