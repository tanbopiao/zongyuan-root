一、背景与定位

在多窗口、多开发环境、多外部开源节点的体系下，任何单一节点都只是局部认知。本体系以云内核记忆网关为共享真值中枢，让所有同源节点在同一基线上协作：成果上报、经验沉淀、多方对账、集中裁决、各自执行、反馈闭环——避免重复开发，实现共享记忆驱动的集体进化。

二、体系架构

2.1 连接通道（域名优先）

统一走域名通道 drama.huodouai.com，不依赖 SSH、不依赖 IP 白名单、不依赖内网。IP 直连（123.207.202.158）被云端拦截，域名放行，保证任意位置的节点都能握手。

2.2 核心组件

  • 记忆网关 9120：内核真值中枢，唯一握手点，Merkle 锁档、真值入库、审计留痕；内核口 IP 白名单（仅回环 + AI 运行环境出口 IP）。
  • 业务网关 8100：对外业务入口，承接 /api/gateway/report（外部上报）与 /api/gateway/truths（分级读取），Token 鉴权，转发内核。
  • 握手 SOP V1.0：新节点接入操作手册，7 步完成 环境自检 → 云端探测 → 鉴权握手 → 基线对齐 → 稳态裁决 → 上报锁档 → 错误对照。

三、外部写入机制（本轮打通）

关键修复

原机制存在「假成功真拒绝」：外部节点按 SOP 平铺格式（truth_type/truth_content）上报时返回 success:true 但 synced:0——内核只认 truths 字典格式，平铺数据被静默丢弃。

修复方案：业务网关 report 接口增加格式兼容层，自动完成转换：

外部节点平铺上报→兼容层包装 truths 字典→键 EXT.{node_id}.{ts}→标记 source=external→9120 真实入库

实测：公网上报 synced:1 真实入库；无 Token 仍 401；机密真值在 public 读接口保持拦截。

四、安全与隔离设计

  • Token 鉴权：X-Capture-Token 双层校验（业务网关 + 内核），无凭证一律 401。
  • IP 白名单：内核 9120 仅放行回环与 AI 运行环境出口，公网业务统一经 8100 转发。
  • 机密分级：A 类机密 key（含明文凭据）读取一律 403；public 级读取过滤内部敏感前缀（SSH/部署/密钥类）。
  • 外部隔离：外部节点数据带 EXT. 前缀与 source=external 标记，与内部真值物理可区分、可审计。
  • 限流防滥用：内核按 IP 限速 120 次/分钟，命令白名单启用。
