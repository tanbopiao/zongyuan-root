## P0 致命断点（5项）

### P0-1: 核心服务未常驻运行
- **现状**: Ω-Brainμ FastAPI服务状态"未运行"，守护进程未启动
- **影响**: 所有API端点不可访问，外部无法调用内核能力
- **证据**: `daemon_manager.py status` → "Ω-Brainμ 状态: 未运行"
- **修复**: `python3 daemon_manager.py start` 或配置systemd/supervisor
- **根因**: 创建了管理脚本但从未实际启动服务

### P0-2: 自进化循环未真正常驻
- **现状**: evolution_loop状态为"initialized"而非"running"，events_processed=0
- **影响**: 事件队列无人消费，定时触发依赖外部cron而非内核内常驻
- **证据**: status显示`"status": "initialized", "events_processed": 0`
- **修复**: `python3 evolution_loop.py` 以前台/后台模式启动常驻循环
- **根因**: 只测试了trigger单次模式，未启动daemon常驻模式

### P0-3: 负载均衡器完全崩溃
- **现状**: 启动即报`KeyError: 'host'`，无法运行
- **影响**: 多实例部署完全不可用
- **证据**: `load_balancer.py status` → Traceback KeyError: 'host'
- **根因**: instances.json保存格式与加载格式不匹配（保存时用to_dict含url，加载时期望host/port字段）
- **修复**: 统一instances.json格式，或修复_load_instances解析逻辑

### P0-4: 横向扩展为"伪执行"
- **现状**: execute_daily_expansion只是把任务名append到completed列表，没有真正实现任何功能
- **影响**: 声称完成14个P0任务，实际0个功能真正实现
- **证据**: 工具功能维度completed_tasks=0但显示进度60%；输出形态10/9=111%超目标
- **根因**: 设计为"状态机模拟"而非"功能执行器"，缺少实际实现逻辑
- **修复**: 每个任务需要对应的实际实现代码，而非仅标记完成

### P0-5: 自进化循环6阶段为模拟数据
- **现状**: _stage_truth_base/_stage_architecture等方法返回硬编码模拟值
- **影响**: 每次"进化循环"实际没有执行任何真实校验/推演/锁档
- **证据**: 方法内无实际文件读取/哈希计算/API调用，直接return固定值
- **根因**: 快速搭建骨架时用模拟数据占位，未替换为真实逻辑
- **修复**: 将各阶段替换为实际调用local_tools.py/function_call_tools.py的真实逻辑

## P1 严重短板（12项）

### P1-1: RAG引擎未配置API
- **现状**: local模式，doubao_api_key为空，本地索引仅5条
- **影响**: 语义检索用hash降级，准确率低，无法召回复杂语义
- **修复**: 配置豆包Embedding API Key，接入真实向量检索

### P1-2: rag_config.json缺失
- **现状**: config目录下无rag_config.json，每次运行用默认配置
- **影响**: RAG配置无法持久化，重启后丢失
- **修复**: 创建config/rag_config.json，写入实际配置

### P1-3: chromadb未安装
- **现状**: pip install失败（权限问题），向量库不可用
- **影响**: 无法使用标准向量数据库，只能用内存hash方案
- **修复**: 使用--user安装或切换到faiss-cpu/annoy等轻量替代

### P1-4: Function Call工具未接入模型
- **现状**: function_call_tools.py定义了8个工具和Schema，但没有接入豆包模型的Function Call机制
- **影响**: 模型无法自主决策调用工具，工具库形同虚设
- **修复**: 接入豆包API的function_call参数，实现工具自动调用闭环

### P1-5: 多模态流水线只生成prompt
- **现状**: multimodal_pipeline.py只生成prompt文本，不实际调用image_gen/video API
- **影响**: "1输入→14资产"实际是14个prompt文件，不是14个真实资产
- **修复**: 接入image_gen/image_to_video/text_to_audio工具，真正生成媒体文件

### P1-6: IM通知未配置接收者
- **现状**: im_notifier.py中receive_id为"USER_DEFAULT"占位符
- **影响**: 告警/回执无法真正发送到飞书
- **修复**: 配置实际的用户open_id或群chat_id

### P1-7: 无真正的安全/权限控制

- **影响**: 敏感配置(API Key等)明文存储，资产可被任意修改
- **修复**: 核心配置加密存储，增加访问审计日志

### P1-8: 无备份/灾难恢复机制

- **影响**: 磁盘故障或误操作可能导致资产丢失
- **修复**: 建立定期备份到第三方存储，增加快照恢复脚本
