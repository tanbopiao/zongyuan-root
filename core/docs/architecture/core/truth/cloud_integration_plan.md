## 三、融合策略（零冲突原则）

### 3.1 核心原则
**不修改云服务器现有架构，只做增量接入。**
- 云服务器现有前端、Nginx、网关框架全部保留
- 本地开发的调度器、巡检器作为"离线计算引擎"运行
- 通过Git双远程作为唯一同步通道
- 云内核恢复后再做API级在线同步

### 3.3 具体融合步骤

**第一步：Git同步通道（已完成）**
- 本地所有变更 → commit → push GitHub+Gitee
- 云服务器部署时：git pull 即可获取最新内核
- 零冲突：Git是单向推送，云服务器只读拉取

**第二步：路由增量注册（待云服务器操作）**
当云服务器API网关恢复后，注册以下路由：
- POST /api/operator/schedule → 接入本地调度器
- POST /api/operator/health → 接入巡检引擎
- GET /api/kernel/truth → 读取本地真值库
- 不覆盖现有路由，只增量添加

**第三步：控制台Basic Auth接入**
- 本地巡检报告 → 通过HTTP Basic Auth推送到 /console/
- 作为只读监控面板，不修改控制台现有功能

**第四步：OpenAI兼容代理修复**
- /v1/models 502问题，需要在云服务器上重启代理服务
- 本地已配置5个有效大模型端点，恢复后自动切换在线模式
