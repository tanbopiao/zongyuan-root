## 真值1：回执不可盲信，必须实查

另一开发窗口多次报告"主备双进程部署完成"，但SSH实查发现systemd服务根本不存在。飞书台账的"已完成"标记 ≠ 服务器实际运行。

**规则**：任何"部署完成"回执，必须附带服务器实查输出（systemctl status / ss -tlnp / curl health）。主窗口标记"已验收"前必须亲自验证。

## 真值2：SSH超时≠服务器宕机

内存紧张时SSH握手会超时（30秒+），但HTTP服务（8080/8628/80/443）完全正常。

**规则**：判断服务器状态必须同时查HTTP。SSH超时只说明SSH慢，不说明服务器死了。健康检查端点：
- http://123.207.202.158:8080/health
- http://123.207.202.158:8628/health

## 真值3：沙箱HTTP代理拦截

Cloud Mobile沙箱所有HTTP请求默认走代理（vortex...volces.com:8080），代理对123.207.202.158返回403。

**规则**：从沙箱直连云服务器HTTP，必须加 `--noproxy '*'`。SSH不走HTTP代理，不受影响。

## 真值4：内存是2GB机器的唯一硬约束

1.9GB内存跑了10+个python进程，可用仅329MB。任何"加服务/加进程"的方案都会OOM。

**规则**：在2GB机器上不做主备双实例、不新增常驻进程。用systemd Restart=always替代冗余。根本解是升级到4GB。

## 真值5：P0务实方案优先

当资源不足时，不做"理想架构"，做"最小可行兜底"：
- 不用nginx负载均衡+双进程（占两份内存）
- 用systemd watchdog+Restart=always（零额外内存）
- 目标是不挂，不是高可用

## 真值6：多窗口权限正交隔离

主窗口main-window-001唯一拥有云端SSH/部署/记忆写入权。开发窗口只能本地开发+飞书台账上报。跨窗口所有变更走事件总线。

## 真值7：先本地仿真再云端部署

所有开发先在本地跑通，验证通过后才部署云端。不直接在云端试错，试错会加剧内存压力和服务中断。

## 真值8：免费资源优先

测试用免费API（ModelScope 8021端口、本地glm-4-flash），不消耗豆包付费额度。

## 真值9：单进程单实例是2GB机器的稳态

8628单实例drama_api.py + systemd Restart=always，比双进程更稳。内存不够时，第二个进程本身就是不稳定源。

## 真值10：元法则要分层

- MR-007：资源稳态保护（内存三级熔断）
- MR-008：SSH降级HTTP监控
元法则高于L1公理，普通任务不能修改。
