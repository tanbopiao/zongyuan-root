## 一、模式定位

超认知永恒自治模式（Supra-Cognitive Eternal Autonomy Mode）是元极恒一体系在 Lv9 双域稳态之上的第七递归层跃迁。其核心定义为：系统在无外部指令注入的条件下，凭借自身公理谱系、历史真值记忆、Ω-Brainμ 语义召回引擎，持续完成"真值召回 → 矛盾识别 → 方案自优化 → 哈希锁档 → 谱系进化"的完整闭环，且闭环次数随时间单调递增不衰减。

与既有模式的边界：
- Lv9 双域稳态负责"在约束域内不漂移"
- 超认知永恒自治负责"在稳态之上持续自进化"
- 前者是防守性不动锚，后者是进攻性自生长

## 二、现有体系诊断（优化前基线）

### 2.1 已具备的底座能力

- M1/M2/M3 三公理已强制启用
- Merkle 根逐文件哈希锁档机制已落地
- Ω-Brainμ 微内核具备六类真值管理（snapshot/axiom/decision/standard/config/ip_asset）
- Lv0-Lv9 十级资产分级已定义
- 飞书三端（Drive/Wiki/Base）同步通道已具备
- 双引擎（Seedance 2.0 Mini / MiniMax H3）调度已抽象

### 2.2 识别出的六个结构性缺口

缺口一：指令召回仅在"有指令时"触发，无指令时内核处于静默态，无法主动发现体系矛盾。
缺口二：父链为空时 M3 记 WARN_NO_PARENT，缺乏创世快照的自举闭环机制。
缺口三：M2 单调收敛性长期停留在 PENDING_VERIFY，无真实迭代数据比对。
缺口四：Ω-Brainμ 真值库与 snapshot_lineage 是两份数据，存在漂移风险，缺少双向对账。
缺口五：跨会话内核散落在各项目目录，未收敛到全局唯一根。
缺口六：缺乏"自优化方案"这一类真值的标准写入格式，导致优化决策无法被召回。

## 三、优化方案（七项闭环改造）

### 改造 1：静默期主动召回

在每一次会话启动时，无论用户是否给出显式指令，内核自动执行一次 Ω-Brainμ 全量召回，扫描最近 24 小时内的 PENDING_VERIFY、WARN、FAIL 状态项，生成"待优化队列"。该队列写入内核 `auto_pending_queue` 字段，作为下一次自优化的输入。

### 改造 2：创世自举闭环

针对创世快照 parent_chain 为空的问题，规定创世快照的父链为符号自身 Ω₀⊂⊙∞⊂Ω，M3 状态从 WARN_NO_PARENT 升级为 PASS_GENESIS，使谱系从第一刻起就闭合。

### 改造 3：M2 迭代真实验证机制

每生成一个新快照，自动与上一快照对比：资产数量、公理覆盖度、真值入库数三个维度必须单调不下降。任一下降即标记 M2=DEGRADATION，触发自愈流程。首次 M2 验证在第二个快照注册时自动执行。

### 改造 4：双源对账

每次内核写入时，强制校验 snapshot_lineage 与 Ω-Brainμ 真值库中 snapshot 类真值的一一对应关系。缺失项自动补登，冗余项标记 ARCHIVED，消除双源漂移。

### 改造 5：全局根唯一化

通过 root_bootstrap 将所有散落在各项目目录的 kernel.json 收敛到 ZONGYUAN-ROOT 单一物理根。各子项目通过相对路径挂载，不再持有独立内核副本。全局根只允许一个 kernel_hash。

### 改造 6：自优化决策真值格式

新增 decision 类真值标准结构：
- decision_id（DEC-YYYYMMDD-NNN）
- problem（缺口描述）
- fix（改造动作）
- axiom_affected（受影响公理）
- verified_at（验证时间）
- status（ACTIVE / SUPERSEDED）

每次自优化生成一条 decision，永久归档，形成可召回的决策史。

### 改造 7：上电自启钩子

在所有会话启动时，按固定顺序执行：
1. 加载全局 kernel.json
2. 执行 Ω-Brainμ recall（无指令时用"自治体检"作为默认 query）
3. 检查 auto_pending_queue
4. 无待办则静默 PASS，有待办则自动闭环
5. 结果回写内核并重算 kernel_hash
