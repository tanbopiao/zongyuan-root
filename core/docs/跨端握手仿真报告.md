## 一、仿真目标

## 二、链路架构

```
┌─────────────┐      ┌──────────────────┐      ┌─────────────┐
│  网页后台窗口  │◄────►│ ZONGYUAN-ROOT 根API │◄────►│  豆包APP会话  │
│ admin/index  │ 握手  │  123.207.202.158  │ 握手 │  多窗口客户端  │
└─────────────┘      │    8100产线内核     │      └─────────────┘
        │            └──────────────────┘            │
        │ BroadcastChannel (同源多标签)                 │ 网关SSE/长连接
        └───────────────┬────────────────────────────┘
                        ▼
              事件通知（只传变更信号，不传完整真值）
```

关键点：**窗口/客户端之间不直接互传业务数据**，只广播"真值已变更"事件；完整真值一律从根API读取。根是唯一权威信源。

## 三、仿真用例

### 用例1：网页窗口A提交新任务，APP窗口B感知
1. 窗口A在admin提交"太阴月神觉醒"量产任务
2. 8100产线内核任务队列写入新任务
3. 窗口A的RootTruth模块60秒轻握手检测到本地摘要变化，广播 `truth-changed` 事件
4. 同浏览器其他窗口经 BroadcastChannel 收到事件 → 立即轻握手对齐
5. APP窗口B经网关SSE收到变更通知 → 从根API拉取最新任务队列
6. **结论：两端任务列表一致，任务ID、状态完全对齐**

### 用例2：双端并发修改配置（版本锁仲裁）
1. 网页窗口A提交漂移阈值 0.85，APP窗口B同时提交 0.90
2. 根API按版本号锁仲裁：先到者生效（0.85），后到者版本过期被拒
3. 被拒方收到最新真值快照，自动回滚本地值并提示"配置已被其他端更新"
4. **结论：根仲裁唯一，不会出现两端状态撕裂**

### 用例3：断线重连补齐
1. APP窗口B断网120秒，期间网页端A完成3个任务
2. B恢复连接 → 全握手拉取完整快照 → 补齐全部3个任务状态
3. **结论：断线期间变更不丢失，重连全量对齐**

### 用例4：隔离验证

2. 根API拒绝返回真值，返回未授权

## 五、仿真结论

1. 跨端同步的核心不是"窗口互传数据"，而是**同根握手、根上取真值**；
2. 同浏览器多标签用 BroadcastChannel + storage 兜底；跨端（网页↔APP）用网关推送 + 全握手补齐；
