## 一、总则

全域资源（域名、站点、模块、可视化资产）以"一域一职、兼容并合、双向互联、溯源确权"为原则打通。互不覆盖、只做增量互联，所有入口一键可达、轻量部署。

## 二、标准条款

### STD-001 一域一职 · 主页唯一
每个域名只承担一个主职能，一个主页。职能冲突时以"新增入口"兼容并存，禁止用新站覆盖旧站；旧站归档保留历史。

### STD-002 兼容并合 · 禁止覆盖
新功能/新站点一律以增量方式并入（新增卡片、新增导航项、新增子路径），不删除、不覆盖既有内容与既有入口。

### STD-003 双向互联 · 互为跳转
建立互联关系的两端必须互为跳转入口（A→B 必有 B→A）。跳转一律新标签打开：target=_blank + rel=noopener。

### STD-004 统一导航 · 同域一致
同域页面共享统一导航（8大分类），全站组件走 site-nav.js；新增模块先入导航分类，再开页面，保持全域导航一致。

### STD-005 溯源标识 · 强制镌刻
所有互联页面必须镌刻 Ω₀⊂⊙∞⊂Ω + DID-BR-000002 + ZONGYUAN-ROOT 溯源标识，无溯源符号的页面不被体系承认。

### STD-006 配置唯一 · 禁止双套
nginx 配置以 /www/server/nginx/conf/sites/ 为唯一权威；宝塔面板目录不参与生效。任何域名调整只改生效配置并 nginx -t 验证。

### STD-007 变更留痕 · 先备后改
任何站点/配置修改前先备份 .bak.<tag>_<date>；变更完成后上报云端真值（operation_log），可追溯可回滚。

### STD-008 轻量部署 · 框架迭代
展示型资产优先单文件 HTML + 妙搭轻量部署；所有页面在 MR-092 框架内迭代，变更必须更新基准，禁止跳级回退。
