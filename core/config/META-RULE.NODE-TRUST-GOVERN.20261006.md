# 元规则·节点信任分层与写入盖章规则（Node Trust & Write Stamp）

> 确权: DID-BR-000002 | 溯源: Ω₀⊂⊙∞⊂Ω | 层级: 元规则
> 借鉴: MemClaw 治理型共享记忆（visibility scope + trust tier + 行级隔离 + 全审计）
> 日期: 2026-10-06 | 关联: 飞书共享大脑写权限治理 + 多窗口权限隔离架构

## 定位
飞书共享大脑与全域资产写入的信任治理铁律，解决"公开可读但写需权限""内部真值外泄""越权写入"问题。优先级高于普通L2真值，受L0天元法则与M1公理约束。

## 正文

### 一、节点信任分层（对应MemClaw trust tier）
```
T3  主窗口/主权根（DID-BR-000002 签名）→ 全读写+部署+审批+高危操作
T2  开发窗口（已注册）             → 本地开发+成果上报，云端只读
T1  外部协作账号（已授权）         → 经共享大脑公开层读取，无写
T0  匿名/未授权                    → 仅公开层只读
```

### 二、写入盖章规则（对应MemClaw write-time stamping）
1. 任何节点写共享大脑/全域资产，必须**盖章**：`visibility`(可见域) + `trust`(信任级) + `did`(身份签名)。
2. 盖章缺任一字段 → 拒绝写入。
3. 写入时自动扫描敏感信息（PII/内部Token/未公开IP）→ 命中自动隔离，**绝不进入公开层**。

### 三、召回过滤（对应MemClaw recall-time filtering）
1. 任何节点读共享大脑，只返回其 scope+permission 允许的内容。
2. T0/T1 匿名或外部：仅见公开层（飞书公开/魔搭/官网）。
3. T2 开发窗口：见公开层+本窗口成果，不见私有审批。
4. T3 主窗口：全量可见+可写。

### 四、公开/私有分层（对应MemClaw 可见域）
```
公开层  飞书共享大脑公开链接 / 魔搭湖 / 官网 → 外部可读
私有层  任务审批 / 未公开真值 / 内部Token / 敏感IP → 仅T3/T2受限
```

### 五、审计与熔断（对应MemClaw 全审计）
1. 每次共享大脑读写写入审计日志，编辑diff留痕。
2. 越权写入/访问 → 触发 auto_violation_detect，高危自动局部熔断。
3. 违反信任分层的操作，审计永久留存不可擦除。
