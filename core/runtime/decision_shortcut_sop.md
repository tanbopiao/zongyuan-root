# decision_shortcut_sop.md
> 归属：ZONGYUAN-ROOT / AxiomGate 裁决调度内核
> 用途：最优稳态决策推理开销短路优化 SOP，不破坏元公理、单源真值、账本溯源约束
> 确权标识：DID-BR-000002
> 锁档权限：444，修改需人工审批解锁
> 版本：v1.0
> 生成时间：2026-11-07

## 1. 总则
### 1.1 目标
在**不篡改公理逻辑、不跳过红线校验、保证裁决可审计溯源**的前提下，降低单次稳态裁决的 IO 开销与计算开销，区分快速通路与全推演通路，减少全账本扫描与完整风险熵求解频次。

### 1.2 不可突破铁律
1. 任何短路分支**必须优先执行元宪法硬规则校验**，红线命中直接拒绝，禁止缓存放行高危动作；
2. 所有缓存、快照绑定 `state_fingerprint（系统状态哈希）+ task_hash（任务指纹）`，底层资产、账本、配置变更自动失效缓存；
3. 短路放行的裁决，同样生成精简证据链写入账本，不能无记录放行；
4. 仅**常规稳态任务**走短路；跨版本内核变更、仓库收敛归一、锁档/解锁、资产删除类高危任务强制走全链路稳态推演，禁止短路。

### 1.3 分流总链路
```
裁决请求入队
    ↓
【Step1 前置红线熔断层（必跑，开销极低）】
    ├─命中禁令 → 返回拒绝 + 证据，终止
    └─未命中 → 进入置信分流
        ↓
【Step2 置信分流路由】
        ├─高置信 + 状态无变动 → 读取幂等缓存快照，返回历史裁决结果
        ├─中等置信 + 常规运维 → 读取热态缩影快照，轻量计算稳态分（简化熵查表）
        └─低置信 / 高危任务 / 状态变更 → 进入完整全链路稳态推演
```

## 2. Step1：前置红线熔断层（P0 最高优先级）
### 校验清单（键值比对、哈希、正则校验，无浮点计算）
1. 权限校验：当前节点是否具备目标操作的审批权限；
2. 配额硬限：API 额度、磁盘空间、并发数是否触碰元法则硬上限；
3. 资产保护：是否触发删除、覆盖、篡改只读锁档 444 内核文件；
4. 单源真值校验：基线 HASH 是否与 converge 分支权威账本匹配；
5. 跨域禁令：是否触发元宪法内明确禁止的行为。

### 输出
命中任意一条：`verdict=reject`，附带违规项，直接落账本，不再进入后续稳态计算。

## 3. Step2：置信分流路由规则
### 3.1 高置信通路（System1 缓存复用）
触发条件全部满足：
- 任务类型属于白名单：巡检、同步索引、普通素材入库、状态上报；
- 输入参数完全一致；
- `state_fingerprint` 和上一次裁决指纹完全相同（账本、配额、锁档标记无变更）；
- 子算子置信度 ≥ 预设阈值（默认 0.85）。

处理逻辑：直接读取缓存内预存的稳态得分、裁决结论、精简证据指纹；复用结果，**不再调用打分算子、不再重算效用/风险熵**。
> 缓存 KV 键：`sha256(state_fingerprint + task_hash)`
> 缓存 TTL：随状态变更失效，不设固定超时。

### 3.2 中等置信通路（热态缩影快照轻量计算）
触发条件：
- 不在缓存内，但属于常规非高危任务；
- 仅依赖热态快照 `state_snapshot.json`，不需要加载完整 Merkle 历史账本。

处理逻辑：
1. 加载常驻内存的热态缩影快照（只保留关键字段：配额、锁档标记、同步状态、基线哈希）；
2. 风险熵采用**预计算 LUT 查表**，替换实时 log 对数运算；
3. 效用分项只计算动态变量，静态公理惩罚项直接读取预编译常量；
4. 稳态得分达标则放行，同时写入缓存供下次复用。

> 快照更新机制：事件驱动，仅在联邦记忆、服务器状态、内核配置变更时刷新，不轮询磁盘。

### 3.3 低置信/高危通路（System2 全链路推演，禁止短路）
触发条件满足任意一条：
- 子算子置信度 ＜ 阈值；
- 任务属于高危黑名单：仓库收敛、内核锁档解锁、版本回滚、大批量资产删除、跨节点冲突消解；
- `state_snapshot` 标记为不稳定状态（同步中、磁盘告警、算子异常）；
- 全新任务类型，无历史裁决样本。

处理逻辑：完整执行原有全链路：全账本按需加载 → 调用子打分算子（THX-02 等）→ 效用函数+风险熵完整求解 → 证据链完整采集 → 写入账本 → 按需更新缓存。

## 4. 配套组件规范
### 4.1 常驻内存池
- 常驻加载：meta-rules 公理表、场景阈值表、LUT 风险熵查表；
- 不常驻：完整历史账本、归档资产，仅审计、全推演时按需读取。

### 4.2 子算子批量打包规则
短时间内同源、同场景多条裁决请求，合并为 batch 送入 THX-02 等打分算子，减少 HTTP 握手、模型初始化开销；批量上限在配置内可控，防止单批过大超时。

### 4.3 算子降级预案
子算子超时、报错时，不阻塞裁决：自动切换为体系内置保守先验分数，公理层继续终审，并在证据链标注【算子降级】标记。

## 5. 缓存清理与失效策略
1. 主动失效：`state_snapshot` 更新时，清空全部关联该指纹的缓存条目；
2. 被动淘汰：LRU 淘汰长期未访问缓存，保留最近 2000 条高频裁决缓存；
3. 审计追溯：缓存结果同样在账本留下引用标记，可追溯原始裁决证据。

## 6. 日志与账本字段扩展
短路裁决账本固定增加字段：
```json
{
  "shortcut_path": "reject_cache / fast_cache / light_snapshot / full_infer",
  "state_fingerprint": "xxx",
  "task_hash": "xxx",
  "cache_hit": true/false,
  "risk_entropy_method": "lut / realtime_calc"
}
```

## 7. 上线验证与灰度
1. 先开启日志埋点，统计各通路占比、平均耗时；
2. 优先开放红线熔断 + 热态快照轻量通路；缓存通路灰度观察 24 小时；
3. 每日自治巡检脚本采集短路命中率、裁决错误率，写入验收证据账本；
4. 若出现稳态裁决偏差，立刻关闭缓存通路，回归全推演模式排查。
