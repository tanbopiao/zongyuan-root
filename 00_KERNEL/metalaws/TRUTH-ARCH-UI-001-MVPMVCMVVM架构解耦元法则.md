## 一、核心公理

**视图层（View）不得直接读写自治内核真值存储，所有读写操作必须经过调度中间层做校验过滤。**

```
View ⇏ Model (禁止直连)
View → Controller/Presenter → Model (必须经过中间层)
Model = 真值内核 + Ω-Brainμ + 向量库 + manifest + Merkle谱系 [唯一可信源]
```

## 二、三套范式映射与选型

| 范式 | 适用场景 | 体系映射 | 风险 |
|------|----------|----------|------|
| **MVC** | 对外HTTP API接口 | Controller=API网关, Model=内核, View=JSON返回 | 网关易堆积业务逻辑，需代码规模巡检 |
| **MVP** | 内核+产线+同步主体（首选） | Presenter=记忆网关/产线编排器, View=飞书/API/渲染, Model=内核 | 无显著风险，最契合自治体系 |
| **MVVM** | 监控可视化面板 | ViewModel=双向绑定层 | 双向绑定隐式数据流易致状态漂移，必须叠加Merkle哈希校验 |

## 三、体系各层映射

### Model（模型层 - 唯一可信源）
- 真值内核（Ω-Brainμ）
- 向量真值库
- manifest资产清单
- 快照Merkle谱系
- root_state.json / kernel_state.json
- **只负责真值、数据、规则、资产状态，不关心谁来读取**

### View（视图层 - 仅输出呈现）
- 飞书Wiki输出
- API返回JSON
- 短剧关键帧渲染结果
- 日志报告
- 前端展示面板
- **只做输出呈现，禁止修改内核真值**

### Controller/Presenter/ViewModel（调度中间层）
- 记忆网关（8077）
- Git桥接同步脚本
- 产线编排器
- 巡检任务调度
- 协议过滤网
- **接收外部指令→校验→调度内核→输出结果**

## 四、强制约束

1. **视图层禁止直接读写内核文件**（root_state.json、kernel_state.json、M9账本等）
2. **所有写入/锁档操作必须经过调度中间层**，执行参数校验、eFuse熔断校验、Merkle快照校验
3. **产线（多模态短剧生成）属于View视图输出**，不能修改内核规则，只能读取真值
4. **MVVM面板必须定时拉取内核根哈希校准**，不能完全信任双向绑定
5. **巡检规则**：检测是否出现视图模块直接读写内核文件，一旦出现标记为架构风险告警

## 五、漂移防护价值

- 从架构层面杜绝外部视图直接篡改内核真值
- 同一套内核真值可输出多套视图（飞书Wiki/Drive/GitHub/云服务器）
- 修改产线渲染逻辑不需改动内核协议；修改锁档规则不需改动飞书输出脚本
- 内核Model可脱离飞书/前端界面单独运行，便于测试与部署迁移
