## 一、法则真值定位

本法则为ZONGYUAN-ROOT元极恒一自治体系的自进化底层规则，定义系统自我诊断、自我优化、自我演进的完整闭环机制。

核心真值：**系统必须具备在元秩序层约束下的受控自进化能力，通过"建议→确认→沙箱→锁档"四阶段闭环实现稳态演进，而非无序随机变化。**

## 二、四阶段自进化闭环（不可篡改真值）

### 阶段1：建议生成（Suggestion Generation）

**触发条件：**
- 系统监控发现异常（服务宕机、性能下降、安全漏洞）
- 性能指标低于阈值（响应时间、错误率、资源使用率）
- 用户反馈问题（功能缺陷、体验问题、需求变更）
- 定期巡检发现优化点（架构腐化、技术债务、规则冲突）

**建议类型：**
- 性能优化（缓存、索引、资源调配、算法优化）
- 安全加固（权限、加密、漏洞修复、合规检查）
- 功能补全（API完善、文档补充、错误处理、日志记录）
- 架构演进（模块拆分、服务化、容器化、微服务化）
- 规则更新（元法则修订、配置优化、策略调整）

**输出格式：**
```json
{
  "suggestion_id": "SUGG-{timestamp}-{type}",
  "type": "性能优化|安全加固|功能补全|架构演进|规则更新",
  "title": "建议标题",
  "description": "详细描述",
  "expected_benefit": "预期收益",
  "risk_level": "low|medium|high",
  "implementation_plan": ["步骤1", "步骤2", "步骤3"],
  "estimated_time": "预估时间",
  "created_at": "时间戳",
  "status": "pending"
}
```

### 阶段2：人工确认（Human Confirmation）

**审批层级：**
- **低风险（low）**：自动通过，无需人工干预
- **中风险（medium）**：管理员确认，记录审批日志
- **高风险（high）**：最高权限确认 + 沙箱验证 + 回滚预案

**确认方式：**
- 云内核控制台审批（Web界面）
- API调用确认（程序化审批）
- 定时批量确认（低风险建议批量处理）

**超时处理：**
- 72小时未确认自动归档为待审
- 待审建议每周汇总提醒
- 超过30天未处理自动关闭并记录

### 阶段3：沙箱执行（Sandbox Execution）

**沙箱环境规范：**
- **隔离类型**：Docker容器隔离，独立网络命名空间
- **资源限制**：CPU 1核、内存 512MB、磁盘 1GB
- **网络隔离**：仅允许访问指定白名单域名，禁止内网访问
- **文件系统**：只读挂载系统目录，可写沙箱目录，执行后自动清理

**执行流程：**
1. 创建沙箱环境（Docker容器启动）
2. 部署待验证变更（代码、配置、数据）
3. 执行自动化测试（单元测试、集成测试、端到端测试）
4. 性能基准对比（响应时间、吞吐量、资源占用）
5. 安全扫描（漏洞扫描、依赖检查、权限审计）
6. 生成验证报告（测试结果、性能数据、安全报告）
7. 销毁沙箱环境（容器停止、资源释放）

**验证标准（必须全部通过）：**
- 功能测试通过率 >= 95%
- 性能不降级（响应时间增加 <= 10%）
- 安全扫描无高危漏洞
- 兼容性（不破坏现有API契约）

### 阶段4：锁档生效（Lock & Activate）

**锁档内容：**
- 变更代码（完整diff或完整文件）
- 配置文件（变更前后对比）
- 验证报告（测试、性能、安全）
- 审批记录（审批人、时间、意见）
- 性能基准（变更前后对比数据）

**锁档方式：**
- SHA256哈希计算（内容完整性校验）
- Merkle-DAG追加（链式溯源，不可篡改）
- eFuse熔断固化（硬件级只读保护）
- 三层归档（云盘备份 / 知识库归档 / 内核快照）

**生效方式：**
- 灰度发布（10%流量 → 50%流量 → 100%流量）
- 蓝绿部署（新旧版本并行，验证后切换）
- 滚动更新（逐节点更新，保证服务不中断）

**回滚机制：**
- 保留最近10个版本，支持一键回滚
- 回滚触发条件：错误率 > 5%、响应时间 > 200%、严重故障
- 回滚后自动记录并生成分析报告

## 三、进化规则库（真值约束）

### 性能优化规则
1. API响应时间 > 500ms时建议添加缓存
2. 内存使用率 > 85%时建议优化内存占用
3. 数据库慢查询 > 1s时建议优化索引
4. CPU使用率持续 > 80%时建议扩容或优化

### 安全加固规则
1. 发现明文密钥时建议移入环境变量
2. 发现开放端口未授权时建议添加访问控制
3. SSL证书到期 < 30天时建议续期
4. 发现依赖漏洞时建议升级

### 功能补全规则
1. API端点缺少文档时建议补充OpenAPI文档
2. 缺少监控告警时建议添加监控
3. 缺少错误处理时建议完善异常处理
4. 缺少日志记录时建议添加结构化日志

## 四、审批权限矩阵（不可越权）

| 建议类型 | 低风险 | 中风险 | 高风险 |
|---------|--------|--------|--------|
| 性能优化 | auto | admin | root |
| 安全加固 | admin | admin | root |
| 功能补全 | auto | admin | admin |
| 架构演进 | admin | root | root |
| 规则更新 | admin | root | root |

**权限定义：**
- `auto`：系统自动审批，无需人工干预
- `admin`：管理员权限确认，记录审批日志
- `root`：最高权限确认 + 沙箱验证 + 回滚预案

```
系统监控 → 异常检测 → 建议生成 → 风险评估 → 自动审批(低风险)
    ↓                                            ↓

    ↓                                            ↓
验证通过 → 锁档归档 → 灰度发布 → 效果监控 → 进化完成
    ↓                                            ↓
验证失败 → 回滚预案 → 问题分析 → 建议修订 → 重新审批
```
