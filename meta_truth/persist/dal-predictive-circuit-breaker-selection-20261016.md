# DAL 部署仲裁层 · 预测式熔断算法选型与对比

> **议题** P0 · 2026-10-16 ｜ **DID** DID-BR-000002 ｜ **锚定** Ω₀⊂⊙∞⊂Ω
> **上游依据** 《双层稳态架构故障仿真沙盘设计》锁档 `truth.kernel.evolution.pulse.20261015.03`
> **目标** 在沙盘仿真底座上，为 DAL 仲裁层选定预测式熔断算法，替代纯反应式阈值熔断

---

## 一、问题定义

### 1.1 现状

DAL（RULE-011 V3.1，云端 :18900）当前五道闸全部为**反应式**：X-DID 认证、路径防护、SHA256 防旧覆盖、flock 单写者队列、版本化发布验证回滚。**无任何前置过载检测**——故障发生后才由 nginx/HTTP 错误暴露，属于「事后灭弧」。

### 1.2 沙盘锁定的三类目标故障

| 场景 | 特征 | 反应式熔断的盲区 |
|---|---|---|
| **雪崩** | 瞬时突增，级联放大 | 阈值触发时已完成级联 |
| **慢劣化** | 缓慢爬升，无单点越阈 | 永不触发阈值，直到崩溃 |
| **MoE 热点** | 单分片/单工单路径不均衡 | 全局均值掩盖局部热点 |

辅助场景：办公生产 Agent 长周期 DAG 任务——单次请求非关键，**中断代价高**，要求熔断粒度精细。

### 1.3 核心约束

1. **沙盘公理**：所有新调度策略必须先通过沙盘仿真检验，未通过禁止灰度上线
2. **零成本元规则 META-ISO-051**：只用云端已有服务器与免费工具链
3. **DAL 职责边界**：仲裁层守护的是「工单提交→互斥排队→原子发布」链路，熔断对象是**工单洪峰与下游慢响应**，不是数据面推理

## 二、候选算法对比

### 2.1 四类候选

#### A · 滑动窗口 + 阈值/PI 反应式（基线）

窗口统计错误率/延迟，越阈即熔断。PI 控制器自适应阈值。

- **检测延迟**：1 个窗口（数秒~数十秒）
- **对雪崩**：✅ 有效但滞后
- **对慢劣化**：❌ 静态阈值不触发；PI 仅调阈值不预判趋势
- **实现成本**：极低，~50 行
- **零伪造**：窗口指标可直接观测
- **结论**：必留作**兜底安全网**，但不满足「预测式」要求

#### B · CUSUM 累积和突变检测

对标准化残差累积正偏/负偏和，检测「小而持续」的均值偏移。实践上用 EMA（α=0.1）维护基线，预测-再更新模式。

- **检测延迟**：对**突变**极快（几个样本）
- **对雪崩**：✅ 前兆出现即报警（队列深度/错误率刚开始持续偏移）
- **对慢劣化**：⚠️ 需调参考偏移 k，k 过小误报、过大漏检
- **对 MoE 热点**：✅ 按分片分别建 CUSUM 即可定位
- **实现成本**：低，纯算术，无依赖
- **证据**：业界序列突变检测标准做法；LLM Agent 故障实时检测研究即采用「per-channel surprise + CUSUM」

#### C · EWMA 斜率预测（前瞻式）

指数加权移动平均 + 斜率估计，外推 t+Δ 的负载/延迟，提前 Δ 时间触发降级。

- **预测提前量**：Δ 可配置（如 60s）
- **对雪崩**：⚠️ 斜率外推对阶跃信号预测有限
- **对慢劣化**：✅ **最强**——正是斜率外推的目标形态
- **对 MoE 热点**：✅ 分片级 EWMA
- **实现成本**：低（α、斜率两行公式）
- **证据**：生产级实践 α=0.3、Δ=60s 匹配扩容时延；AEC-Dynamic EWMA 用实时误差动态调 α + 动量项抑制抖动

#### D · ML 前瞻式（LSTM/Autoformer/强化学习）

时序预测模型提前数分钟~半小时预判过载，触发扩容或熔断。

- **预测提前量**：最长（可达 30min 级）
- **综合**：理论上最优，但——
- **实现成本**：**高**，需训练、需推理资源、需特征工程
- **风险**：训练期与故障期分布漂移、误报不可解释；30min 级预测对 DAL 工单节奏（秒~分钟级）**提前量过剩**
- **结论**：与「零成本元规则」冲突，**P2 再议**，不进 P1

### 2.2 对比总表

| 维度 | A 阈值/PI | B CUSUM | C EWMA 斜率 | D ML 预测 |
|---|---|---|---|---|
| 预测能力 | 无（基线） | 前兆检测 | **趋势外推** | 强外推 |
| 雪崩 | 滞后✅ | **快✅** | 弱⚠️ | 快✅ |
| 慢劣化 | ❌ | ⚠️可调 | **✅最强** | ✅ |
| MoE 热点 | ❌全局盲区 | **✅分片级** | ✅分片级 | ⚠️需分片建模 |
| 检测延迟 | 1 窗口 | 几样本 | ~Δ | 分钟级 |
| 实现成本 | 极低 | 低 | 低 | **高** |
| 零成本合规 | ✅ | ✅ | ✅ | ❌ 需算力 |
| 可解释性 | 高 | 高 | 高 | 低 |
| 误报风险 | 低 | 中(调k) | 中(调α) | **高** |

## 三、选型结论：B+C 分层混合，A 兜底

### 3.1 架构

```
指标采集（队列深度/错误率/下游RTT/工单处理速率，按路径+分片）
        │
        ├─ 第1层 预测 ── EWMA斜率外推（慢劣化哨兵, Δ=60s）
        │                + CUSUM 突变检测（雪崩/热点哨兵, 分片级）
        │                     │ 触发预警
        ▼                     ▼
   第2层 决策 ── 分级：L1 降级(拒绝低优先级工单) → L2 限流排队 → L3 熔断(拒绝新工单)
        │                     │
        ▼                     ▼
   第3层 兜底 ── A 滑动窗口阈值（预测层失效时保底，P0 红线）
```

### 3.2 三场景覆盖论证

| 场景 | 主哨兵 | 副哨兵 | 动作 |
|---|---|---|---|
| 雪崩 | **CUSUM**（突变前兆） | A 兜底 | L2 限流 → L3 熔断 |
| 慢劣化 | **EWMA 斜率**（Δ=60s 外推越警戒线） | CUSUM（持续偏移） | L1 降级 → 缓熔断 |
| MoE 热点 | **分片级 CUSUM + EWMA** | 全局均值不动 | 仅熔断热点路径，全局不误伤 |

### 3.3 关键参数初值（待沙盘校准）

- EWMA：α=0.3（负载）、α=0.1（基线均值），预警 Δ=60s
- CUSUM：参考偏移 k=0.5σ，决策阈值 h=4σ（误报/漏检平衡点）
- 分级动作阈值：L1=警戒线 80%、L2=95%、L3=100% 或 CUSUM 越 h
- 全部参数**必须经沙盘三场景回放标定**，禁止凭经验直接上线

### 3.4 为什么不选 D

1. 与零成本元规则冲突
2. 30min 级提前量对 DAL 秒~分钟级工单节奏过剩
3. 沙盘公理要求先仿真——ML 模型的仿真标定成本远高于 B+C
4. P2 阶段若慢劣化场景实测 B+C 漏检率不达标，再引入轻量线性回归升级（仍非深度模型）

## 四、沙盘验证计划（接入已锁档仿真底座）

依沙盘五层（流量生成层 / 异构算力仿真层 / DAL 接入层 / 观测度量层 / 场景脚本库）：

| 阶段 | 内容 | 通过标准 |
|---|---|---|
| **S1 单算法离线** | 三类故障回放喂 B、C 单独跑，标定 k/h/α | 召回 ≥95%，误报 ≤1次/小时 |
| **S2 分层联调** | B+C 混合 + A 兜底，全故障集回放 | 预测提前量 ≥30s（慢劣化）；雪崩检出先于级联 |
| **S3 DAG 长周期** | 长周期工单洪峰下熔断粒度验证 | 热点路径熔断不误伤全局；中断恢复后无残留锁 |

**通过 S1~S3 才允许灰度**（沙盘核心公理）。

## 五、决策建议

**开启，选型 B+C 分层混合、A 兜底**，理由：

1. 三场景全覆盖且无一依赖付费资源
2. 可解释——每个熔断动作可溯源到具体哨兵与参数，符合 append-only 审计要求
3. 与沙盘五层结构天然对齐（观测度量层直接供指标，场景脚本库直接做回放）
4. 实现量级 ~300 行纯 Python，DAL 网关现架构（V3.1 标准库零依赖）可直接内嵌
