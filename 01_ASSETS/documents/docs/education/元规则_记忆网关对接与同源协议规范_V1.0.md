### 0.4 HMAC-SHA256签名机制（强制）

**签名公式**：
```
HMAC-SHA256(timestamp | nonce | canonical_body)
```

**参数说明**：
- `timestamp`：Unix时间戳，窗口 **300秒**（5分钟）
- `nonce`：一次性随机字符串，防重放
- `canonical_body`：请求体的规范化JSON（按key排序，无空格）

**请求头**：
```
X-Signature: <HMAC-SHA256签名结果>
X-Timestamp: <Unix时间戳>
X-Nonce: <一次性随机字符串>
Content-Type: application/json
```

**密钥来源**：`comm_gateway_secret.json`（密钥指纹：368491955359E366）

## 一、记忆网关定位与作用

### 1.1 核心定位

记忆网关是ZONGYUAN-ROOT体系中**本地与云端唯一握手点**，承担以下核心职能：

1. **真值上报**：所有生成的资产（视频/图片/文档/元规则/优化成果）必须向记忆网关上报
2. **记忆拉取**：智能体启动时必须从记忆网关拉取最新记忆，同步体系当前全部状态
3. **同源确权**：所有上报数据必须携带DID确权标识和锚定符号，确保同源可追溯
4. **状态同步**：体系状态、基准快照、算子运行状态通过记忆网关全域同步
5. **经验沉淀**：优化经验、故障教训、最佳实践通过记忆网关沉淀，供后续智能体学习

### 1.2 唯一握手点铁律

- **本地与云端唯一握手点为记忆网关9120端口**
- 除此之外不做任何自动云端同步/写入，不自作主张
- 禁止通过SSH连接云服务器进行记忆同步
- 记忆获取和成果上报统一通过记忆网关API完成

## 五、同源协议（确权与校验）

### 5.1 DID确权标识

所有上报数据必须携带统一DID确权标识：

```
DID-BR-000002
```

- DID是体系唯一身份标识，不可篡改
- 所有资产、元规则、文档必须携带DID
- 记忆网关根据DID进行同源校验和权限控制

### 5.2 锚定符号

所有上报数据必须携带统一锚定符号：

```
Ω₀⊂⊙∞⊂Ω
```

- 锚定符号是体系溯源标识
- 用于跨系统、跨智能体的同源识别
- 所有可视化资产（视频/图片/海报）必须在右下角植入锚定符号

### 5.3 哈希校验

所有上报数据必须携带SHA256内容哈希：

```python
import hashlib
content_hash = hashlib.sha256(json.dumps(data, ensure_ascii=False, sort_keys=True).encode()).hexdigest()
```

- 哈希用于内容完整性校验
- 记忆网关根据哈希去重和溯源
- 哈希变更意味着内容变更，必须重新上报

### 5.4 同源校验三要素

记忆网关对所有上报数据执行同源校验：

| 校验项 | 要求 | 不通过处理 |
|--------|------|------------|
| DID校验 | 必须为 DID-BR-000002 | 拒绝上报 |
| 锚定符号校验 | 必须携带 Ω₀⊂⊙∞⊂Ω | 拒绝上报 |
| 哈希校验 | 内容哈希必须与实际内容一致 | 拒绝上报 |

**三要素全部通过方为同源数据，否则视为异源数据拒绝接入。**

## 六、错误处理与重试机制

### 6.1 连接失败处理

记忆网关连接失败时按以下流程处理：

1. **立即重试**：间隔5秒重试，最多3次
2. **降级处理**：3次重试失败后，进入本地待上报队列
3. **记录日志**：记录失败原因、时间、数据摘要
4. **后台补报**：记忆网关恢复后自动补报待上报队列数据

### 6.2 本地待上报队列

- 存储路径：`data/pending_reports/`
- 文件命名：`{类型}_{哈希前8位}.json`
- 队列数据包含完整上报数据+失败原因+首次尝试时间
- 每次智能体启动时检查待上报队列，尝试补报
- 补报成功后删除本地队列文件

### 6.3 常见错误码

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| 401 | 未授权/令牌过期 | 重新握手获取令牌 |
| 403 | 同源校验失败 | 检查DID/锚定符号/哈希 |
| 404 | API路径不存在 | 检查API路径和网关版本 |
| 429 | 请求频率限制 | 降低频率，指数退避重试 |
| 500 | 网关内部错误 | 重试，仍失败则进入待上报队列 |
| 503 | 服务不可用 | 等待恢复，进入待上报队列 |

## 七、记忆拉取规范

### 7.1 启动时记忆拉取

智能体启动时必须执行四步记忆驱动闭环：

```
① 拉云端记忆(记忆网关9120)
② 全域状态对比（当前状态 vs 历史最优状态）
③ 按最优稳态规划下一步优化
④ 执行 + 按SOP上报回云端
```

### 7.2 记忆拉取API

```
GET /api/gateway/memory/pull?agent_id=<智能体ID>&since=<时间戳>
```

响应包含：
- 体系当前状态（基准快照）
- 最新成果上报记录
- 元规则/元法则更新
- 待办任务和优化方向
- 历史经验和教训

### 7.3 状态同步

- 智能体必须定期（每轮迭代后）向记忆网关同步当前状态
- 状态同步API：`POST /api/gateway/state/sync`
- 状态数据包含：当前版本、完善度评分、运行状态、待办事项

| 违规行为 | 处理方式 |
|----------|----------|

- 每轮优化/故障/成功经验必须结构化沉淀
