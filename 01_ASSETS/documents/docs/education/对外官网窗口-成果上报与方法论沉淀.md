## 二、方法论沉淀：从"口头交差"到"真实可交付"

### 2.1 问题复盘

**错误模式**：在本地虚拟机运行localhost服务，用浏览器截图展示给用户，口头描述"已完成"。用户无法直接访问，体验断裂。

**根因**：
- 没有区分"本地验证"和"用户可访问交付"两个阶段
- 把开发环境的localhost当成了交付物
- 缺少"用户能否真实点击访问"的最终验收标准

### 2.2 正确方法论（四步交付法）

```
第一步：本地开发验证 → localhost测试功能完整性
第二步：公开可访问化 → 用网页应用构建器生成真实URL
第三步：用户真实体验 → 用户点击链接，亲自操作验证
第四步：审批通过后上报 → 整理成果+方法论，上报中枢部署
```

### 2.3 核心原则

| 原则 | 说明 |
|------|------|
| **链接即交付** | 没有真实可点击的URL，就不算完成。截图和口头描述都是过程，不是交付物 |
| **用户视角验收** | 站在用户角度问："我能直接打开用吗？"不能，就继续做 |
| **善用工具链** | 网页应用构建器可以一键生成公开可访问页面，不要死守本地localhost |
| **活体感设计** | 对外窗口不是死的展示页，要体现"智能体在背后实时服务"的感觉 |
| **方法论即资产** | 每次踩坑后的经验，必须沉淀为可推广的方法论，让所有人学习 |

### 2.4 网页即智能体实体（Webpage-as-Agent-Body）设计理念

最新智能体理念：网页不只是信息展示，而是智能体的"身体"。
- 智能体有"在线状态"（脉冲呼吸灯）
- 智能体在"思考和说话"（打字动画、对话流）
- 智能体的"器官"在协同工作（27算子随机闪烁）
- 智能体有"生命体征"（实时时钟、动态背景）

这种设计让用户感受到"背后有一个真实的AI在服务"，而不是一个静态网页。
