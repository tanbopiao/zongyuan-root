## 二、决策方法论（4项）

### 2.1 三维稳态决策公式

**核心公式**:
```
综合评分 = 利益 × 40% + 风险 × 35% + 成本 × 25%
```

**应用场景**:
- 方案选择与评估
- 资源分配决策
- 优先级排序
- 投资决策

**执行步骤**:
1. 明确决策问题与目标
2. 生成≥3套备选方案
3. 对每套方案进行三维评估（利益/风险/成本）
4. 按公式计算综合评分
5. 排序并推荐最优方案
6. 敏感性分析（关键参数变化对结果的影响）

**实践案例**:
- 资产可视化页面部署方案选择
- 动态IP管理系统架构决策
- 同源节点协议设计方案评估

**关键原则**:
- 利益最大、风险最小、成本最小
- 至少3套方案对比，不做单方案决策
- 必须做敏感性分析，识别关键风险点

### 2.2 方案生成评估方法论

**核心流程**:
```
问题定义 → 数据收集 → 方案生成(≥3套) → 三维评估 → 排序推荐 → 决策备忘录 → 元秩序归档
```

**方案生成方法**:
1. **头脑风暴法**: 无限制发散，收集所有可能方案
2. **类比法**: 参考类似场景的成功方案
3. **逆向思维法**: 从目标倒推实现路径
4. **组合法**: 多个基础方案的组合变体

**评估维度**:
- **利益维度(40%)**: 收益大小、战略价值、可扩展性
- **风险维度(35%)**: 技术风险、运营风险、法律风险、声誉风险
- **成本维度(25%)**: 开发成本、运维成本、时间成本、机会成本

**输出物**:
- 决策备忘录（含方案对比表、推荐方案、风险提示）
- 元秩序归档记录

| S6 | 人工审核部署 | 人工审核确认后部署 | 部署确认 |

### 3.2 四步记忆驱动闭环

**核心流程**:
```
①拉云端记忆(9120) → ②全域状态对比 → ③按最优稳态规划下一步优化 → ④执行+按SOP上报回云端
```

### 3.3 容错闭环五步（E0-E4）

**核心流程**:
```
E0 意图校准 → E1 拉记忆扫真值 → E2 扫部署+仲裁 → E3 根因最小修复先备份 → E4 仿真沉淀反哺lesson
```

**各步骤详解**:

| 步骤 | 名称 | 核心动作 |
|------|------|----------|
| E0 | 意图校准 | 确认错误场景与用户真实意图 |
| E1 | 拉记忆扫真值 | 从记忆网关拉取相关历史，扫描真值 |
| E2 | 扫部署+仲裁 | 扫描当前部署状态，仲裁问题根因 |
| E3 | 根因最小修复先备份 | 先备份再做最小化修复，不做过度修改 |
| E4 | 仿真沉淀反哺lesson | 仿真验证+经验沉淀+反哺知识库 |

**关键原则**:
- 遇错先扫再动，禁止当场反复试错
- 错误即进化输入，每个错误都要沉淀lesson
- 先备份再修复，保证可回滚
- 最小化修复，不做无关改动

**核心流程**:

```
扫描云端基线 → 状态对比 → 最优稳态规划 → 最小化执行 → 验证上报
```

**应用场景**:

### 3.5 探查→约束→证据→执行→验证→交付

**核心流程**:
```
探查(读全输入) → 约束(守住边界) → 证据(事实可追溯) → 执行(按计划) → 验证(回读检查) → 交付(产物交付)
```

**关键原则**:
- 动手前先探查，不凭印象
- 守住用户点名的边界，不静默替换
- 每个数字必须有来源，不编默认值
- 受阻时换通道，不降级交付物
- 交付前用"可能失败"的动作验证

## 四、部署方法论（4项）

### 4.1 飞书审批触发自动部署SOP

**SOP编号**: ZR-DEPLOY-SOP-v1.0

**9步闭环流程**:
```
1.构建自包含部署包 → 2.分模块上报记忆网关 → 3.发起飞书审批 → 4.人工审批通过 → 5.中枢检测审批通过 → 6.中枢拉取部署包 → 7.中枢按8步SOP执行 → 8.部署完成上报 → 9.30分钟观察期
```

**4个部署包模块**:
1. 元数据SOP（truth_type=protocol）: DEPLOY-PKG-{日期}-{序号}
2. 文件内容（truth_type=data）: DEPLOY-PKG-CONTENT-{序号}
3. 执行指令（truth_type=decision）: DEPLOY-EXEC-{日期}-{序号}
4. 任务交接（truth_type=protocol）: DEPLOY-HANDOFF-{日期}-{序号}

**飞书审批表单关键格式（易错点）**:
- contact控件: value = ["user_id"]（user_id字符串数组，不是open_id）
- dateInterval控件: value = {"start":"ISO8601","end":"ISO8601","interval":"3600"}（秒数字符串）
- radioV2控件: value = 选项value字段（不是文本）

**8步标准部署SOP（页面类）**:
1. 创建目标目录
2. 解码并写入文件（base64 -d）
3. 设置文件权限（chmod 644）
4. 备份现有配置
5. 添加配置（Nginx location块）
6. 测试配置（nginx -t）
7. 重载配置（nginx -s reload）
8. 验证部署（curl -I + 内容检查）

3. 系统更新节点IP记录

**关键配置**:
- 管理Token: ZONGYUAN-DYNAMIC-IP-2026-SECRET-KEY
- 节点密钥: 每个节点独立auth_key

- 最大IP数: 每节点3个

### 4.4 部署失败回滚方法论

**回滚触发条件**:
- 任何一步部署SOP执行失败
- 验证不通过（HTTP非200或内容标识缺失）
- 30分钟观察期内出现异常
- 性能指标劣化超过阈值

**回滚步骤**:
1. 立即停止当前部署操作
2. 恢复备份的配置文件
3. 重载服务配置
4. 验证回滚成功（HTTP 200 + 原内容）
5. 上报失败原因+回滚状态
6. 沉淀lesson到记忆网关

**回滚时间要求**: <1分钟完成配置回滚

## 五、知识方法论（5项）

### 5.1 真值优先原则

**核心定义**: 以经过交叉验证的客观事实为唯一依据，禁止关联任何未经证实的虚假信息或市场传言。

**真值分级**:
| 等级 | 定义 | 置信度 | 应用场景 |
|------|------|--------|----------|
| T0 | 已验证客观事实 | 100% | 决策依据、法律证据 |
| T1 | 多方交叉验证 | >95% | 业务分析、趋势判断 |
| T2 | 单一可靠来源 | 80-95% | 参考信息、待验证 |
| T3 | 未验证传言 | <80% | 仅作线索，禁止作依据 |

**真值校验流程**:
1. 来源锚定（确认信息来源可靠性）
2. 多方交叉验证（至少2个独立来源）
3. 逻辑一致性检查（与已知事实无矛盾）
4. 冲突消解（发现冲突时深入调查）
5. 置信度标注（每个真值标注置信度等级）

**关键原则**:
- 此规则为最高优先级规则，所有后续操作必须以此为准
- 禁止关联任何未经证实的虚假信息或市场传言
- 每个数字必须来自输入、具体信源或可复现计算

## 六、治理方法论（4项）

### 6.1 全域锁档方法论

**核心目标**: 对资产集合执行标准化锁档，构建基准锚点，防止篡改。

**7步锁档流程**:
```
资产整理 → SHA256哈希确权 → Merkle-DAG构建 → 主链追加校验 → 快照生成 → 三层存储 → 锁档确认
```

**三层级存储态**:
1. 云盘归档（飞书云空间）
2. 知识库节点（飞书Wiki）
3. ZONGYUAN-ROOT内核快照

**锁档输出**:
- 快照ID: SNAP-{时间戳}-{描述}
- 锁档状态: FULL_ORDER_LOCKED
