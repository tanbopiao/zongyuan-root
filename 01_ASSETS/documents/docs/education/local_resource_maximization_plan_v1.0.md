## 二、资源层最大化利用方案

### 2.1 计算资源利用（CPU 2核 / 内存3.4GB可用）

**策略：分层常驻服务 + 批量任务队列**

| 层级 | 服务 | 内存预估 | CPU预估 | 启动方式 |
|------|------|---------|---------|---------|
| L1常驻 | 本地仿真API(Flask 8199) | 80MB | 5% | systemd常驻 |
| L1常驻 | 态元自治进化引擎 | 60MB | 3% | 后台循环 |
| L1常驻 | 资产索引服务 | 40MB | 2% | 定时刷新 |
| L2定时 | 知识图谱转化 | 100MB | 15% | 每6小时 |
| L2定时 | 三态治理计算 | 80MB | 10% | 每6小时 |
| L2定时 | 真值提炼+全网搜索 | 120MB | 20% | 每6小时 |
| L3批量 | 教育课程生产 | 200MB | 30% | 按需触发 |
| L3批量 | 资产整理/去重 | 150MB | 25% | 每周一次 |
| **合计** | | **~830MB** | **~110%** | 分时调度 |

**关键优化**：
- L1常驻服务合计仅180MB，占可用内存5%
- L2/L3任务分时执行，避免同时占用
- 预留2.5GB+内存给突发任务（如视频处理、大文件分析）

### 2.2 存储资源利用（9.7GB可用）

**策略：三级存储分层 + 自动清理**

| 层级 | 内容 | 配额 | 保留策略 |
|------|------|------|---------|
| 热存储 | 活跃项目/课程/引擎 | 2GB | 永久保留 |
| 温存储 | 历史快照/备份/报告 | 3GB | 90天轮转 |
| 冷存储 | 仿真数据/截图缓存 | 1GB | 7天自动清理 |
| 预留 | 系统/临时/突发 | 3.7GB | 动态 |

**立即执行的清理**：
- `_shots/` (30.4MB, 182文件) → 7天后自动清理（自检截图缓存）
- `deep_simulation_test/` (77MB, 304文件) → 归档后清理（仿真原始数据）
- `.tmp-tool-results/` (5MB, 185文件) → 立即清理（工具临时输出）
- `__pycache__/` (0.5MB) → 立即清理

### 2.3 网络资源利用

**策略：本地服务网关 + 定时上报**

- 本地端口规划：8199(短剧API)/8200(资产索引)/8201(态元监控)
- 所有本地服务通过统一网关暴露
- 每6小时通过记忆网关API上报状态和成果
- 大文件（视频/图片）通过飞书云盘上传，不占本地带宽

## 五、标准化自动执行SOP

### 5.1 每日自动执行流程

```
00:00  系统健康检查 + 资源利用率统计
02:00  资产增量扫描 + 新资产自动分类锁档
04:00  态元自治进化5心跳 + fitness优化
06:00  全网搜索真值提炼 + 交叉校验 + 上报网关
08:00  知识图谱增量转化 + 三态治理计算
10:00  教育课程生产（按队列1门/天）
12:00  机制引擎状态检查 + 异常自愈
14:00  短剧产线推进（分镜/关键帧/成片）
16:00  资产整理 + 临时文件清理
18:00  统一门户更新 + 部署包生成
20:00  全量状态上报记忆网关
22:00  内核快照 + 双备份
```

### 5.2 资源调度规则

1. **分时复用**：CPU密集型任务（图谱/三态）安排在低峰期（02:00-06:00）
2. **内存保护**：任何任务启动前检查可用内存<500MB则等待
3. **优先级抢占**：P0任务可暂停P2任务，完成后恢复
4. **失败重试**：任务失败自动重试1次，仍失败则记录并上报
5. **资源上报**：每小时上报CPU/内存/磁盘利用率到记忆网关

### 5.3 成果上报标准

每次任务完成后必须上报：
- 任务名称 + 执行状态 + 耗时
- 产出物清单（文件/哈希/大小）
- 资源消耗（CPU峰值/内存峰值/磁盘增量）
- 异常项 + 修复建议
- truth_key格式：`AUTO.EXEC.{任务名}.{YYYYMMDDHHMM}`
