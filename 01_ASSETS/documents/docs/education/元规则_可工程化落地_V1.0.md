## 一、元规则定义

**可工程化落地（Engineering-Ready Deployment）**

### 元规则定位
本元规则是本源智能普惠教育体系的**顶层强制元规则**，高于所有业务规则、功能设计和技术选型。所有功能模块、系统组件、产线流程必须满足本元规则要求，否则不得纳入体系、不得部署上线、不得宣称完成。

### 元规则核心公理
> **所有功能必须可工程化落地，所有链路必须全面打通，不留链路，不留断点。**

## 二、元规则六大强制条款

### 条款1：全链路打通（No Broken Links）
- 任何功能模块从输入到输出必须形成完整闭环，不得存在"只有格式没有实际生成"、"只有接口没有实现"、"只有设计没有代码"的断点
- 数据流转路径上的每个节点必须有实际可执行的处理逻辑，不得用TODO/占位符/模拟数据替代真实实现
- 验证标准：从系统最左端输入到最右端输出，端到端一次执行成功，中间无人工干预、无手动跳转、无未实现分支

### 条款2：实际输出验证（Real Output Verification）
- 每个声称具备的能力必须能产生实际的、可验证的输出文件/数据/结果
- 图像生成能力必须能输出实际图片文件（PNG/JPG），不得只输出提示词
- 视频生成能力必须能输出实际视频文件（MP4），不得只输出分镜表/规格说明
- 音频生成能力必须能输出实际音频文件（WAV/MP3），不得只输出文本脚本
- 文档生成能力必须能输出实际文档文件（DOCX/PDF/MD），不得只输出大纲
- 验证标准：`os.path.exists(output_path) == True` 且 `os.path.getsize(output_path) > 0`

### 条款3：仿真+真实双模式（Dual-Mode Architecture）
- 所有生成类能力必须同时支持**仿真模式**和**真实API模式**
- 仿真模式：使用本地工具（ffmpeg等）生成占位输出，确保链路可独立运行、可测试、可验证
- 真实API模式：通过配置的API端点调用真实生成服务（Seedream/Seedance/TTS等），输出真实质量内容
- 两种模式共享同一套流水线代码、同一套接口、同一套验证逻辑，仅生成后端可插拔替换
- 验证标准：仿真模式下端到端流水线100%通过；API模式下配置端点后可无缝切换

### 条款4：依赖最小化与环境自洽（Minimal Dependencies）
- 系统核心功能不得依赖外部不可控服务即可运行（仿真模式必须完全自洽）
- 外部依赖（API服务、云平台、第三方库）必须可配置、可替换、可降级
- 核心运行环境仅依赖：Python 3.8+、ffmpeg、标准库+少量通用库（requests/flask等）
- 不得引入需要付费授权、闭源二进制、特定硬件才能运行的依赖
- 验证标准：在干净的Linux环境中，执行`pip install -r requirements.txt`后系统可完整运行

### 条款5：可部署可运维（Deployable & Operable）
- 系统必须提供完整的部署说明、启动脚本、健康检查接口、日志输出
- API服务必须可后台常驻运行，支持进程管理、优雅重启、异常恢复
- 所有配置项必须外部化（配置文件/环境变量），不得硬编码在业务逻辑中
- 数据持久化必须有明确的存储路径、备份策略、恢复方案
- 验证标准：按照部署说明，在新环境中30分钟内完成部署并通过健康检查

### 条款6：测试驱动与持续验证（Test-Driven & Continuous Verification）
- 每个功能模块必须有对应的单元测试，测试覆盖率不低于80%
- 每个端到端流水线必须有集成测试，验证从输入到最终输出的完整链路
- 每次代码变更后必须运行全量测试，全部通过方可合并
- 测试必须包含：正常路径、异常路径、边界条件、性能基准
- 验证标准：`python3 -m unittest discover tests/` 全部通过，无skip、无expected failure

## 三、元规则违反判定与处理

### 违反等级
| 等级 | 定义 | 处理方式 |
|------|------|----------|
| P0 严重 | 核心链路存在断点，端到端无法运行 | 立即阻断，不得交付，限期修复 |
| P1 高 | 某模块只有接口无实现，或只有格式无实际输出 | 标记为未完成，不得纳入交付清单 |
| P2 中 | 缺少测试、缺少部署说明、配置硬编码 | 限期补齐，补齐前标记为beta |
| P3 低 | 代码风格、文档完整性等非功能性问题 | 记录待办，后续迭代优化 |

### 自检清单（每次交付前必须逐项确认）
- [ ] 所有声称的功能都有实际代码实现，无TODO占位
- [ ] 端到端流水线从输入到输出一次执行成功
- [ ] 每个生成类能力都能输出实际文件（非空、格式正确）
- [ ] 仿真模式可独立运行，不依赖外部API
- [ ] API模式有明确的配置接口和切换方式
- [ ] 全量测试通过（单元+集成+端到端）
- [ ] 部署说明完整，新环境可复现部署
- [ ] 健康检查接口可用，日志输出完整
- [ ] 配置项外部化，无硬编码密钥/路径
- [ ] 数据持久化路径明确，有备份恢复方案

## 四、元规则在视频教学通道中的落地验证

### 已验证通过的链路（V1.4）
1. ✅ 知识点获取 → 知识图谱实体查询
2. ✅ 教学脚本生成 → 结构化脚本JSON（5环节）
3. ✅ 分镜表生成 → 短剧流水线兼容格式（含所有标准字段）
4. ✅ 关键帧图片生成 → 实际PNG文件（ffmpeg生成，仿真模式）
5. ✅ 视频片段生成 → 实际MP4文件（ffmpeg生成，仿真模式）
6. ✅ 配音音频生成 → 实际WAV文件（ffmpeg生成，仿真模式）
7. ✅ 字幕文件生成 → 实际SRT文件（标准格式）
8. ✅ 视频片段拼接 → 实际MP4文件（ffmpeg concat）
9. ✅ 音频混合 → 实际MP4文件（ffmpeg audio merge）
10. ✅ 字幕压制 → 实际MP4文件（ffmpeg subtitles burn）
11. ✅ 最终成片交付 → 实际MP4文件 + 哈希确权 + 双库归档

- 最终视频大小：约0.17MB（仿真占位视频）
- 全量测试：231项全部通过
- API接口：110+个，全部可调用
