## 一、七步标准迭代流程

### S1：意图校准（需求确认）

**输入**：用户需求/优化建议/自动巡检发现的问题
**动作**：
- 明确需求范围（是新增功能/优化体验/修复Bug）
- 确认交付形态（网页/API/文档/部署包）
- 识别是否涉及数据存储（决定全栈还是纯前端）
**输出**：一句话需求描述 + 验收标准清单
**验收**：需求可量化、可验证、不模糊

### S2：方案设计（架构规划）

**输入**：S1的需求描述
**动作**：
- 确定技术方案（前端页面/后端API/数据库表结构）
- 设计模块间数据流和调用链路
- 评估对现有模块的影响，确保不破坏已有功能
- 遵循ENGINEERING_FIRST元规则：真实API+完整数据流+端到端可测试
**输出**：技术方案要点 + 模块链路图 + 影响范围评估
**验收**：方案可工程化落地，每个模块有真实输入输出

### S3：开发实现（编码落地）

**输入**：S2的技术方案
**动作**：
- 按方案实现代码，禁止空壳模块和假接口
- 新增功能必须有真实的数据流闭环
- 模块间链路必须真实打通（不能只写文档不写代码）
- 遵循现有代码规范和命名约定
**输出**：可运行的代码
**验收**：代码无语法错误，功能可启动运行

### S4：本地测试（全链路验证）

**输入**：S3的代码
**动作**：
- 启动服务，用curl测试所有API接口
- 用浏览器测试所有页面交互
- 测试新增功能与已有功能的联动
- 测试异常场景（空输入/错误输入/边界值）
- 移动端响应式测试
**输出**：测试通过记录 + 发现的问题清单
**验收**：核心功能100%通过，无阻断性Bug

### S5：公开部署（用户可访问）

**输入**：S4测试通过的代码
**动作**：
- 网页类产品：用网页应用构建器生成公开可访问URL
- 全栈系统：打包部署包，生成一键部署脚本
- **关键原则：链接即交付** — 没有真实可点击的URL就不算完成
- 部署后立即验证线上可访问性
**输出**：公开可访问的链接/部署包
**验收**：用户可直接点击访问，无需任何本地环境

### S6：用户验收（真实体验）

**输入**：S5的公开链接
**动作**：
- 把链接发给用户，让用户亲自操作体验
- 收集用户反馈，记录满意点和改进点
- 用户审批通过后进入下一步
- 用户不满意则返回S1重新校准
**输出**：用户验收结论（通过/需修改）
**验收**：用户明确表示"满意/审批通过"

### S7：沉淀上报（归档进化）

**输入**：S6用户验收通过
**动作**：
- 生成成果上报文档（资产信息+功能清单+设计说明）
- 沉淀方法论（本次踩坑记录+最佳实践+可推广经验）
- 上报记忆网关（IP受限则内置到部署脚本，服务器端执行时上报）
- 飞书文档永久归档
- 更新版本号，更新优化路线图
- 将经验写入元规则，供后续迭代复用
**输出**：归档文档 + 飞书链接 + 版本记录
**验收**：成果可追溯，经验可复用，全网可推广

## 二、自动化进化触发机制

### 2.1 自动巡检触发

以下条件自动触发优化迭代：

| 触发条件 | 优化方向 |
|---------|---------|
| 页面加载时间 > 3秒 | 性能优化（图片压缩/代码分割/懒加载） |
| 某工具使用率 < 5% | 功能优化（简化入口/增强引导/合并同类） |
| 用户反馈某功能难用 | 体验优化（交互重构/增加引导/简化流程） |
| 出现新的AI能力 | 能力升级（接入新模型/新算子/新工具） |
| 竞品出现新功能 | 对标优化（学习借鉴+差异化创新） |
| 安全漏洞发现 | 安全加固（权限校验/输入过滤/数据加密） |

### 2.2 自治进化闭环

```
自动巡检 → 发现问题 → 意图校准(S1) → 方案设计(S2) → 开发实现(S3)
    ↑                                                        ↓
沉淀上报(S7) ← 用户验收(S6) ← 公开部署(S5) ← 本地测试(S4)
```

- 小版本迭代（v1.x）：自动执行，无需人工审批
- 大版本升级（v2.0）：生成方案后推送人工确认，确认后自动执行
- 紧急修复（安全漏洞/数据丢失）：立即执行，事后补报

## 三、质量门禁（Delivery Gate）

每个版本发布前必须通过以下门禁：

### 3.1 功能门禁
- [ ] 所有新增功能有真实API调用，非mock假数据
- [ ] 所有模块间链路真实打通，端到端可测试
- [ ] 无空壳模块、无占位页面、无"即将上线"
- [ ] 异常输入有友好提示，不崩溃不白屏

### 3.2 体验门禁
- [ ] 页面首屏加载 < 3秒
- [ ] 所有按钮有hover/click反馈
- [ ] 加载状态有明确指示（不卡死无响应）
- [ ] 移动端适配正常，无横向滚动
- [ ] 颜色对比度符合可访问性标准

### 3.3 交付门禁
- [ ] 有真实可点击的公开访问链接
- [ ] 有完整的成果说明文档
- [ ] 有版本号和更新日志
- [ ] 有回滚方案（出问题可快速回退）
- [ ] 已上报归档，可追溯

## 四、可视化设计标准

### 4.1 网页即智能体实体（Webpage-as-Agent-Body）

所有对外可视化页面必须体现智能体活体感：

| 要素 | 标准实现 |
|------|---------|
| 在线状态 | 脉冲呼吸灯 + "在线服务中"文字 |
| 思考过程 | typing打字动画 + 算子调用状态提示 |
| 协同运算 | 算子标签随机激活闪烁 |
| 实时数据 | 数字滚动动画 + 定时波动更新 |
| 动态背景 | 浮动光晕 + 渐变流光 |
| 交互反馈 | hover上浮 + 点击波纹 + 加载进度 |

### 4.2 设计语言规范

- 主色：深蓝靛 #1a1a2e（智慧/科技）
- 强调色：琥珀橙 #f59e0b（火/活力）
- 辅助色：薄荷青 #10b981（公益/生长）
- 卡片：玻璃拟态（半透明背景+模糊+边框）
- 字体：展示用衬线体，正文用无衬线体
- 圆角：12-16px，柔和不尖锐
