## 1. 执行摘要

### 1.1 项目定位

ZONGYUAN-ROOT 本源体系是一套面向个人与企业的**自治内核架构**，核心理念是"内核轻量+能力外置"：2核4GB运行Ω-Brainμ编排内核，所有重计算通过豆包API卸载，飞书云盘无限扩展存储。内核只做决策/校验/记忆，外部能力做生成/计算/存储。

### 1.2 核心成果

| 维度 | 指标 |
|------|------|
| 代码模块 | 19个（全部active，0 draft） |
| 总代码行数 | ~5,800行 |
| 集成测试 | 132/132 通过（100%） |
| 四真值交叉校验 | 5/5 通过 |
| 锁档记录 | eFuse blown，不可回退 |
| 设计真值 | 5条 |
| 代码真值 | 19条（去重后） |
| 运行真值 | 4条 |
| 规划真值 | 6条 |

### 1.3 架构原则

> **内核只做编排/校验/记忆，所有生成/计算/存储全部外置。让2核4GB的每一个时钟周期都花在"决策"上，而不是"干活"上。**

- **轻内核**: Ω-Brainμ仅占~200MB内存，负责编排、校验、记忆
- **重能力外置**: 文本/图像/视频生成全部走豆包API
- **无限存储**: 飞书云盘/Wiki/Base作为持久化层
- **可信优先**: 四真值交叉校验 + 执行哈希链 + eFuse锁档
- **自治进化**: 每日终极进化循环，自动发现断点并修复

## 4. 手脚驱动层

### 4.1 六层架构

手脚驱动层是内核的**执行骨架**，解决"代码有了但驱动不起来"的核心问题：

| 层级 | 职责 | 核心模块 |
|------|------|----------|
| **决策层** | 意图解析、Action选择、参数构造 | limb_driver统一入口 |
| **调度层** | 任务队列、持久化、并发控制、重试 | executor |
| **防护层** | 熔断、限流、幂等、补偿 | circuit_breaker + idempotency |
| **执行层** | Action抽象、具体执行、回滚 | action_base + 各Action实现 |
| **可信层** | 哈希链、权限校验、审计 | execution_hash_chain + action_rbac |
| **观测层** | 指标采集、健康检查、告警 | execution_metrics + health_endpoint |

### 4.2 Action抽象基类

所有可执行动作继承`BaseAction`，统一接口：

```python
class BaseAction:
    def validate(self) -> bool:      # 参数校验
    def run(self) -> ActionResult:    # 执行主体
    def rollback(self) -> bool:       # 回滚
    def get_metrics(self) -> dict:    # 指标
```

执行结果统一为`ActionResult`，包含状态(success/failed/blocked)、数据、错误、回滚标记。

### 4.3 漂移熔断器

三级状态机：**CLOSED → OPEN → HALF_OPEN**

- 连续失败N次 → 熔断(OPEN)，快速失败
- 冷却时间后 → 半开(HALF_OPEN)，放行少量请求探测
- 探测成功 → 关闭(CLOSED)，恢复正常
- 探测失败 → 重新熔断(OPEN)

熔断器是防止外部API故障雪崩的关键防线。

### 4.4 幂等与补偿事务

- **幂等键**: 每个Action生成唯一幂等ID，重复执行返回相同结果
- **补偿事务**: 失败时自动执行rollback，支持多级补偿链
- **去重窗口**: 可配置的幂等有效期，防止长期占用

## 5. 五层深度加固

### 5.1 加固目标

> **解决代码执行中断点、异常、篡改、越权、不可观测导致的逻辑漂移。**

### 5.2 五层加固详解

| 层级 | 模块 | 防护目标 |
|------|------|----------|
| **L1 执行哈希链** | execution_hash_chain | 防篡改：每次执行哈希链式记录，不可篡改 |
| **L2 两阶段提交** | two_phase_action | 防中断：prepare→commit两阶段，支持回滚 |
| **L3 RBAC权限矩阵** | action_rbac | 防越权：动作级权限控制，高危操作需确认 |
| **L4 执行指标采集** | execution_metrics | 防不可观测：全链路指标，P50/P95/P99延迟 |
| **L5 流水线执行引擎** | pipeline_executor | 防断点：多阶段流水线，断点续跑 |

### 5.3 执行哈希链

每次执行生成哈希记录，链式连接：

```
block_n = SHA256(block_{n-1}.hash + action_name + status + result_hash + timestamp)
```

特性：
- 不可篡改：修改任意块导致后续所有哈希变化
- 可追溯：任意执行可通过哈希链回溯
- 完整性校验：链尾哈希 = 全链完整性证明

### 5.4 两阶段提交

```
Phase 1 (Prepare):  校验参数 + 预执行 + 锁资源
Phase 2 (Commit):   正式执行 + 释放资源
失败 → Rollback:    撤销Phase 1的所有变更
```

适用于多资源协调的复杂操作，确保要么全部成功，要么全部回滚。

### 5.5 动作级RBAC

| 角色 | 权限 |
|------|------|
| observer | 只读查询 |
| operator | 普通Action执行 |
| admin | 全部Action + 配置修改 |
| root | 全部 + 内核升级 + 锁档 |

高危操作（如锁档、配置修改）需二次确认，确认TTL默认300秒。

### 6.5 P2: 多写入者执行器

**文件**: `multi_writer_executor.py` (350行)

解决并发写入冲突，基于fcntl文件锁：

| 特性 | 说明 |
|------|------|
| 分布式锁 | 基于fcntl.flock，支持共享/独占 |
| 写入者注册 | writer_id + resource + lock_type |
| 心跳监控 | 5秒心跳，30秒超时判定死亡 |
| 冲突检测 | 同一资源多个独占写入者 |
| 冲突解决 | last_write_wins / merge / reject |

| 审计日志 | 所有锁操作记录到jsonl |

**带锁执行流程**:
```
1. 注册写入者(检查并发数上限)
2. 获取资源锁(超时30秒)
3. 启动心跳线程(5秒/次)
4. 执行Action
5. 记录执行哈希链
6. 采集执行指标
7. 停止心跳
8. 释放锁 + 注销写入者
```
