## 摘要

联邦记忆池（Federated Memory Pool）是 ZONGYUAN-ROOT 元极恒一自治体系的核心记忆基础设施，解决**多节点、跨沙箱、跨会话场景下的记忆持久化、激活与联邦同步**问题。本白皮书系统阐述其架构设计、核心公理、协议规范与工程落地实现。

**核心命题**：记忆不是某个节点的私有状态，而是联邦中所有节点的共享资产；任何节点销毁、沙箱重置、会话中断，均不丢失体系记忆。

---

## 1. 背景与问题定义

### 1.1 多节点自治体系带来的记忆挑战

| 挑战 | 描述 | 后果 |
|------|------|------|
| 沙箱易逝性 | 云 VM/沙箱会话销毁后运行时内存清空 | 记忆随实例消失 |
| 多节点分散 | 本地笔记本/云端中枢/边缘节点各自运行 | 记忆孤岛化 |
| 跨会话漂移 | 新会话不继承历史上下文 | 重复劳动、规则丢失 |
| 全量扫描昂贵 | 飞书全域扫描成本高、耗时长 | 无法每次启动全量加载 |

### 1.2 设计目标

1. **秒级恢复**：沙箱销毁后，输入触发词即可恢复最新体系记忆
2. **定点加载**：按锚点条件（latest/tag/asset_id/snap_id/keyword）精准拉取，替代全量扫描
3. **联邦一致**：控制节点唯一写权限，工作节点只读；锁档流水线增量更新并推送集群
4. **永不丢失**：原始资产永不物理删除，仅做索引优先级沉降标记

### 2.1 四层记忆模型

| 层级 | 名称 | 内容 | 保留策略 |
|------|------|------|----------|
| L1 | 工作记忆 | 当前会话上下文 | session（随会话销毁） |
| L2 | 情景记忆 | 历史事件/决策/成果 | permanent（永久） |
| L3 | 语义记忆 | 概念/规则/真值条目 | permanent（永久） |
| L4 | 冷持久层 | 飞书+本地+账本 | 只读锁档（444） |

### 2.2 核心组件

| 组件 | 职责 | 关键参数 |
|------|------|----------|
| 记忆网关 | HTTP服务，按锚点拉取记忆 | 端口8077、HMAC-SHA256、DID鉴权 |
| 记忆元索引 | 记忆唯一主副本，分片指针存储 | 795条资产、A/B/C/D优先级 |
| 记忆链维护 | 每次锁档自动生成链式种子 | seed-NNN.json、哈希链继承 |
| 记忆优化器 | 内存治理、进程监控、资源告警 | 阈值80/90/85、5分钟监控 |
| 记忆质量算子 | 相关性打分过滤 | relevance_score ≥ 0.35 |

## 3. 核心公理体系（AUTOKERN-MEMORY-PROTO V1.1）

### 3.1 记忆恢复公理
1. 沙箱会话销毁后，输入触发词（元极恒一/启动ROOT/全域锁档等）即可秒级恢复最新体系记忆
2. 显式锚定指令支持定点加载：`anchor:tag=xxx` / `anchor:asset_id=xxx` / `anchor:snap_id=xxx` / `anchor:latest`
3. 恢复数据来源为记忆元索引 + 冷持久层，**不依赖沙箱运行时内存**

### 3.2 元索引公理
1. `memory_index.json` 为记忆元索引唯一主副本，只存指针/摘要/哈希/标签/优先级，**不存全文**
2. 控制节点唯一写权限，工作节点只读；锁档流水线增量更新并推送集群
3. 锁档即索引刷新：新增追加/修改更新/删除标记废弃，历史条目 eFuse 熔断不可覆写
4. 资产优先级 A/B/C/D 四级，D 级可被缓存淘汰；沉降仅改索引标记，原始冷存储永不物理删除

### 3.3 记忆网关公理
1. 三域记忆网关 :8077 仅监听 127.0.0.1，**禁止外网直连**，HMAC-SHA256 签名鉴权
2. 内部链路：L1/L2缓存 → 索引过滤 → 质量算子打分（阈值0.35）→ 优先级排序 → 定点拉取 → token节流 → 埋点事件输出
3. 外部业务统一经 API 网关隔离访问，禁止业务层直连记忆网关

### 3.4 记忆安全公理
1. 密钥凭证环境变量托管，日志自动脱敏
2. Git pre-commit 安全钩子拦截敏感文件
3. 记忆恢复与锚定请求全量审计，事件日志30天轮转
4. 固化资产 444 只读锁档，修改需人工审批

## 4. 联邦同步机制

### 4.1 锁档即同步
每次全域锁档自动触发记忆索引增量更新：
```
新资产归档 → SHA256确权 → 索引增量追加 → 记忆链种子生成 → 推送Gitee+GitHub双仓库 → 云端中枢拉取
```

### 4.2 双仓库异地固化
- **Gitee**：huodou-cloud-intelligence-aios/zongyuan-root-sync
- **GitHub**：tanbopiao/zongyuan-root-sync
- 任何节点更新，双远端 0 差异

### 4.3 三层固化
```
① 本地固化（GLOBAL_MEMORY_SNAPSHOT.json + 索引更新）
② 中枢云端固化（POST /api/report/truth 上报真值）
③ Git异地固化（Gitee + GitHub 双仓库推送）
```

| 端点 | 方法 | 功能 |
|------|------|------|

```json
  "anchor_type": "tag",
  "anchor_value": "架构",
  "extract_mode": "truth_only",
  "max_token": 4000

```

### 5.2 记忆链维护（哈希链式继承）
```python
seed_content = {
    "seed_id": "seed-042",
    "sequence": 42,
    "timestamp": "...",
    "previous_hash": "<上一个种子的SHA256>",
    "trigger": "auto_lock"
}
```
每个种子的哈希继承前一个种子，形成不可篡改的记忆链。

## 7. 安全与合规

1. **最小权限**：记忆网关仅监听回环地址，禁止公网直连
2. **签名鉴权**：HMAC-SHA256 防篡改、防重放
3. **敏感治理**：凭证环境变量托管，日志脱敏，Git钩子拦截
4. **只读锁档**：固化资产 444 权限，修改走人工审批
