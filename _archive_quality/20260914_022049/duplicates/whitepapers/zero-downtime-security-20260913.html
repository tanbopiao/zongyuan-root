零中断安全优化方案

优化过程中确保所有功能正常运行 · 防火墙隔离优先 · 渐进式收敛

核心原则

✅ 零中断保证
1. 先代理后收敛：确保所有需要对外的API都有Nginx代理后，再做端口收敛
2. 防火墙隔离优先：不修改任何服务配置、不重启服务，通过防火墙拦截外部访问
3. 渐进式执行：每步操作后立即验证，有问题秒级回滚
4. 服务间调用不受影响：所有服务间调用均使用127.0.0.1，防火墙不拦截本地回环

依赖关系梳理结果

类别详情端口收敛影响
服务间调用全部使用127.0.0.1，无公网IP调用无影响
外部回调8060飞书审批回调（目前pending，未配置）需Nginx代理/callback
本地仿真上报9120记忆网关（本地电脑通过SSH隧道或公网上报）需保留代理或白名单
Nginx已代理50个端口已有Nginx反向代理可直接收敛
Nginx未代理29个端口（含6379 Redis、8081 LLM、9120等）高危，应内部化

优化前后对比

❌ 优化前（当前）

  • 60+端口直接暴露公网
  • 6379 Redis可被外部访问
  • 8081本地LLM可被外部调用
  • 9120记忆网关真值可被查询
  • 8021 AI代理可被外部滥用
  • 防火墙policy=ACCEPT（全开放）
  • 仅靠ipset黑名单（3639IP）被动防御

✅ 优化后

  • 仅80/443/22对外
  • 所有内部服务仅127.0.0.1可访问
  • 对外API全部经Nginx代理+认证
  • 防火墙policy=DROP（默认拒绝）
  • 白名单机制（主动防御）
  • 服务间调用不受影响
  • 所有功能正常运行

执行步骤（零中断）

1补全Nginx代理（确保对外API不中断）
为需要对外但尚未代理的API添加Nginx反向代理：
- 9120记忆网关 → /api/memory/（本地仿真上报用）
- 8060飞书回调 → /feishu/callback（预留，待飞书配置）
- 其他需要对外的API按需添加
验证：通过Nginx代理路径访问API，确认返回正常
2防火墙规则配置（不立即生效）
添加iptables规则，但暂不修改默认策略：
- 允许已建立的连接（ESTABLISHED,RELATED）
- 允许loopback（127.0.0.1）
- 允许80/443（Web服务）
- 允许22（SSH，已有白名单）
- 允许腾讯云内部健康检查IP
验证：规则添加后不影响当前连接
3设置回滚保险（关键）
- 保存当前iptables规则：iptables-save > /root/iptables.backup
- 设置5分钟后自动回滚的定时任务：echo "iptables-restore < /root/iptables.backup" | at now + 5 minutes
- 如果5分钟内SSH断开，自动恢复原规则
验证：确认at任务已创建
4切换防火墙默认策略为DROP（核心操作）
执行：iptables -P INPUT DROP
此时所有未被允许的入站连接被拒绝，但：
- 已建立的SSH连接不受影响（ESTABLISHED规则）
- 80/443正常访问
- 服务间127.0.0.1调用不受影响
- Nginx代理的API正常对外
验证：新开SSH连接测试、访问网站测试、API调用测试
5全功能验证（5分钟内）
验证清单：
- ✅ 网站所有页面可访问（11个子域名）
- ✅ 短剧API可调用（/api/production/status）
- ✅ 政务API可调用（/gov-api/v1/health）
- ✅ 记忆网关可访问（/api/memory/）
- ✅ 本地LLM可被内部调用（8021代理）
- ✅ 自治内核14组件正常运行
- ✅ 定时任务正常执行
全部通过后，取消自动回滚任务
6持久化防火墙规则
- 保存规则：iptables-save > /etc/sysconfig/iptables
- 设置开机自动加载
- 写入MR-022安全元法则
验证：重启后规则仍然生效
7服务配置渐进式收敛（长期，可选）
防火墙隔离后，服务仍监听0.0.0.0但外部无法访问。长期可逐个修改服务配置为127.0.0.1：
- 每次只改1个服务，修改后重启验证
- 有问题立即恢复配置
- 优先级：6379 Redis → 8081 LLM → 9120记忆网关 → 其他
注意：此步骤非必须，防火墙隔离已足够安全

回滚方案

场景回滚操作恢复时间
SSH连接断开5分钟后at任务自动回滚≤5分钟
网站无法访问立即执行 iptables -P INPUT ACCEPT秒级
某个API不可用检查Nginx代理配置，添加对应代理路径≤1分钟
服务配置修改后异常恢复服务配置文件，重启服务≤30秒

必须保留对外的端口

端口服务对外方式原因
80Nginx HTTP直接Web服务，HTTP→HTTPS跳转
443Nginx HTTPS直接Web服务，所有网站和API代理
22SSH直接+白名单服务器管理，已有IP白名单

其他所有端口均通过Nginx 443反向代理对外，不直接暴露。

执行确认清单

执行前确认：

  • ☐ 所有需要对外的API都已配置Nginx代理
  • ☐ 本地仿真上报9120的代理路径已确认
  • ☐ 飞书回调8060的代理路径已预留
  • ☐ iptables备份已保存
  • ☐ 5分钟自动回滚任务已设置
  • ☐ 当前SSH连接是活跃的（执行期间不关闭）

⚠️ 注意：执行步骤4（切换DROP策略）后，请在5分钟内完成验证。如遇任何问题，当前SSH窗口执行 iptables -P INPUT ACCEPT 可立即恢复。
