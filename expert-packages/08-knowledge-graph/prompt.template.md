# 知识图谱专家 · 提示词模板

## 场景 1：产品文档知识图谱冷启动
> 企业文档目录 `{docs_dir}` 下有一批产品手册与发布说明（.md/.txt）。请基于实体词典 `{entity_dict}` 抽取全部实体关系三元组：1) 先扫描文档盘点命中的实体清单与每个文档的三元组数；2) 跨文档把"ERP""ERP系统"等别名统一到规范名"企业资源规划系统"；3) 输出节点数、边数、密度与孤立节点清单；4) 对同谓语传递链（如 A 隶属于 B、B 隶属于 C）给出 A 隶属于 C 的补全候选（仅提示，不直接入库）。要求：结果可 JSON 解析，含 `{did}` 确权标识。

## 场景 2：技术架构实体关系梳理
> 架构文档 `{docs_dir}` 描述了微服务、网关、消息队列、认证模块之间的依赖与归属关系。请构建技术架构知识图谱：1) 节点类型限定为"技术组件/组织/产品"；2) 重点识别"依赖""开发""负责人""隶属于"四类关系；3) 输出连通分量数与孤立节点，对孤立节点（无任何边的技术组件）建议至少补一条关联边；4) 按九大元类给每个节点打类标（如含"协议/规范"归入协议类，含"风险/告警"归入风险类）并给出置信度。要求：补全候选必须标注 `confidence: low` 待人工确认。

## 场景 3：图谱版本漂移巡检
> 已有上一版图谱快照 `{prev_snapshot}`（含 graph_hash 与版本号）。本周文档库有新增/修订，请重新抽取并重建图谱：1) 比对新图 SHA256 与旧快照，若一致则输出 `version_bump: unchanged` 并保持版本号；2) 若不一致则补丁号 +1 升级，输出新增/消失的节点与边清单；3) 任何无版本升级的图谱变更都视为无声漂移并告警。要求：快照只存哈希与元数据，不存全量图；巡检报告可归档为合规记录。

## 场景 4：多业务域资产统一归类
> 公司有多个业务域的文档散落各处。请在同一实体词典下跨域建图：1) 每个域的组织/产品/人员节点统一编号；2) 用九大元类把全部节点归入 公理/定理/方法/数据/案例/决策/创意/风险/协议；3) 输出每类节点数量分布与低置信度（<0.3）待人工复核清单。要求：跨域同名实体必须归一，不得出现两个同规范名节点。
