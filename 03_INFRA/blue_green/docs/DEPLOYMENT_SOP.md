## 一、核心原则

1. **不停机**：更新过程中旧版本持续运行，用户无感知
2. **可回滚**：发现问题秒级切换回旧版本，无需重新部署
3. **灰度验证**：新版本先给小流量验证，稳定后逐步全量
4. **数据兼容**：数据库变更必须向前/向后双兼容
5. **配置隔离**：新旧版本配置独立，互不影响
6. **健康熔断**：新版本异常自动熔断，流量切回旧版本

## 二、更新前检查清单

执行更新前，必须确认以下所有项：

### 2.1 代码检查
- [ ] 新版本代码已通过本地测试
- [ ] 新版本代码已通过代码审查
- [ ] 新版本无已知的严重Bug
- [ ] 新版本依赖已确认兼容

### 2.2 数据检查
- [ ] 数据库变更为扩展式（只新增，不修改/删除现有字段）
- [ ] 数据库变更已在测试环境验证
- [ ] 数据迁移脚本已准备
- [ ] 数据库备份已完成

### 2.3 配置检查
- [ ] 新版本配置文件已准备
- [ ] 配置与旧版本兼容（旧版本能读取新配置）
- [ ] 敏感配置（API密钥等）已正确设置
- [ ] Nginx配置模板已验证

### 2.4 环境检查
- [ ] 蓝环境（当前运行）状态正常
- [ ] 绿环境（备用）已清空并准备就绪
- [ ] 磁盘空间充足（至少2倍新版本大小）
- [ ] 内存和CPU资源充足
- [ ] 备份机制正常

### 2.5 回滚准备
- [ ] 回滚预案已确认
- [ ] 回滚工具已验证可用
- [ ] 回滚联系人已确认
- [ ] 回滚决策人已授权

## 三、蓝绿部署标准流程

### 步骤1：备份当前版本（自动）
```bash
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/blue_green_deploy.py \
  --source-dir /path/to/new_version \
  --version v2.0.0
```
工具会自动完成：
1. 备份当前运行版本（代码+配置）
2. 部署新版本到备用环境
3. 备用环境健康检查
4. 流量切换（秒级）
5. 切换后验证

### 步骤2：验证新版本
- [ ] 核心功能测试通过
- [ ] 页面访问正常
- [ ] API响应正常
- [ ] 数据库读写正常
- [ ] 错误率在正常范围
- [ ] 响应时间在正常范围
- [ ] 用户反馈无异常

### 步骤3：观察期（30分钟-24小时）
- 持续监控新版本健康状态
- 监控错误率、响应时间、用户反馈
- 旧版本保持运行，随时可回滚

### 步骤4：确认稳定
- 观察期内无异常
- 新版本承载100%流量
- 旧版本转为备用（保留7天）

## 四、金丝雀发布流程（更安全）

适用于重大更新或高风险更新。

### 放量阶段
1. **5%流量**：验证基本稳定性（5分钟）
2. **20%流量**：扩大验证范围（10分钟）
3. **50%流量**：对半验证（15分钟）
4. **100%流量**：全量发布

### 命令
```bash
# 开始金丝雀发布
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/canary_release.py --start

# 查看发布状态
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/canary_release.py --status

# 手动回滚
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/canary_release.py --rollback
```

## 五、回滚预案

### 5.1 回滚触发条件

满足以下任一条件，立即触发回滚：
1. 错误率 > 5%，持续2分钟
2. 响应时间 > 2秒，持续2分钟
3. 核心功能不可用
4. 数据异常或数据丢失
5. 用户投诉集中爆发
6. 安全漏洞被利用
7. 系统资源耗尽（CPU/内存/磁盘）

### 5.2 三层回滚保障

| 层级 | 触发条件 | 回滚时间 | 操作 |
|------|----------|----------|------|
| **L1 流量回滚** | 新版本异常 | <1秒 | Nginx切换回旧版本，旧版本仍在运行 |
| **L2 配置回滚** | 配置变更导致问题 | <5秒 | 恢复上一版本配置，reload服务 |
| **L3 版本回滚** | 代码级问题，L1/L2无法解决 | <1分钟 | 从备份目录快速恢复旧版本代码 |

### 5.3 回滚命令

```bash
# L1 流量回滚（最快，优先使用）
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/rollback.py --level L1

# L2 配置回滚
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/rollback.py --level L2

# L3 版本回滚（最彻底）
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/rollback.py --level L3

# 自动选择回滚层级
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/rollback.py --auto --reason "错误率过高"
```

### 5.4 回滚后验证

- [ ] 核心功能测试通过
- [ ] 错误率恢复正常
- [ ] 响应时间恢复正常
- [ ] 数据一致性验证
- [ ] 用户反馈确认
- [ ] 记录回滚事件和原因

## 六、数据库变更规范

### 6.1 强制规则
1. **只扩展，不修改**：只新增字段/表，不修改/删除现有字段
2. **双写过渡**：新旧版本同时写新旧字段
3. **灰度迁移**：数据分批迁移，每批验证后继续
4. **向后兼容**：新版本能读取旧版本的数据格式
5. **向前兼容**：旧版本能读取新版本的数据格式（新增字段可为空）

### 6.2 数据库变更流程
1. 扩展式变更（新增字段，可为空）
2. 新版本双写（新旧字段同时写）
3. 历史数据灰度迁移（分批）
4. 新版本读取新字段
5. 观察期（7天）
6. 旧字段废弃（30天后确认无问题再考虑删除）

## 七、健康监控与自动熔断

### 7.1 健康检查
```bash
# 执行一次健康检查
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/health_monitor.py --once

# 查看健康状态
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/health_monitor.py --status

# 持续监控模式（守护进程）
python3 /opt/ZONGYUAN-ROOT/blue_green/scripts/health_monitor.py --daemon
```

### 7.2 自动熔断阈值
- 错误率 > 5%
- 响应时间 > 2秒
- 连续失败 >= 3次

触发自动熔断后，系统自动执行L1流量回滚。

## 八、更新后清理

更新确认稳定后（7天）：
1. 旧版本代码可归档（不删除，保留30天）
2. 旧版本配置可归档
3. 数据库旧字段可标记为废弃（30天后再删除）
4. 更新记录写入Merkle-DAG确权
5. 更新经验沉淀到学习进化引擎
