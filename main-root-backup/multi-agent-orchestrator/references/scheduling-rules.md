# 多智能体并行编排 · 落地调度规则 v1.0

Ω₀⊂⊙∞⊂Ω｜DID‑BR‑000002｜ZONGYUAN‑ROOT
> 关联技能：multi-agent-orchestrator ｜ 本文为任务级并行调度的完整细化规则（推演→落地的规则层）

## 定位

推演给出"组织该长什么样"；本规则给出"任务怎么拆、怎么分、怎么并行、怎么收、失败怎么办"。这是多智能体并行编排真正能跑起来的执行层规范。类比：批量工单派单平台的自动分配规则。

---

## 规则一：任务分配规则（Task-Allocation）

**目标：一个任务进来，确定它拆不拆、拆几片、每片归谁。**

1. 单次只读预检：判定前最多做一次轻量探查，只数关键量（对象数O / 维度数D / 通道数C / 流水线单元数U / 记录数N）。
2. 命中任一触发门槛即委派，否则主智能体直接完成（见 SKILL 第三章）。
3. 每任务只创建一个编排智能体（OrganizerAgent），但编排智能体可拆 2–4 个并行子智能体分片。
4. 分片维度优先级：平台/通道 → 目录/地域 → 时间片 → 类型。一个任务主用单维度分片，不混用。
5. 每个子智能体分片必须"端到端自持"：采集→处理→分析→校验→标准化输出，全程独立完成。
6. 分配记入计划表：`shard_id | 归属单元 | 负责人 | 输入 | 输出schema | 依赖`。

**铁律：** 分配时以"最小化显著缩短关键路径的分片数"为度，默认 2–4；不是越多越好。

---

## 规则二：并行与并发规则（Parallelism & Concurrency）

**目标：确定哪些片能同时跑，哪些必须等，并发度上限多少。**

1. **片间并行、片内串行**：互不依赖的单元并行执行；同一单元内的串行步骤保持串行（前一步是后一步前提）。
2. **独立流水线单元判定**：只有"最小对象其完整采集→处理→校验可独立完成、不依赖另一单元结果"才计为一个可并行单元。
3. **大 N/B 不必然扇出**：资源量只说明"需要编排执行"，不自动产生多个子智能体；扇出仍须存在可独立执行的分区。
4. 并发度默认 ≤ 并行分片数；不设全局并发上限的隐性放大，避免过度并行拖垮共享资源。
5. 共享状态/共享资源的分片必须串行或加锁，不得并行写入同一目标（同文件、同目录、同 Base 表）。

**铁律：** "能不能并行"的判定依据是**依赖关系**，不是"任务看起来大"。

---

## 规则三：负载均衡规则（Load Balancing）

**目标：各分片工作量均衡，避免有的片重载、有的片空转。**

1. 按单元数均衡（轮转）为基线，但必须结合**预估权重**（文件体积、记录数、处理耗时）加权分配。
2. 单单元过重（如单个超大目录/单张大表）时，允许独立成片，不强行均分。
3. 任一分成片权重占比 > 40% 视为失衡，需重新拆分或补充并行。
4. 分配后产出 `shard_id → 预估工作量` 对照表，便于调度复核。

**铁律：** 均衡目标是"各片大致同时间完成"，不是"各片单元数相等"。

---

## 规则四：结果回收与聚合规则（Result Collection & Merge）

**目标：多片结果以统一格式回收，去重、溯源、补缺口，合并为一份台账。**

1. **统一输出 schema**：所有分片使用同一 schema（见 multi_agent_plan.py merge-schema），否则聚合失败。
2. 编排智能体负责聚合：跨片去重、来源溯源（每项标注 local/drive/wiki/base/doc/sheet）、识别覆盖缺口。
3. 冲突处理：同名/同源项以"更新者+哈希"裁定，保留溯源记录；无法裁定则并列标记待人工。
4. 聚合结果必须包含：资产总量、按来源分布、缺口清单、重复清单、未同步清单。
5. 聚合台账交付给主智能体，由主智能体向用户呈现；编排智能体不回直接交付给用户。

**铁律：** 分片输出不一致时，宁可失败重跑该片，也不静默合并。

---

## 规则五：失败处理与隔离规则（Failure Handling & Isolation）

**目标：一片失败不影响整体，可重试、可隔离、可降级。**

1. **失败隔离**：单分片失败不阻塞其他分片；其他分片结果正常回收，失败片单独标记。
2. **重试策略**：瞬时错误（rate limit / 临时网络）有限重试（≤3次，带退避）；非瞬时错误（权限/not found/参数错）不盲目重试，直接上报。
3. **降级路径**：主通道失败可降级到备用通道（如 BGE 不可用→hash 降级），但必须显式标注降级，不静默。
4. **记录**：每失败片写入 `shard_id | 错误类型 | 是否重试 | 重试结果 | 是否降级`，随台账交付。
5. **总控兜底**：编排智能体对无法自愈的失败，作为"待人工处理缺口"列入台账，不吞掉。

**铁律：** 失败必须可见、可追溯；禁止用"看起来完成"掩盖单分片失败。

---

## 规则六：总控与生命周期规则（Orchestrator Control）

**目标：明确谁总控、各执行体生命周期、任务如何收尾。**

1. **主智能体（MainAgent）**：唯一对用户入口，负责：判定是否委派、创建编排智能体、接收台账、向用户交付、处理后续请求。
2. **编排智能体（OrganizerAgent）**：一个任务一个，负责：规划分片、创建子智能体、协调并行、聚合台账、识别缺口、回传主智能体。
3. **子智能体（SubAgent）**：端到端自持一个分片，完成后返回标准化输出；不跨片通信（如需协作，经编排智能体中转）。
4. **生命周期**：子智能体完成即止；编排智能体完成聚合后进入待命（可复用）；任务终结后不长期驻留。
5. **只读任务约束**：扫描/盘点类任务默认只读，禁止删除/移动/覆盖/权限变更；写操作必须先列候选、等确认。

**铁律：** 总控唯一、责任单一；谁创建谁负责收尾；写操作永远先确认。

---

## 规则七：确权与档案规则（Provenance & Archive）

**目标：每次编排产生可追溯证据，纳入昆仑洞天确权体系。**

1. 每次编排执行，产出 `MAO-PLAN-<时间戳>.json`（分片计划）+ `MAO-LEDGER-<时间戳>.json`（执行台账）落盘。
2. 关键文件 SHA-256 追加写入 HASH-LEDGER.csv（确权链）。
3. 分片计划、执行台账、聚合台账三者互链（计划→执行→结果可回溯）。
4. 受 META-ASSET-002（资产双副本镜像备份）与 META-DIR-LOCK-001（目录锁档）元法则约束。

**铁律：** 无确权记录的执行视为未完成；证据链必须可回溯。

## 快速路由（对应规则落盘）

```bash
# 生成分片计划（规则一二三四六）
python3 scripts/multi_agent_plan.py --mode scan-plan --root <ROOT> --channels drive,wiki,base,doc,sheet
# 评估是否达编排门槛（规则一）
python3 scripts/multi_agent_plan.py --mode evaluate --objects 8 --dims 5 --channels drive,wiki,base,doc,sheet --records 200000
# 均衡分片（规则三）
python3 scripts/multi_agent_plan.py --mode shard-plan --units "a,b,c,d,e,f,g,h" --shards 4
# 统一回收schema（规则四）
python3 scripts/multi_agent_plan.py --mode merge-schema
# 失败/总控/确权记录（规则五六七）——由执行过程产生，人工核对
```
