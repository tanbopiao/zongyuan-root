## 一、架构目标

将分散在多个节点/实例的计算资源（CPU、内存、磁盘、负载）统一登记为「算力池」，实现：
- **资源可见**：全节点算力一目了然，不再盲猜实例配置
- **负载可衡**：按负载指标评估节点繁忙度，为任务调度提供依据
- **调度可依**：高负载任务自动倾向空闲节点，低负载节点承接重任务
- **异常可察**：离线/过载节点即时暴露，触发告警

## 二、架构分层

```
┌─────────────────────────────────────────────┐
│ 调度层：任务台账 + 优先级 + 算力池负载匹配    │
├─────────────────────────────────────────────┤
│ 池化层：飞书共享大脑「算力池」表（统一台账）   │
│   节点名称 | CPU核数 | 内存GB | 负载 | 状态    │
├─────────────────────────────────────────────┤
│ 采集层：compute_pool.py（每节点每小时上报）    │
│   /proc/cpuinfo /proc/meminfo /proc/loadavg  │
├─────────────────────────────────────────────┤
│ 物理层：本地实例 / 云端Worker / 边缘节点      │
└─────────────────────────────────────────────┘
```

## 三、数据流

1. 每个节点运行 `compute_pool.py`：读取真实 `/proc` 指标（CPU核数/内存总量/可用内存/1分钟负载/磁盘可用）
2. 按「节点名称」幂等上报至共享大脑算力池表（存在→更新，不存在→创建）
3. 调度时读取算力池表：任务分配优先选 负载低 + 可用内存高 的节点
4. 每小时自动刷新，离线节点（超过 2 小时未更新）标记离线

## 四、调度分配策略

| 条件 | 分配倾向 |
|---|---|
| 负载 < 0.5 且可用内存高 | 优先承接计算型任务 |
| 负载 0.5–1.5 | 承接常规任务 |
| 负载 > 1.5 或可用内存 < 1GB | 暂缓分配，标记高负载 |
| 超过 2 小时未上报 | 标记离线，任务转其他节点 |

## 五、落地组件

| 组件 | 路径 | 职责 |
|---|---|---|
| compute_pool.py | 各节点工作目录 | 采集+幂等上报算力 |
| 算力池表 | 共享大脑 tblTo4qlvzE1EdYR | 池化台账 |
| 每小时挂载 | auto_report_brain.py 第 7 步 | 自动刷新 |

## 六、验收标准

- 本节点算力真实登记：CPU核数/内存GB/负载/状态 四项齐全
- 幂等：重复执行不产生重复记录
- 自动化：每小时自动刷新，无需人工干预
- 数据真实：全部来自 /proc 实测，禁止虚构
