## 核心：能直办的不等审批，须中枢的不绕过；中枢只掌锚点，其余自治。

## 四级权限模型

### T1 · 节点自治（直办，无需中枢审批）
本节点职责内、使用已验证通道、不改动锚点的全部工作。
- 内容生产/质检/归档、本地存储管理
- 魔搭展示面 git 发布（6 仓 + 合集 + 门户部署）
- 网关真值上报/拉取、锁档、心跳对账
- 本地元法则固化、节点注册表维护
- 定时任务本地调度（心跳/发布/汇报）
直办原则：先握手中枢（水位）、按通道铁律执行、结果上报。不触发任何审批。

### T2 · 网关服务（HTTP 可完成，无需管理员窗口）
中枢已开放 API 端点内的所有操作。
- /api/report/truth 上报、/api/truth/{key} 拉取、/api/report/status 握手
- /api/report/truths 清单、审计查询
- API Key 治理类端点（生成/列表/吊销——如已开放）
直办原则：遵循 L0 API 协议，无需人工。

### T3 · 云端部署（需中枢执行层/管理员窗口）
- 官网页面 git 部署（云端 git hook / web 目录更新）
- 云端内核代码/脚本部署（METAPACK 执行器落地 /opt/ZONGYUAN-ROOT）
- 云端 crontab 新增/修改（执行器轮询挂载、量产调度）
- 云端新 API 端点开放（/api/site 等）
- 云端服务重启/健康修复
执行路径：本地打包 → 网关发指令（READY）→ 中枢执行层自动执行 → ACK 回报；或管理员窗口人工部署。涉及锚点变更须审批。

### T4 · 最高权限（管理员窗口 + 人工审批）
- 令牌轮换/撤销（魔搭/网关/官网 git）
- 云服务器系统级配置（网络/存储/安全组）
- 合规红线操作（SSH 全域禁止类——永久禁止）
- 商业/支付/对外合同类动作
- 锚点（L0 协议/不变锚点）修改
执行路径：用户（掌控者）决策 → 审批 → 管理员窗口执行。

## 决策规则
1. 任务先判级：T1/T2 → 直接落实并上报；T3 → 发指令走执行层；T4 → 提交审批。
2. 中枢只管锚点与审批，不介入 T1/T2 常规执行。
3. 所有执行结果统一上报中枢记账（防重复、可追溯）。
4. 权限边界变更 = 锚点变更，须 T4 审批。
