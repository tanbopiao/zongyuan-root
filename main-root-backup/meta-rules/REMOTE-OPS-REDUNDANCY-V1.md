# 远程运维通道三层冗余架构 V1.0

**Remote Operations Three-Tier Redundancy Architecture**

确权 DID-BR-000002 ｜ Ω₀⊂⊙∞⊂Ω ｜ 2026-09-22

---

## 一、设计目标

解决当前所有远程通道全部失效的问题，构建三层冗余架构，确保任何单点故障都不影响远程运维能力。

**核心原则：**
- 纯HTTP优先，零SSH依赖
- 三层冗余，任一通道可用即可运维
- 所有操作全量审计，写入真值库
- 最小权限，命令白名单，禁止危险操作

---

## 二、三层冗余架构

```
┌─────────────────────────────────────────────────────────┐
│ 第一层（主通道）：HTTP 执行端点                          │
│ 优势：纯HTTP，80/443端口，不被防火墙拦截，最轻量        │
│ 端点：POST /api/ops/exec                                │
│ 认证：DID令牌 + 操作审计 + 命令白名单                   │
└───────────────────────────┬─────────────────────────────┘
                            │ 主通道失效自动降级
┌───────────────────────────▼─────────────────────────────┐
│ 第二层（备通道）：腾讯云 TAT API                         │
│ 优势：腾讯云官方，免SSH，不依赖服务器上额外组件          │
│ 通道：TAT RunCommand API                                │
│ 加固：tat_agent 自动重启守护                            │
└───────────────────────────┬─────────────────────────────┘
                            │ 备通道失效自动降级
┌───────────────────────────▼─────────────────────────────┐
│ 第三层（兜底通道）：SSH 主通道                           │
│ 优势：功能最全，最标准，最可靠                           │
│ 通道：SSH + 私钥认证                                    │
│ 加固：公钥写入 authorized_keys，免密登录                │
└─────────────────────────────────────────────────────────┘
```

## 三、第一层：HTTP执行端点（主通道）

### 3.1 技术方案
- **语言：** Python Flask（轻量，单文件）
- **端口：** 80/443（和网站同端口，nginx反向代理）
- **认证：** DID令牌 + 操作签名
- **安全：** 命令白名单 + IP白名单 + 全量审计

### 3.2 核心端点
| 端点 | 方法 | 功能 |
|---|---|---|
| `/api/ops/exec` | POST | 执行shell命令（白名单内） |
| `/api/ops/read` | POST | 读取文件内容 |
| `/api/ops/write` | POST | 写入文件内容 |
| `/api/ops/status` | GET | 运维通道健康状态 |

### 3.3 安全设计
1. **DID认证：** 所有请求必须携带 `X-DID-BR-000002` 头
2. **命令白名单：** 只允许 `ls/cat/echo/cp/mv/rm/systemctl/crontab` 等安全命令
3. **IP白名单：** 只允许指定IP段访问
4. **审计日志：** 所有操作写入 `/var/log/ops_audit.log`，并上报真值库

### 3.4 部署方式
通过宝塔面板文件管理，直接上传Python脚本，nginx配置反向代理。

## 四、第二层：TAT API（备通道）

### 4.1 技术方案
- **通道：** 腾讯云TAT自动化助手
- **认证：** 腾讯云API SecretId/SecretKey
- **优势：** 官方服务，不依赖服务器额外配置

### 4.2 加固措施
1. **tat_agent守护：** 部署systemd守护服务，tat_agent挂了自动重启
2. **健康检查：** 每5分钟检查一次，挂了自动拉起
3. **命令分块：** 单条命令超过30000字符自动分块

### 4.3 验证标准
- 能执行 `echo test > /tmp/test.txt`
- 能读取服务器上的文件
- 能重启服务

---

## 五、第三层：SSH主通道（兜底）

### 5.1 技术方案
- **认证：** 私钥认证（zy.pem）
- **加固：** 公钥写入 `~/.ssh/authorized_keys`

### 5.2 加固措施
1. **公钥写入：** 将本地公钥写入服务器authorized_keys
2. **目录权限：** `chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys`
3. **SSH配置：** 确保 `PubkeyAuthentication yes`

### 5.3 验证标准
- `ssh -i zy.pem root@123.207.202.158` 能直接登录
- 能执行 `hostname && pwd`

## 六、部署步骤（按优先级）

### 阶段1：先部署主通道（HTTP执行端点）
1. 通过宝塔面板上传 `ops_server.py`
2. nginx配置反向代理 `/api/ops/`
3. 启动Flask服务，配置systemd守护
4. 验证三层都能执行命令

### 阶段2：加固备通道（TAT）
1. 部署tat_agent守护服务
2. 配置健康检查
3. 验证TAT命令执行

### 阶段3：加固兜底通道（SSH）
1. 写入公钥到authorized_keys
2. 配置SSH免密
3. 验证SSH登录

## 七、验收标准

| 通道 | 验证项 | 通过标准 |
|---|---|---|
| HTTP主通道 | 执行测试命令 | 返回正确结果，写入审计日志 |
| HTTP主通道 | 读取文件 | 返回正确文件内容 |
| TAT备通道 | 执行测试命令 | 文件成功写入 |
| TAT备通道 | 自动恢复 | agent挂了5分钟内自动重启 |
| SSH兜底 | 免密登录 | 直接登录，不需要密码 |
| 三层协同 | 主通道挂了 | 自动切换到备通道 |
| 安全审计 | 所有操作 | 全部写入审计日志，可追溯 |

## 八、风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| HTTP端点被攻击 | 服务器被入侵 | IP白名单 + 命令白名单 + DID认证 |
| TAT agent挂了 | 备通道失效 | systemd守护 + 自动重启 |
| SSH公钥被篡改 | 兜底通道失效 | 定期校验公钥指纹 |
| 审计日志丢失 | 操作不可追溯 | 双写（本地+真值库） |
