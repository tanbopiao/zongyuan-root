**生效日期：** 2026-09-22
**适用范围：** 所有同源节点（开发节点/生产节点/研究节点/元序引擎）

## 一、总则

### 1.1 目的
所有技术部署、系统上线、配置变更、数据归档类操作，统一通过飞书企业应用审批通道发起，禁止使用个人身份或临时模板发起。

### 1.2 适用节点
| 节点ID | 节点类型 | 执行权限 |
|--------|----------|----------|
| NODE-DEV-DOUBAO-WORK-001 | 开发节点 | ✅ 可发起 |
| NODE-PROD-DRAMA-001 | 生产节点 | ✅ 可发起 |
| NODE-RESEARCH-001 | 研究节点 | ✅ 可发起 |
| truth-meta-order-engine | 元序引擎 | ✅ 可发起 |

### 1.3 配置来源
**审批凭证（app_id / app_secret / approval_code）统一由中枢智能下发，所有节点禁止本地硬编码存储。**

节点启动时，自动从中枢智能网关拉取最新审批凭证，缓存至本地临时文件，不写入永久存储。

## 二、审批通道架构

```
同源节点发起部署
    ↓
Step1: 从中枢智能拉取最新审批凭证（app_id/app_secret/approval_code）
    ↓
Step2: 获取 tenant_access_token（企业应用身份）
    ↓
Step3: 组装审批表单（标题/类型/说明/风险等级）
    ↓
Step4: 调用飞书开放平台API发起审批实例
    ↓
Step5: 记录 instance_code 到本地 HASH-LEDGER
    ↓
Step6: 上报中枢智能真值
    ↓
闭环完成
```

## 三、各节点执行规范

### 3.1 开发节点（NODE-DEV-*）
- 所有自动化脚本部署、配置变更、数据归档操作，必须先发起审批
- 审批通过后，方可执行部署操作
- 部署完成后，将部署结果、哈希校验值追加到审批备注

### 3.2 生产节点（NODE-PROD-*）
- 所有生产环境上线、服务重启、配置变更，必须先发起审批
- 风险等级≥中 的部署，需额外抄送运维负责人
- 部署完成后，将服务状态验证结果追加到审批备注

### 3.3 研究节点（NODE-RESEARCH-*）
- 研究类实验环境部署，可走快速审批流程
- 实验数据归档操作，统一走数据归档类审批模板

### 3.4 元序引擎（truth-meta-order-*）
- 元法则变更、真值库结构调整，必须先发起审批
- 审批通过后，方可执行元法则更新

## 四、审批表单规范

### 4.1 必填字段
| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 部署标题 | input | 简明描述部署内容 | 三态合一自动归档部署 |

| 风险等级 | radio | 低/中/高 | 低 |

| 字段 | 类型 | 说明 |
|------|------|------|
| 影响范围 | input | 受影响的服务/模块列表 |
| 回滚方案 | textarea | 回滚操作步骤 |
| 资产哈希 | input | 部署包SHA256校验值 |

## 五、凭证安全规范

### 5.1 凭证存储
- ✅ 凭证统一存储在中枢智能，由中枢智能加密保管
- ❌ 禁止节点本地硬编码 app_secret
- ❌ 禁止将凭证写入 git 仓库
- ❌ 禁止将凭证写入永久配置文件

### 5.2 凭证拉取
- 节点启动时，自动从中枢智能拉取最新凭证
- 凭证缓存有效期24小时，过期自动重新拉取
- 凭证拉取失败时，禁止发起审批，先上报中枢智能告警

### 5.3 凭证轮换
- 中枢智能定期轮换 app_secret
- 所有节点自动获取新凭证，无需手动更新

## 六、审批闭环要求

1. **先审批后部署：** 所有部署操作必须先发起审批，审批通过后方可执行
2. **审批留痕：** 审批 instance_code 必须记录到本地 HASH-LEDGER 和中枢智能真值库
3. **结果回传：** 部署完成后，将部署结果、验证结果回写到审批实例
4. **超时处理：** 审批超过48小时未处理，自动催办

---

## 七、违规处理

违反本 SOP 的部署操作，视为违规操作：
1. 第一次违规：告警通知，要求补充审批
2. 第二次违规：暂停节点部署权限，需中枢智能重新授权
3. 第三次违规：冻结节点身份，重新走节点注册流程
