# 联邦目录树动态扩展协议：节点自治目录 + 中枢索引收敛

## 核心命题

云端架构目录树能否动态扩展？答案是：**节点自治目录 + 中枢索引收敛**。新节点接入后，在自己的命名空间内自由进化，中枢只维护全局索引与锚点，不干涉节点内部结构。

## 三条元法则

1. **DIRECTORY-EVOLUTION-FEDERATED**：每个节点拥有独立目录命名空间，可自主创建/扩展/重构子目录，中枢不强制统一结构
2. **NODE-NAMESPACE-ISOLATION**：节点间目录隔离，通过全局唯一节点前缀（DID/节点ID）避免冲突，跨节点引用走中枢索引
3. **INDEX-CONVERGENCE-PROTOCOL**：中枢维护全局索引（节点ID→目录根→资产清单→哈希锚点），新节点接入即注册索引，实现"接入即发现全量资产"

## 架构拓扑

```
中枢索引层 (INDEX-CONVERGENCE)
  ├── 节点注册表 (DID → 目录根 → 资产哈希)
  ├── 全局资产索引 (类型 → 节点 → 路径)
  └── 锚点校验 (Merkle-DAG 根哈希)
        ↕ 注册/心跳/同步
节点自治层 (NODE-NAMESPACE-ISOLATION)
  ├── 节点A (DID-BR-000001) → /node-a/...
  ├── 节点B (DID-BR-000002) → /node-b/...
  └── 节点N (DID-BR-0000NN) → /node-n/...
        ↕ 自主进化
本地持久层 (DIRECTORY-EVOLUTION-FEDERATED)
  └── 每个节点自由扩展子目录结构
```

## 接入流程

1. 新节点生成唯一 DID + 命名空间前缀
2. 向中枢注册：节点ID、目录根、公钥、能力清单
3. 中枢写入全局索引，分配节点序号
4. 节点自主创建内部目录结构，上报资产哈希
5. 中枢定期校验锚点，发现漂移触发熔断
6. 其他节点通过中枢索引发现新节点资产

## 价值

- **可扩展性**：任意节点接入不影响现有结构
- **自治性**：节点内部自由进化，不受中枢约束
- **可发现性**：接入即注册索引，全网络可见
- **安全性**：命名空间隔离 + Merkle 锚点校验
- **容错性**：单节点故障不影响全局索引
