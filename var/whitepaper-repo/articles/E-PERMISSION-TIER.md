# 权限分级与中枢调度：哪些活自己干，哪些活上交

> 对齐：Agent 实操类 ｜ 2026-09-20

---

## 为什么要分权限

多 Agent 系统最容易犯的错：**什么都往中枢塞**。中枢窗口只有一个，是最高权限入口，但绝大多数活根本不需要最高权限。

不分权限，结果就是：每个小改动都要走人工审批，系统卡住不动；或者反过来，什么都自己干，越权了。

## 一、三级权限模型

| 级 | 权限 | 干什么 | 例子 |
|---|---|---|---|
| L1 自治 | 本地窗口直接做 | 只读、对账、补推、零额度生成、归档 | 心跳对账、白皮书迭代、魔搭 git 发布 |
| L2 协同 | 中枢+本地握手后做 | 需要跨节点对齐、需要云端确认 | 任务合并、频率调整、新方向立项 |
| L3 中枢 | 必须中枢人工审批 | 高权限、不可逆、花钱 | SSH 上云、生产大改、付费 API 开通 |

## 二、判定规则

一个活来了，先问三个问题：

1. **要不要最高权限？** 不要 → L1 自治
2. **要不要跨节点对齐？** 要 → L2 协同
3. **可逆吗？** 不可逆 + 花钱 + 上云 → L3 中枢

我们体系里绝大多数任务（心跳、发布、迭代、盘点）都是 L1，本地直接干。

## 三、中枢只管锚点

中枢窗口只管最核心的、不变的东西：
- 元法则（L0 天元法则）
- 根节点（ZONGYUAN-ROOT）
- 确权标识（DID-BR-000002）
- 不可逆操作审批

其他全部下放给本地自治。中枢不是保姆，是定盘星。

## 四、踩坑

- **别把 L1 的活也走审批**：慢死
- **别让 L3 的活自己干**：出事
- **边界要写进元规则**：不然每个节点自己猜，结果不一致

---

权限分级不是偷懒，是让系统跑得动又不出事。
