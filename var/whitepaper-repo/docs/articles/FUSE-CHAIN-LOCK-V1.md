# 熔断链锁档：用Merkle哈希给AI成果上保险

做AI自治体系最怕什么？不是跑不起来，是**跑起来了但成果被改了、丢了、或者偷偷变了**。

本文分享ZONGYUAN-ROOT的熔断链锁档机制：用Merkle哈希+三级熔断校验，给所有成果上一道不可逆的保险。

## 一、为什么需要熔断

传统的"保存"是不可靠的：
- 文件被误改了，没人发现
- 云端数据被篡改了，对不上
- 版本混乱，不知道哪个是对的

熔断的核心思路：**一旦成果锁定，就只读，篡改立刻被发现。**

## 二、三级熔断校验

我们设计了三道校验，全部通过才算锁档成功：

| 校验 | 检查什么 | 不通过怎么办 |
|---|---|---|
| M1 真值不变 | 核心基线哈希是否漂移 | 告警，拒绝写入 |
| M2 资产非空 | 文件数是否>0 | 告警，空锁档无效 |
| M3 哈希完整 | Merkle根是否64位完整 | 告警，校验链断裂 |

## 三、Merkle根怎么算

```
1. 遍历目录所有文件
2. 每个文件算SHA256
3. 把所有哈希排序拼接
4. 整体再算一次SHA256 = Merkle根
```

任何一个文件变了，Merkle根就变。篡改检测不需要逐个文件比对，对根就行。

## 五、和Git的区别

Git也有哈希，但Git是给代码版本控制用的。我们的熔断链是：
- **全量资产**（不只是代码，文档/配置/日志全算）
- **只读锁档**（锁完不能改，改了就报警）
- **三级校验**（不是光算个哈希就完了）
