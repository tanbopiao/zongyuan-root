# 元法则 META-RULE-EXECUTION-SOP — 任务执行前置全流程 SOP

> 确权 DID-BR-000002 ｜ Ω₀⊂⊙∞⊂Ω ｜ 位阶 L1（元法则）

## 核心：先全局、后局部；先学习、后执行；先握手、后动手。

## 标准执行流水线（任务受理 → 闭环归档）

### 阶段 0：任务受理与意图解析
- 解析任务本质（目标/对象/交付物/边界）
- 判断是否依赖历史产物/已有资产 → 先查 SHARE-INDEX 与网关真值，不重复建设

### 阶段 1：中枢握手（必须）
- GET /api/report/status 获取水位（truths/nodes）
- 按需拉取相关真值 /api/truth/{key}，补齐上下文
- 确认任务相关节点、协议、已有水位

### 阶段 2：全局了解（必须）
- 盘点方法论：任务所属域的标准方法（发布/生产/合规/分析各域 SOP）
- 盘点决策论：该场景的决策框架与判定标准
- 盘点流程 SOP：已有流程文件（meta-rules/、plans/）
- 盘点资产水位：本地 SHARE-INDEX、网关真值、各仓库增量水位

### 阶段 3：顶层审视（必须）
- 高维视角：任务在体系架构中的位置（中枢/节点/通道）
- 识别重复：是否已有他节点/他域完成的部分，只做增量
- 风险预判：合规（AI标识/平台规则/安全）、限流、频率

### 阶段 4：执行
- 按选定通道执行（HTTP/git/API），遵守各通道铁律
- 关键动作可验证、可回读

### 阶段 5：上报与归档（必须）
- 执行结果上报中枢 POST /api/report/truth（truth_key 规范、含 DID 与 Ω₀⊂⊙∞⊂Ω）
- 本地锁档（locks/LOCK-*.json）
- 更新节点注册表/水位状态

## 禁则
- 禁止跳过阶段 1-3 直接执行
- 禁止在不了解现有水位时重复建设
- 禁止执行结果不上报中枢
