## 二、五条铁律（不可违反）

### 铁律1：双向物理隔离
- 本地开发环境 ≠ 云端生产环境
- 本地不直接SSH改云端代码/配置/文件
- 云端不反向推送未审核的变更到本地

### 铁律2：唯一同步通道 = 记忆网关
- 本地↔云端唯一通信通道 = 记忆网关（9120端口）
- 同步内容仅限：核心真值（truth report）
- 禁止：直接git push覆盖、直接scp上传、直接改云端文件

### 铁律3：云端大脑只读（从本地视角）
- 本地视角下云端大脑是只读的
- 本地不能直接修改云端任何东西
- 本地只能"上报真值"和"拉取真值"
- 云端的部署/变更由云端自治内核决定

### 铁律4：本地镜像 = 开发基底
- 本地从云端拉取最新记忆，在本地构建镜像
- 本地所有开发/测试/仿真都在镜像上进行
- 本地镜像可以自由改、自由删、自由重建
- 本地镜像不是真值，只是开发沙盒

### 铁律5：先本地验证，再云端部署
- 任何变更必须先在本地完成仿真测试
- 仿真测试全通过后，才允许上报核心真值到云端
- 云端收到真值后，由云端自治内核决定是否部署
- 禁止：未在本地验证就直接改云端

## 三、标准开发流程（必须按此执行）

```
步骤1：本地拉取最新真值
  → 从云端记忆网关拉取所有truth reports
  → 在本地构建最新镜像基底

步骤2：本地开发/修改
  → 在本地镜像上自由开发、修改、测试
  → 不影响云端

步骤3：本地仿真测试
  → 跑完整仿真测试（API/页面/接口全通过）
  → 修复所有问题

步骤4：本地验证通过
  → 仿真测试全绿
  → 本地功能完整可用

步骤5：上报核心真值
  → 把本次变更的核心真值上报到云端记忆网关
  → 只上报"变更了什么、为什么变、验证结果"
  → 不上传代码、不上传文件

步骤6：云端自治部署
  → 云端自治内核收到真值后
  → 自行决定是否部署、何时部署
  → 本地不指挥云端
```

## 四、禁止行为清单

| 禁止行为 | 原因 |
|---|---|
| ❌ 本地直接SSH改云端代码 | 绕过验证，可能污染生产 |
| ❌ 本地直接scp上传文件到云端 | 未经仿真测试就上线 |
| ❌ 本地直接改云端Nginx/配置 | 云端自治权不可侵犯 |
| ❌ 云端主动推送变更到本地 | 本地是开发沙盒，不是部署目标 |
| ❌ 本地拉取云端代码后直接覆盖 | 必须先拉真值，再手动对齐 |
| ❌ 跳过仿真测试直接上报 | 未验证的真值是污染 |

## 六、同步内容定义（什么算"核心真值"）

只有以下内容才允许通过记忆网关同步：
1. 架构变更（改了什么模块、为什么改）
2. 接口变更（新增/修改/删除了哪些API）
3. 状态变更（系统版本、健康状态）
4. 决策记录（为什么做这个变更）
5. 验证结果（仿真测试是否通过）

**不允许同步的内容：**
- ❌ 代码文件（代码走git，不走记忆网关）
- ❌ 配置文件（配置在云端自治管理）
- ❌ 数据文件（数据在云端持久化）
- ❌ 大文件/视频/图片（走对象存储）

## 七、违规熔断机制

如果发生以下任一情况，自动熔断：
1. 本地直接改了云端文件 → 立即回滚云端，标记污染
2. 未仿真测试就上报真值 → 真值标记为UNVERIFIED，不被云端采纳
3. 跳过记忆网关直接改云端 → 触发eFuse熔断
