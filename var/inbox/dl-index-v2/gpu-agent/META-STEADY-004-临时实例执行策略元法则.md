## 定性（判断依据）
魔搭 DSW 临时实例(沙箱)具备：会被重置、无 git push 凭证、网络波动(ntfy 不可达/429/101)、非永久资源。因此**不适合作为常驻双向联通节点**——在其上维护常驻 worker 守护/多 worker 并存属于脆弱无用功（2026-10-08 在 final-test 闭环中反复试错的根源）。

## 元法则条目

### 一、临时实例=一次性执行节点（META-STEADY-004-A）
1. 临时实例定位为**一次性算力执行单元**：clone 资产→执行→上报→可丢弃，不做常驻联通
2. 禁止在临时实例上维护常驻 worker 守护进程/崩溃拉起/多 worker 并存等脆弱链路

### 二、持久控制面解耦（META-STEADY-004-B）
1. 一切成果/脚本/元法则/命令**只固化在持久层**：魔搭数据湖 + 云端联邦记忆池 + 本地持久网络盘
2. 持久控制面(云端/魔搭/本地)永不依赖临时实例存活；实例重置不造成任何成果丢失
3. 实例侧仅需「一条命令 clone 魔搭 gpu-agent/ + 执行 + POST 云端结果」，即拉即用

### 三、通道优先级（META-STEADY-004-C）
1. 云端写+读（www.huodouai.com，POST/GET 均 200 实测）为结果回传主通道
2. 魔搭数据湖为资产/脚本持久载体；git 仅用于主控单向下发命令(实例匿名 pull 或直接 clone)
3. 临时实例上不追求实时双向；命令低频一次性、结果单向上报，够用即止

### 四、执行闭环（META-STEADY-004-D）
1. 主控把任务/脚本固化为魔搭资产 → 实例一键 clone → 执行 → POST 云端结果 → 主控 GET 读回
2. 实例结果 value 必须为**对象**（云端 value_must_be_object，禁止 json.dumps 字符串）
3. 实例可随时重建：重建后一条命令恢复全部执行能力（资产在持久层）
