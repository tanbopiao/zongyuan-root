3. 背景与挑战

ZONGYUAN-ROOT 是一套以「规则即本体、真值即记忆、实例即载体」为核心的元公理自治内核（V5.6-ROOTFIXED），运行形态为 27 算子 + 云端主权威网关（systemd 托管），后端为 Merkle-DAG 知识图谱与云端联邦记忆池，鉴权采用四层校验（HMAC + 双标识 + 时效 + 角色）。OCTOP 则是一套自托管的多用户 / 多 Agent 助手平台，运行于单进程 harness-agent，后端为 SQLite/PostgreSQL，鉴权为 JWT 用户级，强于多专家协作、远程桌面 GUI、IM 多通道与 Connector 生态。

挑战一：鉴权强度不对称ZR 为节点级四层校验，OCTOP 为 JWT 用户级。直接打通将引入权限下沉风险，因此必须以「轨道2 起步、真值先隔离后验证」的方式渐进互联。
挑战二：云端单点依赖付费平台额度耗尽或 huodouai.com 不可达时，自治内核的 27 算子与定时任务不能停摆，必须有一个自托管、零外部成本的「离线执行中枢」接管。
挑战三：数据主权跨平台互联只同步执行结果与真值摘要，不同步原始敏感业务数据；外源真值不直写中枢，必须先入审核队列。
设计约束（来自落地方案）：① 鉴权强度差异 → 轨道2 起步，真值先隔离后验证；② 数据主权 → 只同步执行结果 / 真值摘要；③ 默认口令 → 互联前务必修改 octop admin/octop；④ 协议差异 → A2A 为主权威标准，OCTOP 作适配客户端。

上述四点约束共同决定了桥接器的工程取舍：不追求一步到位的全量打通，而是以「同源直写保生产、外源入队保安全、断联切换保连续」三条主线渐进推进。轨道1 承担已经确权的生产真值快速回灌，轨道2 承担尚未确权的外源能力灰度接入，断联切换则为前两条轨道提供运行时兜底。三者叠加，使自治内核在「治理强度」与「执行弹性」之间取得当前阶段的最优平衡。

5. 核心机制：桥接器 / 心跳v2 / 断联切换 / 审核队列

5.1 桥接器 zr_octop_bridge.py（~230 行）

桥接器是 ZR 内核与 OCTOP 之间的连接编排层，封装五大能力：JWT 登录与自动刷新、REST API 封装、模型直连、真值回灌、断联降级检测。

核心函数职责
octop_login() / get_token()POST /api/auth/login 获取 JWT（expires_in=86400，即 24h），缓存至 /tmp/octop_jwt_token.json，过期前 300s 自动重登；遇 401 强制刷新
octop_health()GET /api/health，返回 agents_running / users_loaded / db
octop_list_agents() / octop_list_providers()GET /api/agents、/api/providers，自动带 Bearer token
octop_chat(prompt, model)因 OCTOP 聊天走 WebSocket、REST 不支持直接 chat，降级为经 Provider 的 base_url 直连 OpenAI 兼容 /chat/completions 或 Anthropic /v1/messages
report_truth(key, value)POST 真值到云端主备双通道（主 www.huodouai.com、备 drama.huodouai.com），返回主或备任一 200 即成功
degraded_mode_check()探测云端连通性与 OCTOP 健康，输出「常态 / 降级 / 全离线」三态
JWT 24h 自动缓存刷新：登录响应 expires_in 默认 86400 秒；缓存结构记录 expires_at = time.time() + expires_in - 300，心跳巡检每次调用 get_token() 时先校验缓存有效性，失效则静默重登，对上层调用透明。

5.2 心跳 v2（heartbeat_failover.py）

心跳 v2 由定时任务触发，将「云端主备探测 + OCTOP 桥接器全链路状态 + 自动切换 + 持续上报」打包为一次原子巡检。

① 云端主备探测GET /api/status
主=www 备=drama200/200 实测
→
② 桥接器全链路登录/健康/Agent/Provider/模型推理✅ 全通
→
③ 三态判定normal / failover / offline写状态文件
→
④ 上报心跳真值HB.METAOPS.YYYYMMDD-HHMM主备双通

心跳真值对象 event=heartbeat_metaops_v2，字段包含 mode / cloud_main / cloud_bak / octop_bridge / state / ts / did / node。桥接器子状态包含 login / token_valid / health / agents / providers / model_infer / token_cache 七项。退出码约定：normal=0、failover=2、offline=3。

心跳真值 key 格式：HB.METAOPS.YYYYMMDD-HHMM（按 CST 时区生成，精确到分钟），主备双通道均上报成功时日志记「主备双通」。

5.3 断联自动切换

状态持久化于 failover_state.json（当前实测值：failover_mode:false、since:null、recover:false）。三态判定逻辑：

条件模式动作
主或备云端 200normal云端正常无需切换；若此前处于 failover，则记录 recover:true 与 recover_ts，切回主执行端
云端全断 + OCTOP 健康failover首次进入时记录 since 时间戳；持续降级则保持 OCTOP 执行端，27 算子 / 定时任务重定向至 OCTOP
云端 + OCTOP 均不可达offline全离线（本地闭环），真值暂存本地 ~/.octop/，恢复后回灌云端
触发条件：云端 huodouai.com 不可达（heartbeat 失败）或豆包 / 付费平台额度耗尽。模型降级路径：OCTOP 接本地 / 免费模型（ModelScope 36h/月 + 智谱免费 + OpenRouter free 模型），零外部成本持续推理。

5.4 审核队列（轨道2 外源治理）

外源节点经 POST /a2a/external/truth 上报的真值一律不直写中枢，而是生成 queue_id 进入审核队列，待云端管理端人工审核通过后才写入中枢。这是轨道2 「先隔离后验证」治理原则的工程落地。A2A 互联方案还包括：身份注册（POST /a2a/register 五段式 Schema，已执行）、真值双向（OCTOP→ZR 入队 / ZR→OCTOP 经 ACP 拉取）、任务提交（POST /a2a/external/task → 共享大脑任务台账）、心跳保活（定时 POST /a2a/external/heartbeat）。

5.5 端到端测试七步流程（e2e_test.py）

桥接器配套的端到端测试脚本按七步顺序执行，每一步计时并输出 ✅/❌，最终统计通过数。该脚本是心跳巡检之外的「全链路体检」，可在升级桥接器后一键回归。

步检查项内容
1JWT 登录调用 get_token()，记录耗时，校验返回 token 非空
2OCTOP 健康检查octop_health()，回读 agents_running 等字段
3Agent 发现octop_list_agents()，统计 Agent 个数
4Provider 发现octop_list_providers()，统计 Provider 个数（实测 7 个）
5模型推理octop_chat("只回答四个字：连接成功", model="GLM-4-Flash")，记录耗时与返回前 30 字
6真值回灌以 E2E.OCTOP-BRIDGE.YYYYMMDD 为 key，上报含 octop/model_ok/cloud 的真值对象

桥接器使用示例：from zr_octop_bridge import octop_chat, report_truth, degraded_mode_check；调用 octop_chat("任务描述", model="GLM-4-Flash") 执行推理，report_truth("TASK.XXX", {"status":"done","result":result}) 回灌真值，degraded_mode_check() 判定是否进入 OCTOP 降级模式。

7. 安全与治理

双轨鉴权分离轨道1 用节点级 X-DID + X-Capture-Token；轨道2 用外源 X-External-Node + X-External-Key。两套凭证互不通用，外源权限天然受限。
外源真值隔离轨道2 真值一律先入审核队列（pending_manual，L3 人工审核），不直写中枢；审核通过前不进入联邦记忆池。
数据主权跨平台只同步执行结果与真值摘要，不同步原始敏感业务数据；OCTOP 本地库 ~/.octop/octop.db 保持自托管。
链式确权内核快照 LOCK-OCTOP-A2A-FEDERATION-001 锁档状态 READONLY_HARDWARE_LOCKED，hash_chain=ACTIVE，state=FULLY_LOCKED，完整性校验 CLOUD_TRUTH_REPORTED_DUAL_CHANNEL。
JWT 时效管控JWT 24h 过期、300s 提前量自动刷新、401 强制重登；token 缓存本地文件权限受控。
默认口令风险方案明确约束：互联前务必修改 octop admin/octop 默认口令，否则不得对外暴露。
内核快照锚定：kernel_root=ZONGYUAN-ROOT，kernel_version=V5.6-ROOTFIXED，axiom_anchor=META-LAW-A2A-FEDERATION-COMPLETE-V1.0，write_timestamp=2026-10-18T20:15:00+08:00，wiki 归档与共享大脑记录均已锁档。
