# 编排模式参考

多步任务编排的常用模式与选择要点。SKILL.md 已含速查表，本文件给出判定规则与反例。

## 串行流水线

**适用**：后一步必须消费前一步的产物（数据加工链、文档生成链、构建发布链）。

**规则**：
- 每步定义明确产物 + 质量门；质量门失败即停，不带着坏输入继续。
- 每步失败先修本步，再继续；不要跳过质量门"先跑完再说"。
- 例：读取源数据 → 清洗 → 统计 → 渲染图表 → 生成报告。任一步产物回读校验失败则中止。

**反例**：清洗步骤输出空表仍继续出图 → 报告全空但"流程走完"。

## 并行分治

**适用**：多个互不依赖的单元（多源采集、多文件处理、多候选比较）。

**规则**：
- 先确认单元间**无共享可变状态**；共享只读输入可并行，共享写入目标需分片或串行。
- 按"可独立验证的子集"分片，每片端到端完成（采集→处理→验证→标准输出）。
- 合并前先核对各片口径与去重；合并结果做交叉验证。

**反例**：两个单元并发写同一 CSV → 覆盖丢失。

## 重试与幂等

**适用**：外部网络、API、临时性故障。

**规则**：
- 有限次退避重试（如 3 次）；仅对瞬时错误重试，参数错误/权限错误不重试。
- 幂等设计：重复执行结果一致（append-only 账本、固定 ID、upsert）。
- 每次重试记录结果；重试耗尽写入失败日志并继续主流程或明确上报。

**反例**：对 404/参数错误无限重试 → 空耗。

## 增量续跑

**适用**：大批量、耗时、可断点的任务（批量下载、批量转换、长流水线）。

**规则**：
- 保留可复用的中间产物（已下载文件、已处理数据）。
- 记录断点（进度清单/队列文件）；重启时跳过已完成项，续跑未完成项。
- 每项完成即落盘登记，避免整体重算。

**反例**：中断后从头全量重跑 → 重复消耗。

## 质量门清单（每单元至少一项）

- 回读产物：用独立于生成路径的方式读取校验（测试、渲染、抽样）。
- 数值核验：合计/比例用工具重算，与明细并排核对。
- 结构校验：语法检查、schema 校验、行数/条数实数。
- 一致性：同数据跨产物并排核对（索引、账本、报告）。
