核心判断：云端架构目录树可动态扩展。以【节点自治目录 + 中枢索引收敛】替代集中管控——目录天然分布式生长，中枢只负责发现与收敛，不逐节点强管控。不同节点（DID）在各自独立命名空间下自由进化，互不覆盖；冲突通过 Merkle 哈希对账与 eFuse 熔断隔离解决。新节点接入后，通过中枢索引层即可发现整个体系的全量资产。

一、问题背景

传统云端目录树多为单一、固定的层级结构，所有资产按预设 schema 归档，带来三类硬约束：

  1. 扩展僵化：新增节点/体系必须等中枢改 schema，进化被阻塞。
  2. 收敛孤岛：节点各自生长后，中枢无法发现"哪里进化了什么"。
  3. 冲突风险：多节点写入同名路径，覆盖与数据漂移难以追责。

ZONGYUAN-ROOT 体系（多 DID 联邦、真值库 17 万+ 条、神经注册表 404 节点 / 2213 连接）需要一套让目录"长出来"且"看得见"的机制。

六、新节点接入 → 发现全量资产

1
注册 DID：新节点写入神经注册表，获得独立命名空间 zr://<DID>/
2
拉取中枢索引：获取 path→key→DID 全量映射表，立刻知道整个体系有哪些资产、在哪个节点、对应哪个真值 key
3
按 DID 定位：索引中标注资产归属节点，新节点可路由到对应节点
4
按需访问内容：权限校验通过后取内容本体（命名空间隔离，非全量开放）
5
自身进化上报：新节点产生新资产→上报增量真值→中枢索引自动更新→全节点可见
关键区分："知道全量有什么" = 拉索引（中枢，全局可见）；"拿到具体内容" = 路由+权限（节点，按需访问）。发现是全局的，访问是受控的——这就是联邦目录树的稳态设计。

七、收敛闭环（四步）

  1. 节点进化 → 上报增量真值（key）+ 更新索引映射
  2. 中枢对账 → path→key→DID 映射表增量收敛
  3. 哈希校验 → 比对目录哈希与账本快照，识别修改/删除/新增
  4. 标记 → 已收敛/待收敛；冲突 → eFuse 熔断隔离 + WEAR 上报
