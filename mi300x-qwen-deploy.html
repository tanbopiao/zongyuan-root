四、部署推理服务

4.1 最简版直接推理

from transformers import AutoModelForCausalLM, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(model_dir)
model = AutoModelForCausalLM.from_pretrained(
    model_dir,
    torch_dtype=torch.bfloat16,
    device_map="cuda",
)

messages = [{"role": "user", "content": "你好"}]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tokenizer(text, return_tensors="pt").to("cuda")

with torch.no_grad():
    outputs = model.generate(**inputs, max_new_tokens=512)

response = tokenizer.decode(outputs[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
print(response)

五、踩坑记录

坑1：显存占满直接OOM

现象：模型加载到一半直接崩掉。

原因：虽然MI300X有192GB显存，但实例分配的可能不是全部。

解决：留20%波动空间，不够就用4bit量化：

model = AutoModelForCausalLM.from_pretrained(
    model_path,
    load_in_4bit=True,  # 显存降到约5GB
)

坑2：CPU offload导致推理慢

现象：日志里看到 offloaded to the cpu，推理特别慢。

解决：确认 device_map="cuda" 而不是 "auto"。

坑3：磁盘写满

现象：Disk quota exceeded。

解决：日志写/tmp（内存盘），不要写到/mnt/workspace。

七、总结

MI300X跑7B模型真的是降维打击：192GB显存，别说7B，70B都能跑。ROCm环境魔搭已经预装好了，开箱即用。

关键经验
  • 先确认实际可用显存，不要想当然
  • 日志写/tmp，不要占/mnt/workspace空间
  • 4bit量化是兜底方案，显存不够随时切
  • 开机自启一定要配，不然重启就没了
