## 一、设计目标

**破除「沙箱销毁即失联」的困境。**

资料库是唯一跨代持久的权威层；沙箱与本地注入载体都会随会话销毁。本协议将**互联所需全部状态**外置到资料库，使任意新沙箱启动时，仅凭资料库即可恢复完整互联。

## 二、铁律（承既有架构，不重造）

1. **云端权威 ＋ 本地注入镜像** 是唯一可行结构（平台只在会话启动注入本地文件）
2. **资料库 = 权威源**，本地 = 镜像；两者逐字同步，先改云端后同步本地
3. **凭证零入库**，资料库只存**引用指针**，不存明文
4. **零删除、可逆**：本协议只增不删
5. 复用既有入口 `kernel_libsync.py`（双向同步），不另造同步器

## 四、启动恢复流程（新会话开局执行）

### 第一步：加载启动记忆
```
检索资料库 00-启动入口/eOwKAIBrtrNlm13lc5Wg5y
```
### 第二步：读取互联状态台账
```
query_database_record --database-id <BOOT台帐ID>
→ 逐字段读回：通道清单 / 凭证指针 / 同步游标 / 节点身份
```
### 第三步：重建 AtomGit 通道
```
1. 读台账取得 remote URL 与凭证指针
2. 按指针注入凭证（用户提供 或 从网关拉取）
3. git remote add atomgit <url>
4. git fetch 验证握手
```
### 第四步：恢复同步游标
```
按台账记录的 last_sync_commit / direction 恢复断点，续跑 kernel_libsync
```
### 第五步：落本地镜像
```
将启动记忆正文写入本地注入载体（四件套），完成「云端权威＋本地镜像」
```

## 五、辩证边界

- 本协议**不搬真值正文**，只搬状态与台账
- 凭证**永不入库**，仅存指针；新沙箱须重新注入
- 资料库不回写内核基线（锁档面须五态审批）
- 同步走既有 `kernel_libsync.py`，不新建计划任务（只改不建）
